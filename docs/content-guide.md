# コンテンツ執筆ガイド

このサイトは **資格ごとではなく、技術の階層構造** で学習項目（トピック）を整理します。
「ネットワーク > インターネット層 > IPアドレス > アドレスクラス」のように、大きな分野から詳細な技術へ掘り下げられる構成にし、
どの試験の範囲に入るかは各トピックの **`exams`（試験タグ）** と **`tags`（横断タグ）** で表現します。

## ディレクトリ構造 = 階層構造

```
src/content/topics/
├── network/                 … ネットワーク（大分類）
│   ├── index.md             … 「ネットワーク」自身のページ
│   ├── ip/                  … インターネット層
│   │   ├── index.md
│   │   ├── ip-address/      … IPアドレス（子を持つので ディレクトリ + index.md）
│   │   │   ├── index.md
│   │   │   ├── class.md     … アドレスクラス（末端なので単独ファイル）
│   │   │   └── subnet.md
│   │   └── routing.md
```

- **子を持つトピック** は `ディレクトリ/index.md`、**末端のトピック** は `名前.md` にします。
- 末端だったトピックに子を追加したくなったら、`foo.md` を `foo/index.md` に移動するだけで URL は変わりません。
- ファイル・ディレクトリ名は URL になるため **英小文字とハイフン** を使います（例: `ip-address`）。
- 親の `index.md` が無いとビルドエラーになります（階層の抜けを防ぐため）。

トピックの id は `src/content/topics/` からの相対パスから拡張子と `/index` を除いたものです
（例: `network/ip/ip-address/class`）。URL は `/topics/<id>/` になります。

## フロントマター

```yaml
---
title: アドレスクラス          # 必須。ページタイトル
order: 1                       # 同じ階層内での並び順（小さいほど先。省略時 100）
summary: IPv4アドレスをクラスA〜Eに分ける旧来の方式  # 一覧に出る一行説明
exams: [fe, ap]                # 出題範囲に含まれる試験（ip / fe / ap）
tags: [IPv4, アドレッシング, 計算問題]  # 横断タグ（自由。既存タグを優先して再利用）
related: [network/ip/ip-address/subnet]  # 関連トピックの id（存在しない id はビルドエラー）
prerequisites: [network/ip/ip-address]  # 先に読んでおきたいトピックの id（記事の冒頭に「この記事の前に」として表示）
draft: false                   # true にすると本番ビルドに含めない
---
```

### exams（試験タグ）の付け方

| id | 試験 | 目安 |
| --- | --- | --- |
| `ip` | ITパスポート試験 | 用語の意味・役割を説明できればよいレベル |
| `fe` | 基本情報技術者試験 | 仕組みを理解し、計算・トレースができるレベル |
| `ap` | 応用情報技術者試験 | 応用・設計・比較検討ができるレベル |
| `boki3` | 日商簿記検定 3級 | 仕訳・勘定記入・決算整理など、商業簿記の基本 |

- 各試験の **シラバス（IPA公開）・出題区分表（日本商工会議所）に該当項目があるか** で判断します。
  IT系と会計系のように系統の違う試験も、技術・知識の階層の中で同じ記事にタグとして付けます（例: 損益計算書の記事に `fe` と `boki3`）。
- 親トピックの `exams` は「その親ページ自体の説明がどの試験向けか」です。
  フィルタ時は **子孫に該当があれば親も表示** されるので、親に全部付ける必要はありません。
- 試験を追加する場合は `src/data/exams.ts` に追記します。

### tags（横断タグ）

分野をまたいで絞り込みたい観点に使います。既存タグを優先して再利用してください。

- 性質: `計算問題`, `頻出`, `用語`
- 技術横断: `IPv4`, `IPv6`, `暗号`, `プロトコル`, `性能評価`, `信頼性` など

## 本文の書き方

- 見出しは `##` から始めます（`#` はページタイトルとして自動表示されます）。
- 推奨構成:
  1. 冒頭に 1〜3 文の概要（「何のために使うものか」を最初に言う）
  2. **前提となる用語の説明** … 読者が知らない可能性のある用語（例: 売上高・売上原価）は、記事内で一言説明するか、説明している記事を `prerequisites` に指定する
  3. `## 仕組み` / `## ポイント` などの本文（表・箇条書き・コードブロック・図を活用）
  4. `## 実際の進め方` … 手法・フレームワークの記事では、実務でどう使うかを手順（ステップ）で示す。ワークシートの形（表）や、よくある失敗と対策も書く
  5. `## 事例` … 架空の企業・システムを使って、手順を最初から最後まで通して適用してみせる
  6. 計算が絡むものは `## 例題` と解き方
  7. `## 試験対策のポイント` … 試験ごとに問われ方が違う場合はここで書き分ける
- 事例は **架空の企業** で書きます。実在の企業については、広く知られた一般的な事実（例: 業界の構造）の範囲にとどめ、
  具体的な数値や社内の取り組みを推測で書かないでください。
- 子トピックの一覧はページ下部に自動表示されるので、親ページ本文では分野の全体像（何を学ぶか・どうつながるか）を説明します。
- 数値・規格・用語は正確に。不確かな内容は書かないでください。

## 数式（KaTeX）

数式・べき乗・分数などは KaTeX の記法で書くと、ビルド時にきれいに描画されます（`.md` / `.mdx` の両方で使えます）。

| 書き方 | 用途 | 例 |
| --- | --- | --- |
| `$...$` | 文中の数式 | `$2^n - 2$`、`$\dfrac{300}{0.4} = 750$` |
| `$$` で囲んだ行 | 独立した数式（中央寄せ） | 公式の提示 |

```
$$
\text{稼働率} = \frac{\text{MTBF}}{\text{MTBF} + \text{MTTR}}
$$
```

- 日本語は `\text{…}` で囲む
- 複数行の公式は、左辺を左寄せ・`=` の位置をそろえるため次の形で書く（`aligned` は左辺が右寄せになるので使わない）

```
$$
\def\arraystretch{2.2}
\begin{array}{ll}
\text{変動費率} &{}= \dfrac{\text{変動費}}{\text{売上高}} \\
\text{損益分岐点売上高} &{}= \dfrac{\text{固定費}}{1 - \text{変動費率}}
\end{array}
$$
```

  `&{}=` の `{}` は `=` の両側に余白を付けるため。`array` の中の分数は `\dfrac` にする
- べき乗 `2^{10}`、添字 `a_{i}`、掛け算 `\times`、割り算 `\div`、分数 `\frac{a}{b}`（文中では `\dfrac` が読みやすい）
- 3桁区切りのカンマは `1{,}000` と書く（`1,000` だと余白が入る）
- 金額などで `$` 記号そのものを書きたいときは `\$` とエスケープする
- 書き間違えた数式はビルドを止めずに赤字で表示されるので、ページを開いて確認する

## 確認問題（quiz）

フロントマターの `quiz` に書くと、記事の末尾に「確認問題」として表示されます。
選択肢を選ぶとその場で正誤と解説が出て、正答数を数えます（`src/components/Quiz.astro`）。

```yaml
quiz:
  - q: '売上高 2,000万円、変動費 1,200万円、固定費 600万円の企業の損益分岐点売上高はいくらか。'
    choices: ['1,000万円', '1,200万円', '1,500万円', '1,800万円']
    answer: 2          # 正解の選択肢の番号（0 始まり。0=ア, 1=イ, 2=ウ, 3=エ）
    explanation: '変動費率は $\dfrac{1{,}200}{2{,}000} = 0.6$ … $= 1{,}500$ 万円。'
    level: fe          # 難易度の目安となる試験（ip / fe / ap。省略可）
```

- 文字列は **シングルクォート** で囲む（`\` をそのまま書けるため。文中の `'` は `''` と2つ重ねる）
- 問題文・選択肢・解説では `$...$` の数式と `` `コード` `` が使える
- 選択肢は2〜5個。解説では「なぜ正解か」に加え、紛らわしい誤答がなぜ誤りかにも触れる
- 末端の記事は 3〜5問、親ページ（index）は分野の全体像を問う 2〜3問が目安
- 記事本文で説明している内容から出題し、正解が1つに定まることを確認する。計算問題は検算する
- 過去問の文章をそのまま写さず、オリジナルの問題文にする
