**データ構造** とは、データを効率よく格納・操作するための形式です。データの追加・削除・参照のどれを速くしたいかによって、適したデータ構造が変わります。

## 仕組み

### 配列

同じ型のデータを **連続した領域** に並べ、添字（インデックス）で要素を指定します。

- 添字による参照は $O(1)$ で高速
- 途中への挿入・削除は、後ろの要素をずらす必要があり $O(n)$
- 2次元配列は行・列の 2 つの添字で要素を指定します

### 連結リスト（リスト）

各要素（ノード）が **データと次の要素へのポインタ** を持ち、ポインタをたどってつながる構造です。

| 種類 | 特徴 |
| --- | --- |
| 単方向リスト | 次の要素へのポインタのみを持つ |
| 双方向リスト | 次と前の要素へのポインタを持ち、逆方向にもたどれる |
| 環状リスト | 末尾の要素が先頭を指す |

- 挿入・削除はポインタを付け替えるだけでよい（位置が分かっていれば $O(1)$）
- 特定の位置の要素を参照するには先頭からたどる必要があり $O(n)$

### スタックとキュー

| 構造 | 取り出し順 | 操作 | 主な用途 |
| --- | --- | --- | --- |
| スタック | **後入れ先出し（LIFO）** | push（積む）/ pop（取り出す） | 関数呼出しの戻り先管理、式の評価（逆ポーランド記法）、深さ優先探索 |
| キュー | **先入れ先出し（FIFO）** | enqueue（追加）/ dequeue（取り出す） | 処理待ち行列、印刷待ち、幅優先探索 |

### 木構造

親子関係で階層的につながった構造です。最上位の要素を **根**、子を持たない要素を **葉** といいます。

| 種類 | 特徴 |
| --- | --- |
| 二分木 | 各節点の子が最大 2 つ |
| 完全二分木 | 葉以外の段がすべて埋まり、最下段は左から詰めて並ぶ二分木 |
| 二分探索木 | どの節点でも「左部分木の値 < 節点の値 < 右部分木の値」が成り立つ |
| ヒープ | 完全二分木で、どの節点でも「親 ≥ 子」（最大ヒープ）または「親 ≤ 子」（最小ヒープ）が成り立つ |
| B木 | 1 つの節点に複数のキーを持つ多分木。データベースの索引などに使われる |

二分探索木は、木の形が偏らず平衡していれば探索が $O(\log n)$ ですが、昇順に値を挿入するなどして偏ると、リストと同じ $O(n)$ になります。

### 二分木の走査（なぞり方）

| 方法 | 順序 |
| --- | --- |
| 先行順（行きがけ順） | 節点 → 左部分木 → 右部分木 |
| 中間順（通りがけ順） | 左部分木 → 節点 → 右部分木 |
| 後行順（帰りがけ順） | 左部分木 → 右部分木 → 節点 |

二分探索木を中間順でなぞると、値が **昇順** に取り出せます。

## 実際のプログラム・システムでの使われ方

データ構造は、普段使っているソフトウェアの中で次のように使われています。

| データ構造 | 使われている場所 | その構造が選ばれる理由 |
| --- | --- | --- |
| 配列 | 画像（画素を縦×横の2次元配列で持つ）、表計算のセル、音声の波形データ | 位置（添字）を計算するだけで直接読み書きできる |
| 連結リスト | 「最近使った順」の管理（使った要素を先頭へ付け替える）、要素の出入りが多い並び | 位置が分かっていれば、途中の抜き差しがポインタの付け替えだけで済む |
| スタック | 関数の呼出し（呼出しスタック）、ブラウザの「戻る」、エディタの「元に戻す」、括弧の対応チェック、式の計算 | 最後に行ったものから順に取り消す・戻る動きにそのまま合う |
| キュー | 印刷待ち、ジョブキュー（重い処理を受け付けた順に後で実行）、キーボード入力のバッファ、ネットワーク機器の送信待ち | 来た順に公平に処理できる |
| 木 | ファイルシステムのフォルダ構成、Web ページの文書構造（HTML の要素の入れ子）、データベースの索引（B木の仲間） | 階層を表せる。値を順序付けて持てば探索が速い |
| ヒープ | 優先度付きキュー（締切りの近いタスクから実行する、最短経路を求める） | 最大（最小）の要素をすぐに取り出せ、追加・取出しも $O(\log n)$ |

関数の呼出しとスタックの関係は [再帰](../../programming/recursion/) の記事で、データベースの索引は [探索](../searching/) の記事で詳しく扱います。

## 実際の進め方: データ構造を選ぶ

1. **よく行う操作を書き出す**: 「末尾に追加」「先頭から取り出す」「値で探す」「最大のものを取り出す」など。
2. **それぞれの回数とデータ量を見積もる**: 1日に数回の操作なら $O(n)$ でも困りませんが、1秒に何千回も行う操作は速い構造が必要です。
3. **操作ごとの計算量を比べる**（下の表）
4. **言語の標準ライブラリにある実装を使う**: 自分で作るより速く、誤りも少なくなります。

<div style={{ whiteSpace: 'nowrap' }}>

| 操作 | 配列 | 連結リスト | 二分探索木 | ヒープ |
| --- | --- | --- | --- | --- |
| 添字で参照 | $O(1)$ | $O(n)$ | — | — |
| 値で探す | $O(n)$ ※1 | $O(n)$ | $O(\log n)$ ※2 | $O(n)$ |
| 途中に挿入・削除 | $O(n)$ | $O(1)$ ※3 | $O(\log n)$ ※2 | — |
| 最大・最小を取り出す | $O(n)$ ※4 | $O(n)$ | $O(\log n)$ ※2 | $O(\log n)$ |

</div>

※1 整列済みなら二分探索で $O(\log n)$。※2 木が平衡している場合（偏ると $O(n)$）。※3 挿入・削除する位置が分かっている場合。※4 整列していない場合。

例えば Python では、リスト（`list`）は配列なので、末尾への追加 `append` と末尾からの取出し `pop()` は速くスタックに向きますが、先頭からの取出し `pop(0)` は残りの要素を全部ずらすので $O(n)$ かかります。キューには、両端の出し入れが速い `collections.deque` を使います。

## 事例: ブラウザの「戻る」「進む」

ブラウザの「戻る」「進む」は、**2つのスタック** で実現できます。

- 新しいページを開く: 今のページを「戻る用」に積み、新しいページを表示する。「進む用」は空にする
- 戻る: 今のページを「進む用」に積み、「戻る用」から取り出したページを表示する
- 進む: 今のページを「戻る用」に積み、「進む用」から取り出したページを表示する

ページ A → B → C と開き、2回戻ってから1回進み、新しいページ D を開いたときの様子です（スタックは左が底）。

| 操作 | 表示中 | 戻る用スタック | 進む用スタック |
| --- | --- | --- | --- |
| A を開く | A | [ ] | [ ] |
| B を開く | B | [A] | [ ] |
| C を開く | C | [A, B] | [ ] |
| 戻る | B | [A] | [C] |
| 戻る | A | [ ] | [C, B] |
| 進む | B | [A] | [C] |
| D を開く | D | [A, B] | [ ]（C には進めなくなる） |

Python で書くと次のようになります（リストの末尾をスタックの頂上とします）。

```python
back, forward = [], []      # 戻る用・進む用のスタック
current = "A"

def visit(page):
    global current
    back.append(current)    # push
    current = page
    forward.clear()         # 新しいページを開くと「進む」は消える

def go_back():
    global current
    if back:                # 空なら「戻る」は押せない
        forward.append(current)
        current = back.pop()
```

### 括弧の対応チェック

プログラムのエディタやコンパイラは、括弧の対応が正しいかをスタックで調べます。開き括弧は積み、閉じ括弧が来たら頂上を取り出して種類が合うかを確かめ、最後にスタックが空なら正しく対応しています。

```python
def balanced(text):
    pairs = {")": "(", "]": "["}
    stack = []
    for ch in text:
        if ch in "([":
            stack.append(ch)
        elif ch in ")]":
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

balanced("a[(b)+c]")   # True
balanced("a[(b]+c)")   # False（ ] の時点で頂上が ( なので不一致）
```

### ジョブキュー

Web サービスでは、注文を受け付けたときに確認メールの送信のような時間のかかる処理をその場で行わず、**キューに積んで** 別のプログラムが順に取り出して処理することがよくあります。利用者を待たせず、受け付けた順に処理できます。

```python
from collections import deque

jobs = deque()
jobs.append("注文1001の確認メール")   # enqueue（受付順に末尾へ）
jobs.append("注文1002の確認メール")
jobs.popleft()                        # dequeue → "注文1001の確認メール"
```

## 例題

**例題1** 空のスタックに対して、push(1)、push(2)、pop()、push(3)、push(4)、pop()、pop() の順で操作した。最後に取り出された値は何か。

**解き方**: 状態を追います（左が底）。

```
push(1) → [1]
push(2) → [1, 2]
pop()   → 2 を取り出す → [1]
push(3) → [1, 3]
push(4) → [1, 3, 4]
pop()   → 4 を取り出す → [1, 3]
pop()   → 3 を取り出す → [1]
```

答え: **3**

**例題2** 同じ操作をキューで行った場合（push を enqueue、pop を dequeue と読み替える）、最後に取り出された値は何か。

**解き方**

```
enqueue(1), enqueue(2) → [1, 2]
dequeue() → 1 → [2]
enqueue(3), enqueue(4) → [2, 3, 4]
dequeue() → 2 → [3, 4]
dequeue() → 3 → [4]
```

答え: **3**（取り出し順は 1, 2, 3）

**例題3** 次の二分木を中間順になぞった順序を答えなさい。根が 8、その左の子が 3（3 の左の子 1、右の子 6）、根の右の子が 10。

**解き方**: 左部分木（1 → 3 → 6）→ 根 8 → 右部分木 10 の順で **1, 3, 6, 8, 10**。この木は二分探索木なので昇順になります。

## 試験対策のポイント

- **応用情報技術者**: 木の走査順序、ヒープへの要素追加・削除後の形、データ構造の選択理由など、より踏み込んだ理解が問われます。
