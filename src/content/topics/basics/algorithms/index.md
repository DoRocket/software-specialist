**アルゴリズム** は問題を解くための手順、**データ構造** はデータを効率よく扱うための格納のしかたです。
同じ問題でも、データ構造とアルゴリズムの選び方によって処理時間が大きく変わります。ここでは代表的なデータ構造と、探索・整列の基本アルゴリズム、その効率を比較するための **計算量** を学びます。

## この分野の全体像

| トピック | 学ぶこと | 主な試験 |
| --- | --- | --- |
| データ構造 | 配列・リスト・スタック・キュー・木（二分探索木・ヒープ） | IP / FE / AP |
| 探索 | 線形探索・二分探索・ハッシュ表探索と計算量 | FE / AP |
| 整列 | バブル・選択・挿入・クイック・マージ・ヒープソートと計算量・安定性 | FE / AP |

## 学ぶ順序

1. **データ構造** … まず「データをどう並べて持つか」を理解します。スタック（LIFO）とキュー（FIFO）は全試験で出題されます。
2. **探索** … データ構造の上で目的のデータを見つける方法です。データが整列済みかどうかで使える方法が変わります。
3. **整列** … 探索を速くするための前処理でもあります。アルゴリズムごとの計算量と安定性を比較します。

## 計算量（オーダ記法）

データ件数 n に対して処理時間がどのように増えるかを **O（オーダ）記法** で表します。定数倍や低次の項は無視します。

| オーダ | 読み方の例 | 代表例 |
| --- | --- | --- |
| $O(1)$ | 定数時間 | 配列の添字アクセス、衝突のないハッシュ探索 |
| $O(\log n)$ | 対数時間 | 二分探索 |
| $O(n)$ | 線形時間 | 線形探索 |
| $O(n \log n)$ | — | クイックソート（平均）、マージソート、ヒープソート |
| $O(n^2)$ | 2乗時間 | バブルソート、選択ソート、挿入ソート |

n が大きくなるほど、オーダの差が処理時間の差として大きく表れます（例: $n = 1024$ のとき $\log_2 n = 10$、$n^2 =$ 約100万）。

## 試験対策のポイント

- 基本情報技術者試験の科目Bでは、擬似言語で書かれたアルゴリズムのトレース（変数の値の追跡）が中心です。ここで学ぶデータ構造と探索・整列の動きを、自分で手順を追って確認できるようにしておきます。
- 応用情報技術者試験では、計算量の比較やアルゴリズムの選択理由が問われます。
