**探索** は、データの集まりの中から目的のデータを見つける処理です。代表的な方法に **線形探索**・**二分探索**・**ハッシュ表探索** があり、
データが整列済みかどうか、どのような構造で格納されているかによって使える方法と効率が変わります。

## 仕組み

### 線形探索（逐次探索）

先頭から順に 1 つずつ目的の値と比較します。

- データが整列されていなくても使える
- 比較回数: 最大 $n$ 回、見つかる場合の平均は $\dfrac{n + 1}{2}$ 回 → 計算量 **$O(n)$**
- **番兵法**: 配列の末尾に探したい値（番兵）を置いておくと、「配列の終わりに達したか」の判定を毎回行わなくてよくなり、ループ内の判定を減らせます

### 二分探索

**昇順（または降順）に整列済み** のデータに対して、中央の要素と比較し、探索範囲を半分ずつ絞り込みます。

```
探索範囲を [lo, hi] とする
  mid = (lo + hi) ÷ 2（小数点以下切捨て）
  data[mid] == 目的値 → 見つかった
  data[mid] <  目的値 → lo = mid + 1（右半分へ）
  data[mid] >  目的値 → hi = mid − 1（左半分へ）
lo > hi になったら見つからない
```

- 比較回数: 最大 $\lfloor \log_2 n \rfloor + 1$ 回、平均は約 $\log_2 n$ 回 → 計算量 **$O(\log n)$**
- 前提として整列が必要なため、データの追加・削除が多い場合は整列し直すコストがかかります

例題2 の配列で、lo・mid・hi の動きを確かめてみましょう。探す値を変えたり、要素数を増やしたりすると、線形探索との比較回数の差が分かります。

### ハッシュ表探索

キーから **ハッシュ関数** で格納位置（ハッシュ値）を計算し、その位置に直接アクセスします。

- 衝突がなければ 1 回の計算で位置が決まるため、計算量は **$O(1)$**
- 異なるキーから同じハッシュ値が得られることを **衝突（コリジョン）** といい、衝突したキーどうしを **シノニム** といいます

衝突の主な対処法:

| 方法 | 内容 |
| --- | --- |
| オープンアドレス法 | 衝突したら、別の空き位置（例: 次の位置）を規則に従って探して格納する |
| チェイン法（連鎖法） | 同じハッシュ値のデータを連結リストでつなぐ |

### 比較まとめ

| 方法 | 整列の必要 | 最大比較回数 | 計算量 |
| --- | --- | --- | --- |
| 線形探索 | 不要 | $n$ | $O(n)$ |
| 二分探索 | 必要 | $\lfloor \log_2 n \rfloor + 1$ | $O(\log n)$ |
| ハッシュ表探索 | 不要（ハッシュ表に格納） | 衝突がなければ 1 | $O(1)$ |

## 実際のプログラム・システムでの探索

| 場面 | 使われている探索 | ポイント |
| --- | --- | --- |
| Python で `x in リスト` と書く | 線形探索 | 書くのは簡単だが、要素数に比例して遅くなる。何度も調べるなら集合（`set`）に変える |
| Python の辞書（`dict`）・集合（`set`） | ハッシュ表探索 | キーから平均 $O(1)$ で値を引ける。順序を使った範囲の検索はできない |
| 整列済みのリストを `bisect` モジュールで調べる | 二分探索 | 「どの位置に入るか」も分かるので、範囲の検索や順位付けに使える |
| データベースで条件に合う行を探す | 索引が無ければ全件走査（線形探索と同じ）、B-tree 索引があれば木をたどる探索 | B木は1つの節点に多数のキーを持ち、節点の中で比べて次に進む枝を選ぶ。二分探索木を「多分木」に広げたもの |
| バージョン管理で、不具合が入った変更（コミット）を探す | 二分探索 | 「この版では正常、この版では異常」の中間の版を試し、範囲を半分ずつ絞る（Git の `git bisect`）。1,000 個の変更でも 10 回ほど試せば特定できる |

二分探索を使う例です。

```python
import bisect

ids = [1003, 1010, 1025, 1040, 1077]      # 昇順に整列済み
i = bisect.bisect_left(ids, 1025)          # 1025 以上の最初の位置 → 2
found = i < len(ids) and ids[i] == 1025    # True（見つかった）
```

## 事例: 会員 10万人の中から会員番号で探す

架空の会員制サービスで、10万人（$n = 100{,}000$）の会員の中から、ログインのたびに会員番号で1人を探します。

| 方法 | 1回の探索の比較回数 | 準備・維持のコスト | 向いている問合せ |
| --- | --- | --- | --- |
| 線形探索 | 最大 100,000 回、平均 50,000.5 回 | 不要（登録順に並べるだけ） | 件数が少ない、探すのがまれ |
| 二分探索 | 最大 17 回（$2^{16} \leqq 100{,}000 < 2^{17}$） | 整列が必要。新しい会員を途中に挿入するたびに後ろをずらす $O(n)$ | 1件の検索に加え「番号 1000〜1999 の会員」のような範囲の検索 |
| ハッシュ表探索 | 衝突が少なければ ほぼ 1 回 | ハッシュ表の領域（空きを含む）が必要 | 番号がぴったり一致する1件の検索 |

1秒間に数千回ログインがあるなら、1回 5万回の比較は大きな負担です。ログインには **ハッシュ表**、管理画面の「登録日の範囲で一覧」には整列済みの構造（データベースなら B-tree 索引）、と問合せごとに使い分けます。
データベースの索引をどの列に作るかの判断は [データベース設計](../../../database/design/) の記事で扱います。

## 二分探索のプログラムでよくある誤り

二分探索は短いプログラムですが、境界の扱いを1か所でも誤ると正しく動きません。

| 誤り | 何が起きるか | 正しい書き方 |
| --- | --- | --- |
| 繰返しの条件を `lo ＜ hi` にする | 範囲が1要素（lo ＝ hi）になったときに比べずに終わり、最後の1つを見落とす | `lo ≦ hi` の間繰り返す |
| `lo ← mid`、`hi ← mid` と更新する | 範囲が縮まらず、同じ mid を比べ続ける無限ループになる | `lo ← mid ＋ 1`、`hi ← mid － 1` |
| `mid ← (lo ＋ hi) ÷ 2` を固定長の整数で計算する | 要素数が非常に多いと lo ＋ hi が整数の上限を超え（オーバフロー）、負の値になる | `mid ← lo ＋ (hi － lo) ÷ 2` |

3つ目は、実際に広く使われていたライブラリの二分探索で見つかったことのある誤りです。整数の上限とオーバフローについては [補数による負数表現](../../number-systems/complement/) の記事を参照してください。

## 例題

**例題1** 1,000 件の整列済みデータを二分探索するとき、最大の比較回数は何回か。

**解き方**: $2^9 = 512 \leqq 1{,}000 < 1{,}024 = 2^{10}$ なので $\lfloor \log_2 1{,}000 \rfloor = 9$。最大比較回数は $9 + 1 =$ **10 回**。
（線形探索なら最大 1,000 回、平均 500.5 回です）

**例題2** 昇順に並んだ配列 [3, 8, 12, 17, 21, 25, 30]（添字 0〜6）から 25 を二分探索する。比較する要素を順に答えなさい。

**解き方**

```
lo=0, hi=6 → mid=3 → data[3]=17 < 25 → lo=4
lo=4, hi=6 → mid=5 → data[5]=25 → 発見
```

答え: **17 → 25**（2 回）

**例題3** ハッシュ関数を「キー mod 7」（7 で割った余り）とする大きさ 7 のハッシュ表に、キー 10、24、17 を順に格納する。衝突時は次の位置（末尾の次は先頭）に格納するオープンアドレス法とすると、17 はどの位置に格納されるか。

**解き方**

- $10 \bmod 7 = 3$ → 位置 3
- $24 \bmod 7 = 3$ → 衝突 → 位置 4
- $17 \bmod 7 = 3$ → 衝突 → 位置 4 も使用中 → 位置 5

答え: **位置 5**（10・24・17 はシノニム）

## 試験対策のポイント

- **ITパスポート**: 線形探索と二分探索の考え方（二分探索は整列済みデータが前提）を説明できるようにしておきます。
- **基本情報技術者**: 二分探索の最大・平均比較回数、線形探索との計算量の違い、ハッシュの衝突とシノニムの意味がよく出ます。科目Bでは二分探索のプログラムのトレースや、終了条件・添字の更新部分の穴埋めが定番です。
- 「二分探索は整列済みであることが前提」は選択肢の正誤判断で頻繁に使われます。
- **応用情報技術者**: データ件数が増えたときの処理時間の変化（例: n が 2 倍・4 倍になったら $O(\log n)$ はどう変わるか）や、衝突処理の方式の比較が問われます。
