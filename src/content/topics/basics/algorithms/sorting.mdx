**整列（ソート）** は、データを昇順や降順など一定の順序に並べ替える処理です。二分探索の前処理としても重要です。
アルゴリズムによって **計算量**、**安定性**、**追加で必要なメモリ** が異なるため、それぞれの特徴を比較して理解します。

### 前提となる用語

- **キー**: 並べ替えの基準にする項目。「点数の降順、同点なら受付順」のように複数のキーを使うとき、優先する方を第1キー、次を第2キーと呼びます。
- **計算量（O 記法）**: データ件数 n が増えたとき、処理時間がどのような割合で増えるかを表します。$O(n^2)$ なら件数が 10 倍で時間は約 100 倍、$O(n \log n)$ なら約 10 倍強です。
- **配列** や **ヒープ** などのデータ構造は [データ構造](../data-structures/) の記事で扱っています。

## 仕組み

### 基本的な整列法（$O(n^2)$）

| 方法 | 手順 |
| --- | --- |
| バブルソート（交換法） | 隣り合う要素を比較し、順序が逆なら交換する。これを繰り返すと 1 パスごとに最大（または最小）の値が端に確定する |
| 選択ソート（選択法） | 未整列部分から最小値を探し、未整列部分の先頭と交換する。これを繰り返す |
| 挿入ソート（挿入法） | 整列済み部分の適切な位置に、未整列部分の先頭要素を挿入していく |

バブルソートと選択ソートの比較回数は、データの並びに関係なく $\dfrac{n(n - 1)}{2}$ 回です（バブルソートで「交換が 1 回もなければ終了」とする改良をしない場合）。
挿入ソートは、データが **ほぼ整列済み** なら比較・移動がほとんど発生せず $O(n)$ に近づきます。

3 つの方法で、比較・交換が進むようすを見比べてみましょう。最初のデータは例題1・例題2 と同じ [5, 3, 8, 1] です。

### 高速な整列法（$O(n \log n)$）

| 方法 | 手順 |
| --- | --- |
| クイックソート | 基準値（ピボット）を選び、それより小さいグループと大きいグループに分割する。各グループに同じ処理を再帰的に繰り返す |
| マージソート | データを半分に分割し続け、要素 1 個になったら、整列済みの列どうしを併合（マージ）しながら戻していく |
| ヒープソート | データでヒープ（最大ヒープ）を構成し、根（最大値）を取り出して末尾に置き、残りでヒープを再構成することを繰り返す |

### 比較まとめ

| 方法 | 平均計算量 | 最悪計算量 | 安定 | 備考 |
| --- | --- | --- | --- | --- |
| バブルソート | $O(n^2)$ | $O(n^2)$ | ○ | 実装が単純 |
| 選択ソート | $O(n^2)$ | $O(n^2)$ | × | 交換回数が少ない（最大 $n - 1$ 回） |
| 挿入ソート | $O(n^2)$ | $O(n^2)$ | ○ | ほぼ整列済みのデータに強い |
| クイックソート | $O(n \log n)$ | $O(n^2)$ | × | 一般に高速。ピボットの選び方が悪いと最悪 $O(n^2)$ |
| マージソート | $O(n \log n)$ | $O(n \log n)$ | ○ | 併合のための作業領域が必要 |
| ヒープソート | $O(n \log n)$ | $O(n \log n)$ | × | 追加の作業領域がほぼ不要 |

### 安定性とは

**安定な整列** とは、**同じキーを持つデータの元の順序が、整列後も保たれる** ことです。
例えば「受付順に並んだ申込データ」を点数で安定に整列すると、同点の人は受付順のまま並びます。
複数のキーで並べ替えるとき（第2キーで整列してから第1キーで整列する等）に安定性が重要になります。

## 実際のプログラム・システムでの使われ方

実務では、整列のアルゴリズムを自分で書くことはほとんどなく、**言語の標準ライブラリの整列** を使います。標準の整列は高速で誤りもありませんが、**安定かどうか** と **既定の比較方法** は言語ごとに違うので、性質を知ったうえで使います。

| 言語・環境 | 整列の機能 | 安定か | 備考 |
| --- | --- | --- | --- |
| Python | `sorted()`、`list.sort()` | 安定 | マージソートと挿入ソートを組み合わせた Timsort 系の方式。最悪でも $O(n \log n)$ で、ほぼ整列済みのデータは特に速い |
| Java | `Arrays.sort`（オブジェクトの配列）、`Collections.sort`、`List.sort` | 安定 | TimSort を使用 |
| Java | `Arrays.sort`（`int` などの基本型の配列） | 安定ではない | クイックソートを改良した方式。基本型は同じ値を区別できないので、安定性は問題にならない |
| C++ | `std::sort` / `std::stable_sort` | 安定ではない / 安定 | 安定性が必要なら `std::stable_sort` を使う |
| JavaScript | `Array.prototype.sort` | 安定（ES2019 以降） | 比較関数を省略すると **文字列として** 比べる |
| SQL | `ORDER BY` | 保証されない | 同じキーの行どうしの順序は決まっていない。順序を確定させたいときは主キーなどを最後のキーに加える |

### よくある落とし穴

- **数値が文字列として並ぶ**: JavaScript で `[10, 9, 1].sort()` は `[1, 10, 9]` になります（"10" は "9" より前）。数値として並べるには `[10, 9, 1].sort((a, b) => a - b)` と比較関数を渡します。CSV から読み込んだ値が文字列のままだと、Python などでも同じことが起きます。
- **日本語の文字列はコード順に並ぶ**: 文字列の整列は文字コードの順になるので、日本語の書名をそのまま並べても五十音順にはなりません（ひらがな → カタカナ → 漢字の順に固まる）。読み（ふりがな）の列を用意し、それで並べます。
- **同点の順序が実行のたびに変わる**: SQL の `ORDER BY 点数 DESC` だけでは、同点の行の順序が保証されず、画面を再読み込みすると入れ替わることがあります。ページ分割（1〜20 件目、21〜40 件目…）で同じ行が 2 度出たり抜けたりする原因になります。

### 複数のキーで並べる

Python では、キーをタプルにすると「第1キー、同じなら第2キー」の順で比べられます。降順にしたい数値のキーには `-` を付けます。

```python
sorted(books, key=lambda b: (-b["sold"], b["yomi"]))   # 販売数の降順、同数なら読みの昇順
```

安定な整列を使うなら、**第2キーで先に整列し、最後に第1キーで整列する** 方法でも同じ結果になります。2 回目の整列が安定なので、同じ第1キーの中では 1 回目に並べた順序が保たれるからです。

### 大量のデータや上位だけが欲しいとき

- **上位 k 件だけが欲しい**: 全件を整列する必要はありません。ヒープを使うと $O(n \log k)$ で求められます（Python の `heapq.nlargest(k, …)`）。
- **メモリに入りきらないデータ**: データを分割して、それぞれを整列してファイルに書き出し、最後にマージソートの「併合」の考え方でまとめます（**外部整列**）。データベースが大きな表を `ORDER BY` で並べるときにも使われます。
- **何度も検索する**: 一度整列しておけば、[探索](../searching/) の記事で扱う二分探索で $O(\log n)$ で探せます。

## 実際の進め方: 整列の方法を選ぶ

1. **まず標準ライブラリの整列を使う**: 自作より速く、誤りもありません。
2. **キーと順序を決める**: 第1キー・第2キー…と、それぞれ昇順か降順かを書き出します。最後に一意なキー（ID など）を加えると、順序が必ず 1 通りに決まります。
3. **値の型を確かめる**: 数値が文字列になっていないか、日本語の並べ替えに読みの列が必要か、大文字・小文字を区別するかを確認します。
4. **安定性が必要か確かめる**: 「元の順序（受付順など）を同点の中で保ちたい」なら安定な整列を使うか、元の順序を表す項目を最後のキーに加えます。
5. **データ量と必要な結果を見積もる**: 上位数件だけならヒープ、メモリに入らなければ外部整列、何度も検索するなら整列＋二分探索や索引、と使い分けます。

## 事例: あおば書店の売れ筋ランキング

架空のオンライン書店「あおば書店」で、トップページに「今週の売れ筋ランキング」を表示することになりました。要件は「販売冊数の多い順、同じ冊数なら書名の五十音順」です。

| 書名 | 読み | 販売冊数 |
| --- | --- | --- |
| データベース入門 | でーたべーすにゅうもん | 120 |
| はじめての Python | はじめてのぱいそん | 340 |
| 季節の和菓子 | きせつのわがし | 120 |
| アルゴリズム図鑑 | あるごりずむずかん | 340 |
| 週末の山歩き | しゅうまつのやまあるき | 85 |

最初の実装は `sorted(books, key=lambda b: (-b["sold"], b["title"]))` と書名そのもので並べたため、340 冊の 2 冊が「はじめての Python → アルゴリズム図鑑」の順になりました。書名の先頭がひらがなの「は」とカタカナの「ア」で、文字コードではひらがなの方が前にあるためです。第2キーを読みの列に変えると、要件どおりになりました。

```python
ranking = sorted(books, key=lambda b: (-b["sold"], b["yomi"]))
# 340 アルゴリズム図鑑
# 340 はじめての Python
# 120 季節の和菓子
# 120 データベース入門
#  85 週末の山歩き
```

ランキングの元データはデータベースから取り出すので、SQL でも同じ順序を指定しました。

```sql
SELECT 書名, 販売冊数
FROM 週間販売
ORDER BY 販売冊数 DESC, 読み ASC, 書籍ID ASC
LIMIT 10;
```

最後の `書籍ID` は、販売冊数も読みも同じ書籍があった場合に、表示の順序を 1 通りに決めるためのものです。また、全書籍は数万点ありますが、必要なのは上位 10 件だけなので、データベース側で `LIMIT 10` を付けて上位だけを取り出しています。

## 例題

**例題1** データ [5, 3, 8, 1] をバブルソートで昇順に整列する。各パス終了時の並びと、交換の合計回数を答えなさい（先頭から隣どうしを比較する）。

**解き方**

```
パス1: (5,3)交換→[3,5,8,1] (5,8)そのまま (8,1)交換→[3,5,1,8]   … 8が確定
パス2: (3,5)そのまま (5,1)交換→[3,1,5,8]                       … 5が確定
パス3: (3,1)交換→[1,3,5,8]                                     … 完了
```

交換回数は $2 + 1 + 1 =$ **4 回**。比較回数は $3 + 2 + 1 = 6$ 回 $= \dfrac{4 \times 3}{2}$ です。

**例題2** 同じデータ [5, 3, 8, 1] を選択ソートで昇順に整列する。各パス終了時の並びを答えなさい。

**解き方**

```
パス1: 最小値1を先頭の5と交換 → [1,3,8,5]
パス2: 残り[3,8,5]の最小値3は既に先頭 → [1,3,8,5]
パス3: 残り[8,5]の最小値5を8と交換 → [1,3,5,8]
```

**例題3** データ件数が 1,000 件から 2,000 件に増えたとき、$O(n^2)$ の整列法の処理時間はおよそ何倍になるか。

**解き方**: 処理時間は $n^2$ に比例するので、$\left(\dfrac{2{,}000}{1{,}000}\right)^2 =$ **4 倍**。$O(n \log n)$ の方法なら約 2 倍強にとどまります。

## 試験対策のポイント

- **ITパスポート**: 選択ソート・バブルソート・クイックソートの名前と大まかな手順の対応を押さえておきます。
- **基本情報技術者**: 各整列法の手順の説明文と名前の対応、計算量、途中経過のトレースが頻出です。科目Bでは擬似言語で書かれたソートのトレースや穴埋めが出ます。
- 「安定なのはどれか」はよく問われます。$O(n^2)$ の 3 つではバブル・挿入が安定、選択が不安定。$O(n \log n)$ の 3 つではマージが安定、クイック・ヒープが不安定と整理して覚えます。
- **応用情報技術者**: クイックソートの最悪ケース（整列済みデータで端の値をピボットにした場合など）、マージソートの作業領域、ヒープの再構成手順など、アルゴリズムの特性を踏まえた比較が問われます。
