コンピュータで負の整数を表す代表的な方法が **補数** を使った表現です。
特に **2の補数** 表現を使うと、減算を「負の数の加算」として加算回路だけで計算できるため、現在のコンピュータで広く使われています。

## 仕組み

### 補数とは

ある数に足すと「桁上がりする数」または「その桁の最大値」になる数を補数といいます。n 桁の 2進数 x に対して、

| 種類 | 定義 | 求め方 |
| --- | --- | --- |
| 1の補数 | $(2^n - 1) - x$ | 全ビットを反転する |
| 2の補数 | $2^n - x$ | 全ビットを反転して 1 を足す（= 1の補数 + 1） |

例（4ビット、x = 0101）:

- 1の補数: `1010`
- 2の補数: `1010 + 1 = 1011`

### 2の補数による符号付き整数

最上位ビット（MSB）が **符号ビット** の役割を持ち、0 なら 0 以上、1 なら負の数です。負の数 −x は、x の 2の補数で表します。

4ビットの例:

| ビット列 | 符号なし整数 | 2の補数表現 | 1の補数表現 |
| --- | --- | --- | --- |
| 0111 | 7 | 7 | 7 |
| 0001 | 1 | 1 | 1 |
| 0000 | 0 | 0 | +0 |
| 1111 | 15 | −1 | −0 |
| 1110 | 14 | −2 | −1 |
| 1001 | 9 | −7 | −6 |
| 1000 | 8 | −8 | −7 |

8ビットの 2の補数表現で確かめてみましょう。最上位ビット（符号ビット）だけ重みを **−128** とみなして合計すると、その値になります。「全ビット反転」→「＋1」で、符号を反転した値（2の補数）が得られることも試せます。

### 表現できる範囲

| 表現方法 | n ビットの範囲 | 8ビットの場合 |
| --- | --- | --- |
| 符号なし | $0$ 〜 $2^n - 1$ | 0 〜 255 |
| 2の補数 | $-2^{n-1}$ 〜 $2^{n-1} - 1$ | −128 〜 127 |
| 1の補数 | $-(2^{n-1} - 1)$ 〜 $2^{n-1} - 1$ | −127 〜 127 |

- 2の補数では 0 の表現が 1 通りなので、負の側が 1 つ多くなります。
- 1の補数では +0（0000…）と −0（1111…）の 2 通りの 0 が存在します。

### 2の補数による減算

`A − B` は `A + (Bの2の補数)` として計算し、**n ビットをはみ出した桁上がりは無視** します。

```
  5 − 3（4ビット）
  3 = 0011 → 2の補数 = 1101
    0101
  + 1101
  ------
   10010 → はみ出した1を捨てて 0010 = 2
```

### オーバフロー

結果が表現範囲を超えるとオーバフローが起こります。2の補数表現では、**同じ符号どうしを加算して結果の符号が変わった** 場合にオーバフローと判定できます。
例: 4ビットで 7 + 1 = `0111 + 0001 = 1000` → −8 となり誤り。

## 実際のプログラムでの整数

多くのプログラム言語の整数型は、決まったビット数の 2の補数表現です。範囲は $-2^{n-1}$ 〜 $2^{n-1} - 1$ の式どおりになります。

| ビット数 | 範囲 | 型の例 |
| --- | --- | --- |
| 8 | −128 〜 127 | Java の `byte` |
| 16 | −32,768 〜 32,767 | Java の `short` |
| 32 | −2,147,483,648 〜 2,147,483,647（約 ±21億） | Java の `int` |
| 64 | −9,223,372,036,854,775,808 〜 9,223,372,036,854,775,807（約 ±922京） | Java の `long` |

計算結果が範囲を超えたときの扱いは言語によって違います。

- **Java** など: 上位のはみ出したビットを捨てた値になります（ラップアラウンド）。`int` の最大値 2,147,483,647 に 1 を足すと、ビット列は `0111…1` から `1000…0` に変わり、最小値 −2,147,483,648 になります。エラーにはならないので、気付かないまま誤った値で処理が進みます。
- **C 言語**: 符号付き整数のオーバフローは「未定義動作」で、どうなるかは規格で決められていません。
- **Python**: 整数（`int`）は必要に応じて桁数が増えるので、オーバフローしません。ただし、ファイルや他のシステムとやり取りする値は決まったビット数であることが多く、変換するときに同じ問題が起きます。

32ビットでのラップアラウンドを Python でまねると、次のようになります。

```python
def to_int32(x):
    x &= 0xFFFFFFFF                      # 下位 32 ビットだけ残す
    return x - 2**32 if x >= 2**31 else x   # 最上位ビットが 1 なら負の数として読む

to_int32(2_147_483_647 + 1)    # -2147483648
to_int32(-1)                   # -1（ビット列は 0xFFFFFFFF）
```

### オーバフローの実例: 2038年問題

多くのシステムは、時刻を「1970年1月1日 0時0分0秒（UTC）からの経過秒数」で表します。これを 32ビットの符号付き整数で持っていると、最大値 $2^{31} - 1 = 2{,}147{,}483{,}647$ 秒に達するのが **2038年1月19日 3時14分7秒（UTC）** です。
その1秒後にはラップアラウンドして $-2^{31}$ になり、1901年12月の日時と解釈されてしまいます。対策として、時刻を 64ビットの整数で持つ方式への移行が進められています。

### 符号拡張: ビット数を広げるとき

8ビットの値を 16ビットや 32ビットの変数に入れるときは、**上位の空いたビットを符号ビットと同じ値で埋めます**（符号拡張）。こうすると値が変わりません。

| 値 | 8ビット | 16ビットに符号拡張 | 0 で埋めた場合（ゼロ拡張） |
| --- | --- | --- | --- |
| 5 | `00000101` | `00000000 00000101`（5） | `00000000 00000101`（5） |
| −3 | `11111101` | `11111111 11111101`（−3） | `00000000 11111101`（253） |

ファイルや通信から読み込んだ1バイト `11111111` は、符号なしとして読めば 255、2の補数として読めば −1 です。Java の `byte` は符号付きなので、0〜255 の値として扱いたいときは `b & 0xFF` のように上位を 0 にしてから使います。**同じビット列でも、どの表現として読むかで値が変わる** ことを意識します。

## 実際の進め方: 2の補数の問題を解く手順

1. **ビット数 n を確かめる**: 範囲は $-2^{n-1}$ 〜 $2^{n-1} - 1$。範囲外の値は表せない（問題の前提が崩れる）ので、最初に確認します。
2. **10進 → 2の補数**: 絶対値を n ビットの 2進数にし、負の数なら「全ビット反転 → 1 を足す」。
3. **2の補数 → 10進**: 最上位ビットが 0 ならそのまま読み、1 なら最上位の重みを $-2^{n-1}$ として各桁の重みを足します。
4. **検算する**: 求めたビット列を 3. の方法で読み戻し、元の値になるかを確かめます。
5. **加減算ではオーバフローを判定する**: はみ出した桁上がりは捨て、「同じ符号どうしの加算で結果の符号が変わったか」を見ます。

## 事例: 在庫数が突然マイナスになった

架空の倉庫管理システムで、ある部品の在庫数が、入庫を登録した直後に −32,768 と表示されました。調べると、在庫数を **16ビットの符号付き整数** で持っており、在庫 32,767 個のところに 1 個を入庫していました。

```
  0111 1111 1111 1111   （32767）
+ 0000 0000 0000 0001   （1）
---------------------
  1000 0000 0000 0000   （−32768）← 正どうしの加算で符号ビットが 1 に変わった
```

開発当初は「在庫は数千個まで」と考えて 16ビットにしていましたが、取扱量が増えて上限に達したのが原因でした。対策として次を行いました。

- 在庫数を 32ビットの整数に変える（データベースの列の型も合わせて広げる）
- 加算の前に「結果が上限を超えないか」を確かめ、超える場合はエラーにする
- データベースに `CHECK (在庫数 >= 0)` の制約を付け、負の値が書き込まれたら登録を拒否する

## 例題

**例題1** 8ビットの 2の補数表現で −45 を表しなさい。

**解き方**

1. 45 を 2進数にする: `0010 1101`
2. ビット反転: `1101 0010`
3. 1 を足す: `1101 0011`

答え: `11010011`（16進数で D3）

**例題2** 8ビットの 2の補数表現 `11110110` が表す 10進数を求めなさい。

**解き方**: 符号ビットが 1 なので負の数。絶対値は 2の補数を取って求めます。
反転 `00001001` + 1 = `00001010` = 10 → 答えは **−10**。
（別解: 最上位ビットの重みを $-2^7 = -128$ とみなし、$-128 + 64 + 32 + 16 + 4 + 2 = -10$）

**例題3** 16ビットの 2の補数表現で表せる整数の範囲を答えなさい。

**解き方**: $-2^{15}$ 〜 $2^{15} - 1$ なので **−32768 〜 32767**。

## 試験対策のポイント

- **基本情報技術者**: 「2の補数表現で表した値はどれか」「n ビットで表せる範囲」が定番です。範囲は負の側が 1 つ多い（−128〜127）ことを必ず押さえます。
- 最上位ビットの重みを負（$-2^{n-1}$）として足し合わせる方法を覚えると、負数の 10進変換が速くなります。
- **応用情報技術者**: 算術シフト（符号ビットを保ったまま行うシフト）と組み合わせた計算や、オーバフローの判定条件が問われることがあります。
- 1の補数と 2の補数の違い（0 の表現が 2 通りか 1 通りか、範囲の違い）も選択肢でよく比較されます。
