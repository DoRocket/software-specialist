**浮動小数点数** は、実数を「符号」「指数」「仮数」の組合せで表す方式です。10進数の $6.02 \times 10^{23}$ のような科学的記数法を 2進数で行うもので、
非常に大きい数から非常に小さい数までを限られたビット数で表現できます。その代わり、表現できる桁数（精度）に限りがあるため **誤差** が生じます。

### 前提となる用語

- **固定小数点数**: 小数点の位置をあらかじめ決めておく表し方。整数（小数点が最下位桁の右にある）が代表例です。浮動小数点数は、小数点の位置（指数）も値と一緒に持つ点が違います。
- **有効数字（有効桁数）**: 値の精度を表す、意味のある桁の数。$6.02 \times 10^{23}$ の有効数字は 3 桁です。浮動小数点数では、仮数部のビット数で有効数字の桁数が決まります。
- **2進数の小数**: 小数第1位の重みは $2^{-1} = 0.5$、第2位は $0.25$ です。10進数の 0.1 が 2進数では循環小数になることは、[基数変換](../radix-conversion/) の記事で扱っています。

## 仕組み

### 基本の形

$$
(-1)^{\text{符号}} \times \text{仮数} \times 2^{\text{指数}}
$$

- **符号部**: 0 なら正、1 なら負
- **指数部**: 2 を何乗するか（小数点の位置）
- **仮数部**: 有効数字の部分

### 正規化

仮数部の有効桁を最大限使うため、小数点の位置を一定のルールにそろえることを **正規化** といいます。
IEEE 754 では、2進数を $1.\text{xxxx} \times 2^e$ の形にそろえます。先頭は必ず 1 になるので、この 1 は格納せず（**ケチ表現** / 暗黙の 1）、小数点以下の `xxxx` だけを仮数部に格納します。

### IEEE 754 の形式

| 形式 | 全体 | 符号部 | 指数部 | 仮数部 | バイアス | 10進の有効桁（目安） |
| --- | --- | --- | --- | --- | --- | --- |
| 単精度（binary32） | 32ビット | 1 | 8 | 23 | 127 | 約7桁 |
| 倍精度（binary64） | 64ビット | 1 | 11 | 52 | 1023 | 約15〜16桁 |

- 指数部には、実際の指数に **バイアス** を加えた値を格納します（単精度なら 指数 + 127）。これにより負の指数も符号なしの値で表せます。
- 単精度では、指数部が全ビット 0 のパターン（0 や非正規化数）と全ビット 1 のパターン（無限大や NaN）は特別な意味に予約されています。

### 変換例（単精度）

−6.5 を IEEE 754 単精度で表します。

1. 2進数にする: 6.5 = `110.1`
2. 正規化: $1.101 \times 2^2$
3. 符号部: 負なので `1`
4. 指数部: $2 + 127 = 129 =$ `10000001`
5. 仮数部: 先頭の 1 を除いた `101` の後ろを 0 で埋める → `10100000000000000000000`

```
1 10000001 10100000000000000000000
→ 16進数で C0D00000
```

## 誤差の種類

| 誤差 | 発生する状況 | 例・対策 |
| --- | --- | --- |
| 丸め誤差 | 表現できる桁数に収めるため、最下位桁より下を四捨五入・切捨て・切上げしたときに生じる | 10進の 0.1 は 2進で循環小数になり、正確に表せない |
| 桁落ち | **値がほぼ等しい 2 数の減算** で、有効数字の桁数が大きく減る | $1.234 - 1.233 = 0.001$（有効数字4桁 → 1桁）。式変形で減算を避ける |
| 情報落ち | **絶対値が大きく異なる 2 数の加減算** で、小さい方の値が結果に反映されない | 大きい数に小さい数を何度も足す場合は、小さい数どうしを先に足す |
| 打切り誤差 | 無限に続く計算（級数展開・反復計算など）を途中で打ち切ることで生じる | 反復回数を増やすことで小さくできる |
| オーバフロー / アンダフロー | 指数部で表せる範囲を超える（大きすぎる / 0 に近すぎる）値になる | — |

情報落ちの例（10進で仮数4桁とする）:

$$
\begin{aligned}
& 1.000 \times 10^4 + 1.000 \times 10^{-1} \\
&= 10000.1 \;\rightarrow\; \text{仮数4桁に収めると } 1.000 \times 10^4 \text{（0.1 が失われる）}
\end{aligned}
$$

## 実際のプログラムで起きる誤差

多くのプログラム言語の小数の型（Python の `float`、Java・C の `double`、JavaScript の数値）は、IEEE 754 の **倍精度** です。そのため、次のような結果は言語を問わず同じように起きます。Python で確かめた例です（`#` 以降は結果）。

```python
0.1 + 0.2              # 0.30000000000000004
0.1 + 0.2 == 0.3       # False
0.1 * 3                # 0.30000000000000004

total = 0.0
for _ in range(10):
    total += 0.1       # 0.1 を 10 回足す
total                  # 0.9999999999999999
total == 1.0           # False
```

0.1・0.2・0.3 はどれも 2進数で循環小数になり、格納した時点で **丸め誤差** を含みます。表示するときは短く丸めて「0.1」と見えますが、実際の値は `0.1000000000000000055511151231257827…` です。足し算を繰り返すと、この小さな誤差が積み重なります。

### 誤差を前提にした書き方

| 場面 | 避けたい書き方 | 代わりの書き方（Python の例） |
| --- | --- | --- |
| 小数どうしが等しいか調べる | `a == b` | 許容誤差付きで比べる: `math.isclose(0.1 + 0.2, 0.3)` → `True` |
| 多数の値を合計する | `+=` で順に足す | 誤差を補正して合計する `math.fsum(...)`（`math.fsum([0.1] * 10)` → `1.0`） |
| 小数で数を数える・繰り返す | `x += 0.1` を条件に使うループ | 整数 i で数え、値は `i / 10` のように毎回計算する |
| 金額・個数 | `float` で持つ | 最小単位（円・セント）の **整数**、または **十進型**（`decimal.Decimal`） |

### 金額計算では整数か十進型を使う

金額では「1 円でも合わない」ことが許されないため、浮動小数点数は使わず、次のどちらかにします。

- **最小単位の整数で持つ**: 円なら円単位、ドルならセント単位（12.34 ドルを 1,234 セント）の整数にします。整数の加減乗算は、表せる範囲内なら誤差がありません。割合を掛けるときは `price * 7 // 10`（7 割、円未満切捨て）のように、整数の掛け算をしてから最後に 1 回だけ割ります。
- **十進型を使う**: 10進数のまま計算する型です。Python の `Decimal`、Java の `BigDecimal`、データベース（SQL）の `DECIMAL` / `NUMERIC` 型がこれに当たります。

```python
from decimal import Decimal, ROUND_HALF_UP

Decimal("0.1") + Decimal("0.2")    # Decimal('0.3')（ちょうど 0.3）
Decimal(0.1)                       # Decimal('0.1000000000000000055511151231257827021181583404541015625')

round(2.675, 2)                                              # 2.67（2.675 が実際は 2.67499… のため）
Decimal("2.675").quantize(Decimal("0.01"), ROUND_HALF_UP)    # Decimal('2.68')（四捨五入）
```

十進型は **文字列から作る** のがポイントです。`Decimal(0.1)` のように float から作ると、float が持っていた誤差までそのまま正確に写し取ってしまいます。

### 整数を浮動小数点数で持つときの限界

倍精度の仮数部は 52 ビット（暗黙の 1 を含めて 53 ビット）なので、整数を正確に表せるのは $2^{53} = 9{,}007{,}199{,}254{,}740{,}992$ までです。これを超えると、隣り合う整数を区別できなくなります（情報落ちと同じ現象です）。

```python
1e16 + 1 == 1e16                 # True（1 が反映されない）
float(9007199254740993)          # 9007199254740992.0（1 ずれる）
```

JavaScript の数値はすべて倍精度なので、安全に扱える整数の最大値 `Number.MAX_SAFE_INTEGER` は $2^{53} - 1$ です。大きな整数の ID（注文番号など）を JSON で JavaScript に渡すと値がずれることがあるため、こうした ID は **文字列として** やり取りするのが一般的です。

### 単精度・倍精度の使い分け

通常の計算は倍精度を使います。単精度（有効数字 約7桁）は、メモリと計算量を節約したい 3D グラフィックスや機械学習などで、精度が足りることを確かめたうえで使われます。

## 実際の進め方: 数値の型を選ぶ

1. **正確さが必要な値か** を見極める: 金額・個数・ポイントのように「ぴったり合う」必要がある値は、整数か十進型にします。
2. **測定値・科学技術計算・統計値** のように、もともと誤差を含む値は倍精度の浮動小数点数で扱います。
3. **比較は許容誤差付きで行う**: 浮動小数点数を `==` で比べない。
4. **丸めは最後に 1 回**: 途中で何度も丸めると、丸めの誤差が積み重なります。端数処理（切捨て・四捨五入）のルールは業務の規則に合わせて決め、どこで丸めるかを仕様に書きます。
5. **境界の値でテストする**: 「ちょうど 0.5 円」「ちょうど割り切れる金額」などで、期待どおりの結果になるかを確かめます。

## 事例: あおば書店の「30%引き」で 1 円ずれる

架空のオンライン書店「あおば書店」で、タイムセール「全品 30%引き（円未満切捨て）」を始めたところ、本体 1,400 円の本のセール価格が **979 円** と表示されるという問い合わせが来ました。正しくは $1{,}400 \times 0.7 = 980$ 円です。

原因は、セール価格を浮動小数点数で計算してから切り捨てていたことでした。

```python
price = 1400
price * 0.7          # 979.9999999999999（0.7 が 2進数で正確に表せない）
int(price * 0.7)     # 979  ← 切捨てで 1 円ずれる
```

0.7 は 2進数で循環小数になり、格納された値はわずかに 0.7 より小さくなります。そのため掛け算の結果が 980 をわずかに下回り、切り捨てると 979 になりました。どの価格でも起きるわけではなく（1,700 円なら正しく 1,190 円）、テストで見つからなかったのもこのためでした。

対策として次のように直しました。

- 割引率を「70 / 100」という整数の組で持ち、`price * 70 // 100` で計算する（$1{,}400 \times 70 = 98{,}000$、$98{,}000 \div 100 = 980$）
- 消費税も同じく `980 * 110 // 100` → 1,078 円のように整数で計算する
- データベースの価格の列は整数型（円単位）とし、割引率のように小数が必要な列は `DECIMAL` 型にする
- 1 円〜10,000 円のすべての価格について、整数で計算した期待値と一致するかを確かめるテストを追加する

## 例題

**例題1** 10進数 0.75 を IEEE 754 単精度で表したときの指数部（8ビット）を求めなさい。

**解き方**

1. 0.75 = `0.11`（2進）
2. 正規化: $1.1 \times 2^{-1}$
3. 指数部 $= -1 + 127 = 126 =$ `01111110`

答え: `01111110`

**例題2** 次の計算のうち、桁落ちが発生しやすいものはどれか。
(ア) 絶対値がほぼ等しく符号が同じ 2 数の減算 (イ) 絶対値が大きく異なる 2 数の加算 (ウ) 2 数の乗算 (エ) 無限級数を途中で打ち切る計算

**解き方**: 桁落ちは「ほぼ等しい数の引き算」で起こるので **(ア)**。(イ) は情報落ち、(エ) は打切り誤差です。
なお、絶対値がほぼ等しく **符号が異なる** 2 数の加算も、実質的には同じ減算になるため桁落ちが起こります。

## 試験対策のポイント

- **基本情報技術者**: 誤差の種類（丸め・桁落ち・情報落ち・打切り）の説明と状況の対応付けが頻出です。「ほぼ等しい数の減算 → 桁落ち」「大きさが極端に違う数の加減算 → 情報落ち」とセットで覚えます。
- 正規化・ケチ表現・バイアスの意味を理解し、簡単な値を IEEE 754 の各部に分解できるようにしておきます。
- **応用情報技術者**: 誤差を小さくするための計算順序（小さい値から先に加算する等）や、特定の形式での表現・値の読み取りが問われます。
- 0.1 のように 2進数で正確に表せない小数があることは、基数変換と合わせて理解しておきます。
