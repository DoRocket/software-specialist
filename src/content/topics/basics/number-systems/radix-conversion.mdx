**基数** とは、各桁で使える数字の種類の数（桁上がりする数）のことです。10進数の基数は 10、2進数の基数は 2 です。
コンピュータは 2進数で処理しますが、人間が読みやすいように 16進数や 8進数で表記することも多く、これらを相互に変換する方法を **基数変換** といいます。

### 前提となる用語

- **ビット（bit）**: 2進数の 1 桁。0 か 1 のどちらかを表す、情報の最小単位です。n ビットで $2^n$ 通りの値を表せます。
- **バイト（byte）**: 8 ビットのまとまり。$2^8 = 256$ 通り（0〜255）の値を表せます。ファイルの大きさやメモリの番地は、通常バイト単位で数えます。
- 基数を明示するときは $(1011)_2$ や $(2\text{F})_{16}$ のように右下に基数を書きます。プログラムでは `0b1011`（2進）、`0o17`（8進）、`0x2F`（16進）のような接頭辞を付ける言語が多くあります。

## 仕組み

### 位取り記数法と重み

n 進数では、各桁に「基数のべき乗」の **重み** があります。

| 桁の位置 | … | 3桁目 | 2桁目 | 1桁目 | 小数第1位 | 小数第2位 |
| --- | --- | --- | --- | --- | --- | --- |
| 10進数の重み | … | $10^2 = 100$ | $10^1 = 10$ | $10^0 = 1$ | $10^{-1} = 0.1$ | $10^{-2} = 0.01$ |
| 2進数の重み | … | $2^2 = 4$ | $2^1 = 2$ | $2^0 = 1$ | $2^{-1} = 0.5$ | $2^{-2} = 0.25$ |

8ビットの 2進数で、各桁の重みを確かめてみましょう。ビットをクリックすると 0 と 1 が切り替わり、10進数を入力するとビットに反映されます。

## 変換方法

### n進数 → 10進数

各桁の数字 × 重み を合計します。

$$
\begin{aligned}
(1011.01)_2 &= 1 \times 8 + 0 \times 4 + 1 \times 2 + 1 \times 1 + 0 \times 0.5 + 1 \times 0.25 = 11.25 \\
(2\text{F})_{16} &= 2 \times 16 + 15 \times 1 = 47
\end{aligned}
$$

### 10進数（整数部）→ n進数

基数で割り続け、**余りを下から順に** 並べます。

```
13 ÷ 2 = 6 余り 1   ↑
 6 ÷ 2 = 3 余り 0   │ 下から読む
 3 ÷ 2 = 1 余り 1   │
 1 ÷ 2 = 0 余り 1   │
→ (13)10 = (1101)2
```

### 10進数（小数部）→ n進数

小数部に基数を掛け、**整数部に出た数を上から順に** 並べます。小数部が 0 になったら終了です。

```
0.375 × 2 = 0.75  → 0   ↓
0.75  × 2 = 1.5   → 1   │ 上から読む
0.5   × 2 = 1.0   → 1   │
→ (0.375)10 = (0.011)2
```

10進数の 0.1 を同じ手順で変換すると `0.000110011001100…` と **循環小数** になり、有限桁の 2進数では正確に表せません。

### 2進数 ⇔ 8進数・16進数

小数点を基準に、2進数を **3桁ずつ（8進数）** または **4桁ずつ（16進数）** に区切って変換します。足りない桁は 0 で補います。

```
(10110110.1)2 → 1011 0110 . 1000 → (B6.8)16
(10110110.1)2 → 010 110 110 . 100 → (266.4)8
```

## 実際のプログラム・システムでの使われ方

16進数の 1 桁はちょうど 4 ビットなので、**1 バイト（8 ビット）は 16進数 2 桁** で過不足なく書けます。このため、バイト単位のデータを人間が読み書きする場面では 16進数がよく使われます。8進数の 1 桁は 3 ビットで、3 ビットずつ意味を持つデータ（ファイルの権限）に使われます。

| 場面 | 表記の例 | 読み方 |
| --- | --- | --- |
| Web のカラーコード | `#FF8000` | 赤・緑・青（RGB）を 1 バイトずつ 16進 2 桁で書く。FF = 255、80 = 128、00 = 0 なので、赤 255・緑 128・青 0（オレンジ色） |
| 16進ダンプ（メモリやファイルの中身） | `41 42 43` | 1 バイトを 16進 2 桁で並べたもの。文字コード（ASCII）では 41 = A、42 = B、43 = C |
| 文字コード | `E3 81 82` | 「あ」を UTF-8 で表した 3 バイト。同じ「あ」が Shift_JIS では `82 A0` になる |
| ファイルの権限（Unix 系 OS） | `chmod 754` | 所有者・グループ・その他の 3 組について、読取り（r）・書込み（w）・実行（x）の 3 ビットを 8進 1 桁で書く |
| IPv6 アドレス | `2001:db8::1` | 128 ビットを 16 ビットずつ 8 つに区切り、それぞれを 16進 4 桁で書く（[IPv6](../../../network/ip/ip-address/ipv6/) の記事を参照） |
| MAC アドレス | `00:1A:2B:3C:4D:5E` | 48 ビットを 1 バイトずつ 16進 2 桁で書く。前半 24 ビットは製造者を表す番号（OUI） |
| IPv4 アドレス | `192.168.1.10` | 32 ビットを 1 バイトずつ 10進数で書く（ドット付き 10進表記）。サブネットの計算では 2進数に直して考える |

### ファイルの権限と 8進数

Unix 系 OS（Linux など）のファイルには、**所有者**・**グループ**・**その他** の 3 組それぞれに、読取り（r）・書込み（w）・実行（x）の権限があります。r・w・x を 1 ビットずつ並べた 3 ビットが、ちょうど 8進数 1 桁になります（r = 4、w = 2、x = 1 の重みを足した値）。

| 8進数 | 2進数 | 権限 | 意味 |
| --- | --- | --- | --- |
| 7 | 111 | `rwx` | 読取り・書込み・実行ができる |
| 6 | 110 | `rw-` | 読取り・書込みができる |
| 5 | 101 | `r-x` | 読取り・実行ができる |
| 4 | 100 | `r--` | 読取りだけできる |
| 0 | 000 | `---` | 何もできない |

`chmod 754 run.sh` は「所有者 7（rwx）・グループ 5（r-x）・その他 4（r--）」という意味で、`ls -l` では `-rwxr-xr--` と表示されます。

### プログラムでの基数変換

多くの言語には基数変換の関数が用意されています。Python の例です（`#` 以降は結果）。

```python
int("101101", 2)      # 45      （2進数の文字列 → 整数）
int("ff", 16)         # 255     （16進数の文字列 → 整数）
bin(45)               # '0b101101'
hex(45)               # '0x2d'
oct(493)              # '0o755'
format(45, "08b")     # '00101101'（8桁にそろえた 2進数）
format(255, "02X")    # 'FF'      （2桁にそろえた 16進数・大文字）
"あ".encode("utf-8").hex(" ")   # 'e3 81 82'（文字をバイト列にして 16進で表示）
```

## 実際の進め方: 基数変換を速く正確に行う

1. **2進数・8進数・16進数どうしは 10進数を経由しない**: 2進数を小数点から左右に 4 桁（16進）または 3 桁（8進）ずつ区切るだけで変換できます。16進 → 8進は、いったん 2進数に直してから 3 桁ずつ区切り直します。
2. **10進数 → 2進数は「大きい 2 のべき乗から引く」方法も使う**: 2 で割り続ける方法のほか、$45 = 32 + 8 + 4 + 1$ のように引ける最大の 2 のべき乗を順に引いていき、使った重みの桁を 1 にする方法もあります。128・64・32・16・8・4・2・1 を覚えておくと速くなります。
3. **16進数 1 桁と 2進数 4 桁の対応（0〜F）を覚える**: 上の対応表の 8 = `1000`、A = `1010`、F = `1111` を起点にすると思い出しやすくなります。
4. **検算する**: 求めた答えを逆向きに変換して元の値に戻るかを確かめます。

よくある失敗は、区切る方向を間違えることです。**整数部は小数点から左へ、小数部は小数点から右へ** 区切り、足りない桁は整数部なら左端、小数部なら右端に 0 を補います（例: $(0.1)_2$ を 16進数にするとき、`0.0001` ではなく `0.1000` と補って $(0.8)_{16}$）。

## 事例: あおば書店のサイト改修

架空のオンライン書店「あおば書店」で、Web サイトの改修を担当した開発者が、次の 3 つの作業で基数変換を使いました。

**1. ブランドカラーをカラーコードにする**

デザイナーから「ブランドカラーは RGB(46, 125, 50)」と指定されました。CSS では 16進数のカラーコードで書くので、各値を 16進 2 桁に変換します。

| 色 | 10進数 | 16で割る | 16進数 |
| --- | --- | --- | --- |
| 赤（R） | 46 | 2 余り 14 | 2E |
| 緑（G） | 125 | 7 余り 13 | 7D |
| 青（B） | 50 | 3 余り 2 | 32 |

結果は `#2E7D32` です。Python の `"#{:02X}{:02X}{:02X}".format(46, 125, 50)` でも同じ `'#2E7D32'` が得られることを確かめました。

**2. 設定ファイルの権限を決める**

データベースのパスワードを書いた設定ファイルは、Web アプリ（所有者）が読み書きでき、同じグループの運用担当者は読むだけ、その他の利用者は何もできないようにしたい、という要件でした。

- 所有者: `rw-` = `110` = 6
- グループ: `r--` = `100` = 4
- その他: `---` = `000` = 0

したがって `chmod 640 config.ini` とし、`ls -l` で `-rw-r-----` と表示されることを確認しました。誤って `chmod 644` にすると、その他の利用者にも読取り（4 = `r--`）を許してしまいます。

**3. 文字化けの原因を調べる**

取引先から受け取った書籍一覧の CSV ファイルで、書名が文字化けしました。ファイルの先頭を 16進ダンプで見ると、「あおば」の部分が `82 A0 82 A8 82 CE` となっていました。UTF-8 なら `E3 81 82 E3 81 8A E3 81 B0`（1 文字 3 バイト）になるはずなので、このファイルは **Shift_JIS**（1 文字 2 バイト）で書かれていると分かり、読み込むときの文字コードの指定を直して解決しました。

## 例題

**例題1** 10進数の 45 を 2進数と 16進数で表しなさい。

**解き方**

1. 2で割り続ける: 45→22 余り1、22→11 余り0、11→5 余り1、5→2 余り1、2→1 余り0、1→0 余り1
2. 余りを下から読むと `101101`
3. 4桁ずつ区切る: `0010 1101` → `2D`

答え: $(101101)_2$、$(2\text{D})_{16}$

**例題2** 16進数の小数 0.C を 10進数で表しなさい。

**解き方**: C = 12、小数第1位の重みは $16^{-1} = \dfrac{1}{16}$ なので $\dfrac{12}{16} =$ **0.75**。
（2進数経由でも `0.1100` $= 0.5 + 0.25 = 0.75$ となり一致します）

**例題3** 次の 10進小数のうち、2進数で有限桁で正確に表せるものはどれか。 (ア) 0.1 (イ) 0.2 (ウ) 0.3 (エ) 0.5

**解き方**: 2進数で有限桁になるのは、分母が 2 のべき乗の分数で表せる小数です。$0.5 = \dfrac{1}{2}$ なので **(エ)**。$0.1 = \dfrac{1}{10}$、$0.2 = \dfrac{1}{5}$、$0.3 = \dfrac{3}{10}$ はいずれも分母に 5 が残るため循環小数になります。

## 試験対策のポイント

- **ITパスポート**: 2進数 ⇔ 10進数の整数の変換、n ビットで表せる数（$2^n$ 通り）が中心です。
- **基本情報技術者**: 小数を含む変換、16進数との相互変換、「2進数で正確に表せる小数はどれか」がよく出ます。分母が $2^k$ になるかで判定できます。
- **応用情報技術者**: 単独で問われるより、浮動小数点数やビット演算など他の問題の前提として使われます。計算を素早く正確に行えるようにしておきます。
- 2進数を左に 1 ビットシフトすると 2 倍、右に 1 ビットシフトすると $\dfrac{1}{2}$ になる（論理シフト、あふれ・切捨てがない場合）ことも合わせて覚えておくと便利です。
