**再帰** とは、関数（または手続）の処理の中で自分自身を呼び出すことです（**再帰呼出し**）。
「大きな問題を、同じ形をした小さな問題に分けて解く」アルゴリズムを短く書けるため、クイックソート・マージソート（分割統治法）や木の走査などで使われます。

## 仕組み

### 基底条件と再帰ステップ

再帰関数は必ず次の 2 つの部分から成ります。

| 部分 | 役割 | 階乗 n! の場合 |
| --- | --- | --- |
| 基底条件（終了条件） | それ以上自分を呼ばずに値を返す | $n \leqq 1$ なら 1 を返す |
| 再帰ステップ | 問題を小さくして自分自身を呼び出す | $n \times (n - 1)!$ を返す |

基底条件がない、または引数が基底条件に近づかないと、呼出しが無限に続いてしまいます。

```
○整数型: fact(整数型: n)
  if (n ≦ 1)
    return 1                  // 基底条件
  else
    return n × fact(n － 1)   // 再帰ステップ
  endif
```

### スタックとの関係

関数を呼び出すと、**戻り先** や **引数・局所変数** などの情報がスタックに積まれ、関数から戻るときに取り出されます。
再帰呼出しでは、呼出しのたびに新しい引数・局所変数の組がスタックに積まれるため、同じ関数でも呼出しごとに別々の値を保持できます。
最後に呼ばれたものから先に戻る（後入れ先出し、**LIFO**）ので、再帰の実現には **スタック** が適しています。

- 呼出しが深くなるほどスタックの使用量が増え、上限を超えるとスタックオーバフローになります
- 再帰で書いた処理は、スタックを自分で用意すれば繰返し（ループ）でも書けます
- 自分自身を呼び出して正しく動作するプログラムの性質を **再帰的（リカーシブ）** といいます。呼出しごとに局所変数を別々に持つ必要があるため、複数から同時に呼ばれても正しく動く **再入可能（リエントラント）** の考え方と関係が深い性質です

### fact(4) の呼出しと戻り

```
fact(4) → 4 × fact(3)           ← 呼出し（スタックに積む）
            fact(3) → 3 × fact(2)
                       fact(2) → 2 × fact(1)
                                  fact(1) → 1   （基底条件）
                       fact(2) = 2 × 1 = 2      ← 戻り（スタックから取り出す）
            fact(3) = 3 × 2 = 6
fact(4) = 4 × 6 = 24
```

呼出しの途中では掛け算は行われず、基底条件に達してから **戻りながら** 計算が進む点がポイントです。

## 代表的な再帰

| 例 | 定義 |
| --- | --- |
| 階乗 | $n! = n \times (n - 1)!$、$1! = 1$ |
| フィボナッチ数 | $\mathrm{fib}(n) = \mathrm{fib}(n - 1) + \mathrm{fib}(n - 2)$、$\mathrm{fib}(1) = \mathrm{fib}(2) = 1$ |
| 最大公約数（ユークリッドの互除法） | $\gcd(a, b) = \gcd(b,\ a \bmod b)$、$b = 0$ なら $a$ |
| ハノイの塔 | n 枚の移動回数は $2^n - 1$ 回 |

フィボナッチ数を上の定義どおり再帰で求めると、同じ値を何度も計算し直すため、呼出し回数が n に対して指数関数的に増えます。

## 実際のプログラムでの使われ方

再帰が力を発揮するのは、**データそのものが入れ子（同じ形の繰返し）になっている** ときと、**問題を同じ形の小さな問題に分けられる** ときです。

| 場面 | 何が「同じ形の小さな問題」か |
| --- | --- |
| フォルダの合計サイズ、ファイルの検索 | フォルダの中のフォルダも、同じ方法で調べればよい |
| Web ページ（HTML）や JSON の入れ子の処理 | 要素の中の要素も、同じ方法で処理すればよい |
| マージソート・クイックソート（分割統治法） | 半分（分割した一部）の並べ替えも、同じ並べ替え |
| 式の計算・プログラムの構文解析 | 括弧の中の式も、同じ「式」として計算する |
| 二分木の走査、二分探索 | 左右の部分木（半分の範囲）も、同じ方法でたどる |

## 事例: フォルダの合計サイズを求める

次のようなフォルダ構成で、docs フォルダの中にあるファイルの合計サイズ（KB）を求めます。

```
docs/
├─ memo.txt        3
├─ photos/
│   ├─ a.jpg     200
│   └─ b.jpg     150
└─ work/
    ├─ plan.txt    5
    └─ old/
        └─ v1.txt  2
```

「フォルダのサイズ ＝ 直下のファイルのサイズの合計 ＋ 直下の各フォルダのサイズ」と考えると、右辺のフォルダのサイズにも同じ考え方が使えるので、再帰でそのまま書けます。
Python で、フォルダを辞書（名前 → 中身）、ファイルをサイズの数値で表すと次のようになります。

```python
def total_size(folder):
    size = 0
    for item in folder.values():
        if isinstance(item, dict):     # フォルダなら
            size += total_size(item)   # 同じ関数で中身を調べる（再帰呼出し）
        else:                          # ファイルなら
            size += item
    return size

docs = {"memo.txt": 3,
        "photos": {"a.jpg": 200, "b.jpg": 150},
        "work": {"plan.txt": 5, "old": {"v1.txt": 2}}}
total_size(docs)   # 360
```

この関数には `if n ≦ 1` のような目立つ基底条件がありませんが、**中にフォルダを含まないフォルダ** では再帰呼出しが起きずに値を返すので、そこが基底条件の役割をします。呼出しと戻りの順は次のとおりです。

| 順 | できごと | 戻り値 |
| --- | --- | --- |
| 1 | total_size(docs) を呼ぶ。memo.txt の 3 を足す | |
| 2 | photos を見つけて total_size(photos) を呼ぶ（深さ 2） | |
| 3 | photos はファイルだけなので 200 ＋ 150 を返す | 350 |
| 4 | docs に戻って 3 ＋ 350 ＝ 353。work を見つけて total_size(work) を呼ぶ（深さ 2） | |
| 5 | work で plan.txt の 5 を足し、old を見つけて total_size(old) を呼ぶ（深さ 3） | |
| 6 | old はファイルだけなので 2 を返す | 2 |
| 7 | work に戻って 5 ＋ 2 ＝ 7 を返す | 7 |
| 8 | docs に戻って 353 ＋ 7 ＝ 360 を返す | 360 |

呼出しは4回（フォルダの数）、呼出しスタックが最も深くなるのは docs → work → old の3段です。
フォルダが何段の入れ子になっていても、関数を書き換える必要はありません。これが再帰で書く利点です。

### 呼出しの深さには上限がある

呼出しのたびに呼出しスタックを使うので、深すぎる再帰はスタックオーバフローを起こします。例えば Python は、標準の設定では再帰の深さがおよそ 1,000 を超えると `RecursionError` という例外で処理を止めます。
10万段の入れ子のように深さが大きくなりうるデータは、繰返し（ループ）と自前のスタックで処理します。

### 同じ計算を繰り返さない工夫（メモ化）

定義どおりの fib は同じ値を何度も計算します。一度計算した結果を覚えておき、2回目以降はそれを返す **メモ化** を使うと、fib(1)〜fib(n) をそれぞれ1回ずつ計算するだけになり、計算量は $O(n)$ に下がります。

```python
from functools import lru_cache

@lru_cache(maxsize=None)    # 引数ごとに結果を覚えておく
def fib(n):
    if n <= 2:
        return 1
    return fib(n - 1) + fib(n - 2)
```

同じ考え方で、小さい n から順に表を埋めていく方法（動的計画法）もあります。

## 実際の進め方: 再帰関数をトレースする

試験で再帰関数が出たら、次の手順で追います。

1. **基底条件を確かめる**: どの引数のときに、自分を呼ばずに何を返すかに印を付けます。
2. **引数が基底条件に近づくかを確かめる**: `n － 1`、`n ÷ 10`、`a mod b` のように、呼ぶたびに小さくなることを確認します。近づかなければ無限に呼び出し続けるプログラムです。
3. **呼出しの木（または呼出しの列）を書く**: 1つの呼出しから2回以上自分を呼ぶ関数（fib など）は木に、1回だけ呼ぶ関数（fact、gcd など）は1列に並べます。
4. **基底条件から順に値を確定させる**: 葉（一番深い呼出し）の値を書き、戻りながら上の値を計算します。小さい引数から表にしていく（`f(0)`、`f(1)`、`f(2)`、…）と速く確実です。
5. **問われているものを数える**: 戻り値なのか、呼出し回数（木の節の数）なのか、深さ（木の段数）なのかを読み違えないようにします。最初の呼出しを数えるかどうかも問題文で確かめます。

## 例題

**例題1** 次の関数で fib(5) を求めるとき、戻り値と、fib が呼び出される回数（最初の呼出しを含む）は。

```
○整数型: fib(整数型: n)
  if (n ≦ 2)
    return 1
  else
    return fib(n － 1) ＋ fib(n － 2)
  endif
```

**解き方**: 呼出しの木を書きます。

```
fib(5)
├─ fib(4)
│   ├─ fib(3)
│   │   ├─ fib(2)
│   │   └─ fib(1)
│   └─ fib(2)
└─ fib(3)
    ├─ fib(2)
    └─ fib(1)
```

戻り値は $\mathrm{fib}(5) = \mathrm{fib}(4) + \mathrm{fib}(3) = 3 + 2 =$ **5**。木の節の数を数えると呼出し回数は **9 回** です（fib(3) を 2 回計算している無駄が分かります）。

**例題2** gcd(48, 18) を、gcd(a, b) = 「b ＝ 0 なら a、そうでなければ gcd(b, a mod b)」で求めよ。

**解き方**

```
gcd(48, 18) → 48 mod 18 = 12 → gcd(18, 12)
gcd(18, 12) → 18 mod 12 = 6  → gcd(12, 6)
gcd(12, 6)  → 12 mod 6  = 0  → gcd(6, 0) → 6
```

答えは **6** です。

## 試験対策のポイント

- **基本情報技術者**: 科目Bで再帰関数のトレースが出題されます。呼出しの木や「呼出し → 戻り」の流れを書き出し、どの順で値が確定するかを追います。科目Aでは「再帰に適したデータ構造はスタック」が定番です。
- **応用情報技術者**: 再帰呼出しの回数や深さ、再帰を使ったアルゴリズム（分割統治法、木の走査）の計算量、再帰的（リカーシブ）・再入可能（リエントラント）といったプログラムの性質と組み合わせて問われます。
