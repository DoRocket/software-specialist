コンピュータは、キーボードやディスプレイ、ストレージなどの周辺装置と **入出力インタフェース** を通じてデータをやり取りします。
周辺装置を OS から使えるようにするのが **デバイスドライバ** で、CPU の負担を減らしながら入出力を行うための仕組みとして **DMA** や **割込み** があります。

## 前提となる用語

- **転送速度の単位**: インタフェースの規格の速度は **ビット/秒**（bps）、ファイルの大きさは **バイト** で表すのが普通です。1 バイト ＝ 8 ビットなので、5G ビット/秒の規格でも理論上の上限は $5 \times 10^9 \div 8 = 625 \times 10^6$、つまり 625M バイト/秒で、実際には制御や符号化のための余分なデータがあるため、さらに遅くなります。
- **規格とコネクタの形**: USB Type-C は **コネクタの形** の名前で、速度は USB 2.0（480M ビット/秒）、USB 3.2 Gen 1（5G ビット/秒）、USB 3.2 Gen 2（10G ビット/秒）、USB4（最大 40G ビット/秒など）のような **規格** で決まります。同じ Type-C の形でも、速度や映像出力への対応はケーブルや機器によって違います。
- **ボトルネック**: データが通る経路のうち、最も遅い部分です。経路全体の速さはここで決まります。

## 仕組み

### データ転送方式

| 方式 | 内容 | 特徴 |
| --- | --- | --- |
| シリアル転送 | 1 本の信号線で 1 ビットずつ順に送る | 信号線が少なく、高速化・長距離化しやすい。現在の主流 |
| パラレル転送 | 複数の信号線で複数ビットを同時に送る | 高速化すると信号のタイミングのずれ（スキュー）が問題になる |

かつてはパラレル転送が高速とされましたが、現在は USB・シリアル ATA・PCI Express など **高速なインタフェースの多くがシリアル転送** です。

### 有線インタフェース

| 名称 | 用途・特徴 |
| --- | --- |
| USB | 汎用のシリアルインタフェース。ハブを使ってツリー状に最大 127 台まで接続できる。ホットプラグ、バスパワー（ケーブル経由の電源供給）に対応。コネクタ形状に Type-A / Type-B / Type-C などがある |
| HDMI | 映像と音声を 1 本のケーブルでデジタル伝送する。テレビや PC のディスプレイ接続に使われる |
| DisplayPort | 主に PC 向けの映像・音声のデジタルインタフェース |
| DVI / アナログ RGB | ディスプレイ接続用。DVI はデジタル、アナログ RGB（VGA 端子）はアナログで映像を送る |
| シリアル ATA | HDD・SSD などのストレージを接続するシリアルインタフェース |
| Thunderbolt | 高速な汎用インタフェース。デイジーチェーン接続ができ、Type-C 形状のコネクタを使う |
| RS-232C | 古くからあるシリアルインタフェース。モデムや機器の設定用ポートなどで使われた |

### 無線インタフェース

| 名称 | 用途・特徴 |
| --- | --- |
| Bluetooth | 2.4GHz 帯を使う近距離無線（数 m〜数十 m）。マウス・キーボード・イヤホンなど。低消費電力版の **BLE（Bluetooth Low Energy）** は IoT 機器で多用される |
| IrDA | 赤外線を使う通信。機器同士を向かい合わせる（見通しが必要）。通信距離は 1m 程度 |
| NFC | 13.56MHz 帯を使う、10cm 程度の非接触通信。IC カードやスマートフォンの「かざす」決済 |
| Zigbee | 低速だが低消費電力で、多数のセンサーをつなぐネットワークに向く |

### 接続形態

| 形態 | 内容 | 例 |
| --- | --- | --- |
| スター / ツリー接続 | ハブを中心に機器を接続し、ハブを多段（カスケード）につなぐとツリー状になる | USB |
| デイジーチェーン接続 | 機器から機器へ数珠つなぎにする。終端に **ターミネーター** が必要な規格もある | Thunderbolt、SCSI |

### デバイスドライバ

**デバイスドライバ** は、OS と周辺装置の間に入り、装置ごとの違いを吸収して OS から共通の方法で操作できるようにするソフトウェアです。

- **プラグアンドプレイ**: 装置を接続すると OS が自動的に認識し、デバイスドライバの組込みや設定を行う機能
- **ホットプラグ**: コンピュータの電源を入れたまま装置を抜き差しできる機能（USB など）

### 入出力制御の方式

| 方式 | 仕組み | CPU の負担 |
| --- | --- | --- |
| プログラム制御方式 | CPU が入出力命令を実行し、データを 1 つずつ装置と主記憶の間で転送する | 大きい |
| DMA 方式 | **DMA コントローラ** が CPU を介さずに主記憶と入出力装置の間でデータを直接転送する。CPU は転送の開始を指示するだけで、終了は割込みで通知される | 小さい |
| チャネル制御方式 | 入出力専用のプロセッサ（チャネル）が入出力処理を代行する。主に大型汎用機で使われる | 小さい |

装置の状態を CPU が定期的に問い合わせて確認する方式を **ポーリング** といいます。これに対し、装置の側から完了などを通知する方式が **割込み** です。

### 割込み

実行中のプログラムを一時中断して、発生した事象に対応する処理（割込み処理）を行い、終わったら元のプログラムを再開する仕組みです。

| 分類 | 種類 | 発生要因の例 |
| --- | --- | --- |
| 外部割込み（CPU の外部が要因） | 入出力割込み | 入出力装置の動作完了、DMA 転送の終了 |
| | タイマ割込み | 一定時間の経過（タイムクウォンタムの終了など） |
| | 機械チェック割込み | 電源異常、ハードウェアの故障 |
| | コンソール割込み | オペレータによる操作 |
| 内部割込み（実行中の命令が要因） | プログラム割込み | ゼロ除算、オーバーフロー、不正な命令、ページフォールト |
| | SVC 割込み（スーパバイザコール） | プログラムが OS の機能を呼び出す |

割込みは OS のタスク管理とも関係しています。入出力の完了割込みによって、待ち状態のタスクが実行可能状態に移ります。

## 例題

**例題1** 次の事象によって発生する割込みを、内部割込みと外部割込みに分類しなさい。

1. プログラムで 0 による除算が行われた
2. プリンタの印刷処理が完了した
3. 仮想記憶で参照したページが主記憶上に存在しなかった
4. ハードウェアで電源異常が検出された

**解き方**: 実行中の命令が原因か、CPU の外部が原因かで判断します。

- 1（プログラム割込み）と 3（ページフォールト）は実行中の命令が原因なので **内部割込み**
- 2（入出力割込み）と 4（機械チェック割込み）は CPU の外部が原因なので **外部割込み**

**例題2** 大量のデータをディスクから主記憶へ読み込む場合に、DMA 方式がプログラム制御方式より有利な理由を説明しなさい。

**解き方**: プログラム制御方式では、CPU がデータを 1 つずつ転送するため、転送中は CPU がほかの処理を行えません。DMA 方式では **DMA コントローラが転送を代行** し、CPU は開始の指示と完了割込みの処理だけを行えばよいので、転送中に CPU を別の処理に使えます。

## 実際の進め方

### 自分の PC の接続を確かめる

| OS | 見る場所 | 分かること |
| --- | --- | --- |
| Windows | デバイスマネージャー | 認識された装置と、デバイスドライバの状態（問題があると「!」などの印が付く） |
| Windows | タスクマネージャーの「パフォーマンス」タブ →「ディスク」 | ディスクの種類（SSD・HDD）、読取り・書込みの速度、アクティブな時間（使用率） |
| macOS | 「システム情報」の「USB」「Thunderbolt/USB4」の項目 | つないだ装置と、つながっている速度 |
| Linux | `lsusb -t`、`lsblk`、`iostat -x 1`（sysstat パッケージ） | USB の接続と速度、ディスクの一覧、ディスクごとの使用率（`%util`）と待ち時間 |

Linux の `lsusb -t` の例です。出力は形式を示す例で、行末の数字が接続の速さ（M ビット/秒）を表します。

```
$ lsusb -t
/:  Bus 02.Port 1: Dev 1, Class=root_hub, Driver=xhci_hcd/4p, 10000M
    |__ Port 2: Dev 2, If 0, Class=Mass Storage, Driver=uas, 10000M
/:  Bus 01.Port 1: Dev 1, Class=root_hub, Driver=xhci_hcd/12p, 480M
    |__ Port 3: Dev 3, If 0, Class=Human Interface Device, Driver=usbhid, 12M
```

ストレージ（Mass Storage）は 10000M ＝ 10G ビット/秒で、キーボードなど（Human Interface Device）は 12M ビット/秒でつながっています。キーボードは送るデータが少ないので、これで十分です。

### インタフェースを選ぶ手順

1. **何をつなぎ、どれだけのデータを送るかを決める**: 外付け SSD でのデータの受渡し、ディスプレイ、マウス、センサーなど。
2. **必要な速さを見積もる**: 転送にかかる時間は「データ量 ÷ 実効の転送速度」で見積もれます（[ネットワークの性能](../../network/performance/) の伝送時間と同じ考え方）。
3. **経路全体で一番遅いところを確かめる**: PC のポート、ケーブル、ハブ、つなぐ装置そのもの（HDD の読み書きの速さなど）のうち最も遅いものが速さを決めます。両端の規格が違うときは、多くの場合、遅いほうの規格で動きます。
4. **電源を確かめる**: ケーブル経由の給電（バスパワー）で足りるか、AC アダプタが必要か。ノート PC を充電しながら使うなら、USB PD（USB Power Delivery）の給電に対応しているかも確かめます。
5. **無線なら距離・消費電力・見通し・干渉を考える**: 2.4GHz 帯は無線 LAN・Bluetooth・電子レンジなどが共用しており、混み合うと途切れることがあります。
6. **ドライバと組織の規程を確かめる**: OS が対応しているか、製造者のドライバが必要か。USB メモリの持込みを制限している組織もあります。

| 用途 | 候補になるインタフェース | 確かめること |
| --- | --- | --- |
| 外付け SSD での大きなデータの受渡し | USB 3.2 Gen 2（10G ビット/秒）以上、Thunderbolt | PC のポートとケーブルの両方が対応しているか |
| 4K ディスプレイ（60Hz） | HDMI 2.0 以降、DisplayPort、映像出力に対応した USB Type-C | 古い規格のケーブルや変換アダプタでは、30Hz に下がったり映らなかったりする |
| マウス・キーボード | USB、Bluetooth | 無線は電池の交換と、ペアリング（機器の登録）が必要 |
| 入退室カード・決済 | NFC | 通信距離は 10cm 程度 |
| 多数の電池駆動のセンサー | BLE、Zigbee | 消費電力と、届く距離 |

### 取り外しと書込みのキャッシュ

OS は、外付けのストレージへの書込みをいったん主記憶にためてから、まとめて装置に書くことがあります（キャッシュの **ライトバック** と同じ考え方で、速く見えます）。
そのため、「取り出し」の操作（Windows の「ハードウェアを安全に取り外してメディアを取り出す」、macOS の「取り出す」、Linux の `umount` など）をせずに抜くと、ためていたデータが書き込まれず、ファイルが壊れることがあります。
書込みのためかたは OS や設定によって違うので、いつも取り出しの操作をしてから抜くのが安全です。

### よくある失敗と対策

| 失敗 | 起きること | 対策 |
| --- | --- | --- |
| Type-C のケーブルなら速いと思い込む | 機器に付属の充電用ケーブル（USB 2.0 相当）で、480M ビット/秒しか出ない | ケーブルの対応規格（速度・映像出力・給電）を確かめる |
| USB 2.0 のポートや古いハブにつなぐ | 速い SSD でも遅いほうの規格で動く | 接続の速さを確かめ、速いポートに直接つなぐ |
| バスパワーの HDD を電源のないハブにつなぐ | 電力が足りず、認識しない・途中で切れる | AC アダプタ付き（セルフパワー）のハブを使うか、PC に直接つなぐ |
| 取り出しの操作をせずに抜く | 書込み途中のデータが壊れる | 取り出しの操作をしてから抜く |
| 変換アダプタを何段も重ねる | 解像度やリフレッシュレートが下がる、映らない | 対応規格を確かめ、なるべく直結のケーブルにする |
| 出所の分からないドライバを入れる | 動作が不安定になる、マルウェアに感染する | 製造者が配布するドライバを使う |

## 事例: みなと事務所の制作チーム

[みなと事務所](../../network/)（社員 30 名・4 階に制作チーム 12 名）で、制作チームから相談が 2 つありました。速度は説明のための仮の値です。

**1. 外付け SSD からのコピーが遅い**

撮影データ 100G バイトを、外付け SSD（10G ビット/秒の USB 3.2 Gen 2 に対応）から PC にコピーすると、50 分近くかかるとのことでした。
接続の速さを確かめると 480M ビット/秒（USB 2.0）で、机の上に置いた古い USB ハブを経由していました。実効の速さを 35M バイト/秒とすると、

$$
\dfrac{100 \times 10^9 \text{ バイト}}{35 \times 10^6 \text{ バイト/秒}} \fallingdotseq 2{,}857 \text{ 秒} \fallingdotseq 48 \text{ 分}
$$

で、相談の内容と合います。PC の 10G ビット/秒のポートに直接つなぎ、実効 800M バイト/秒が出たとすると、

$$
\dfrac{100 \times 10^9}{800 \times 10^6} = 125 \text{ 秒} \fallingdotseq 2 \text{ 分}
$$

に縮みます。参考に、NAS（192.168.20.10）へ有線 LAN（1G ビット/秒、伝送効率 70%）で送ると、実効は $1 \times 10^9 \times 0.7 \div 8 = 87.5 \times 10^6$ バイト/秒なので、

$$
\dfrac{100 \times 10^9}{87.5 \times 10^6} \fallingdotseq 1{,}143 \text{ 秒} \fallingdotseq 19 \text{ 分}
$$

です。そこで「撮影データの取込みは外付け SSD を PC に直結して行い、チームで共有するものだけを NAS に置く」と決めました。ハブはケーブルとともに、規格を確かめて買い直しました。

**2. 新しい 4K ディスプレイの表示がカクつく**

ノート PC の USB Type-C のポートから、以前から使っていた変換アダプタで HDMI に変換して 4K ディスプレイにつないでいました。ディスプレイの設定画面を見ると、リフレッシュレートが 30Hz になっていました。
アダプタの仕様を調べると HDMI 1.4 までの対応で、4K では 60Hz を出せないものでした。PC のポートが映像出力に対応していることを確かめ、USB Type-C と DisplayPort をつなぐケーブルで直結すると、60Hz で表示されるようになりました。

どちらも、PC・ケーブル・ハブ（アダプタ）・装置のうち **一番遅いところ** が全体を決めていた例です。

## 試験対策のポイント

- **ITパスポート**: USB・HDMI・Bluetooth・NFC などの用途と特徴、有線 / 無線の区別、デバイスドライバとプラグアンドプレイの役割が中心です。IoT 機器のインタフェース（BLE など）も押さえます。
- **基本情報技術者**: 各インタフェースの特徴（接続形態、ホットプラグ、通信距離）、DMA 方式の仕組み、割込みの分類（内部 / 外部）が問われます。「CPU を介さずに転送する」= DMA と即答できるようにします。
- **応用情報技術者**: 多重割込みの扱い、割込みとポーリングの比較、入出力制御方式の選択など、仕組みを踏まえた比較・判断が問われます。
