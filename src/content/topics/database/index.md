データベースは、複数の利用者やアプリケーションが同じデータを **矛盾なく・安全に・効率よく** 共有するための仕組みです。
データベースを管理するソフトウェアを **DBMS**（DataBase Management System）と呼び、現在の業務システムでは表形式でデータを扱う **関係データベース（RDB）** が中心です。

## この分野で学ぶこと

| 層 | トピック | 何がわかるか |
| --- | --- | --- |
| 設計の土台 | 関係モデルとキー | データを「表（関係）」として捉える考え方、主キー・外部キー、関係演算 |
| 設計の手法 | 正規化 | 重複や更新時の矛盾（更新時異状）を防ぐための表の分割方法 |
| 操作言語 | SQL | 表の定義（DDL）と、データの検索・更新（DML） |
| 運用の仕組み | トランザクション | 同時実行や障害が起きてもデータを正しく保つ仕組み（ACID、排他制御、障害回復） |
| 設計の実践 | データベース設計と E-R図 | 概念・論理・物理設計の流れ、E-R図から表への変換、インデックス |
| 活用 | データの活用 | データウェアハウス、データマイニング、ビッグデータ、NoSQL |

## 学ぶ順序

1. **関係モデルとキー** で「表・行・列・キー」の用語と、選択・射影・結合といった操作の意味を押さえます。
2. **正規化** で、どのように表を分ければよいかを学びます。関数従属やキーの理解が前提になります。
3. **SQL** で、設計した表を実際に定義・検索する方法を学びます。結合や副問合せは関係演算の考え方そのものです。
4. **トランザクション** で、多数の利用者が同時に更新する場面や障害発生時に、データの整合性がどう守られるかを学びます。
5. **データベース設計と E-R図** で、業務の情報を E-R図で表し、正規化された表に落とし込む設計の流れを通して学びます。
6. **データの活用** で、蓄積したデータを分析に生かす仕組みと、関係データベース以外の選択肢（NoSQL）を学びます。

ITパスポート試験では用語と役割の理解、基本情報技術者試験では SQL の読解や正規化の判定、応用情報技術者試験ではそれらを組み合わせた設計・障害回復の考察まで問われます。
