設計は、要件定義で決めた「何を作るか」を、「どのような構造で作るか」に落とし込む工程です。
処理の流れに着目する **構造化設計** と、データと操作をひとまとめにする **オブジェクト指向設計** が代表的な考え方で、図の表記法として **UML** が広く使われます。

## 構造化設計

機能を段階的に分解し、プログラムを独立性の高いモジュールに分割します。データの流れは **DFD（データフロー図）** で表します。

| 分割技法 | 考え方 |
| --- | --- |
| STS分割 | データの流れを「源泉（Source）→変換（Transform）→吸収（Sink）」に分ける |
| TR分割 | 入力データの種類（トランザクション）ごとに処理を分ける |
| 共通機能分割 | 複数箇所で使う共通処理を独立したモジュールにする |

### 凝集度と結合度

良い設計は **モジュール内の凝集度が強く、モジュール間の結合度が弱い** 状態です。

| 凝集度（上ほど強く望ましい） | 内容 |
| --- | --- |
| 機能的凝集 | 単一の機能だけを実行する |
| 情報的凝集 | 同じデータを扱う複数の機能をまとめ、機能ごとに入口を持つ |
| 連絡的凝集 | 同じデータを使う処理を順番に実行する |
| 手順的凝集 | 決められた順序で実行する処理をまとめる |
| 時間的凝集 | 初期化処理など、同じ時期に実行する処理をまとめる |
| 論理的凝集 | 関連する複数機能を引数などで切り替えて実行する |
| 暗合的凝集 | 関係のない処理を寄せ集めた |

| 結合度（上ほど弱く望ましい） | 内容 |
| --- | --- |
| データ結合 | 必要な単一データ項目だけを引数で渡す |
| スタンプ結合 | 構造体などのデータ構造を丸ごと渡し、その一部を使う |
| 制御結合 | 処理を切り替えるためのフラグなど制御情報を渡す |
| 外部結合 | 単一のデータ項目を外部宣言（グローバル変数）で共有する |
| 共通結合 | データ構造全体を共通域（グローバル領域）で共有する |
| 内容結合 | 他のモジュールの内部を直接参照・変更する |

## オブジェクト指向

データ（属性）と操作（メソッド）を **オブジェクト** としてまとめ、その設計図を **クラス** と呼びます。

| 概念 | 説明 |
| --- | --- |
| カプセル化 | 内部のデータを隠蔽し、メソッド経由でのみ操作させる |
| 継承（インヘリタンス） | スーパクラスの属性・操作をサブクラスが引き継ぐ |
| 汎化・特化 | 共通部分をまとめて上位クラスにするのが汎化、その逆が特化（is-a 関係） |
| 集約 | 全体と部分の関係（part-of 関係） |
| ポリモーフィズム（多態性） | 同じメッセージに対し、オブジェクトごとに異なる振る舞いをする |

## 主なUML図

UML（Unified Modeling Language）は、OMG が標準化したモデリング言語です。図は大きく構造図と振る舞い図に分かれます。

| 種類 | 図 | 表すもの |
| --- | --- | --- |
| 構造図 | クラス図 | クラスの属性・操作と、クラス間の関連・多重度・汎化 |
| 構造図 | コンポーネント図 / 配置図 | ソフトウェア部品の構成 / ハードウェアへの配置 |
| 振る舞い図 | ユースケース図 | アクター（利用者や外部システム）とシステムの機能の関係 |
| 振る舞い図 | アクティビティ図 | 処理の流れ（分岐・並行処理を含む） |
| 振る舞い図 | シーケンス図 | オブジェクト間のメッセージのやり取りを時系列で表す |
| 振る舞い図 | ステートマシン図 | イベントによる状態の遷移 |
| 振る舞い図 | コミュニケーション図 | オブジェクト間の関係に着目したメッセージのやり取り |

クラス図の関連には **多重度** を書きます。例えば「顧客 1 ―― 0..* 注文」は、1人の顧客が0件以上の注文を持ち、1件の注文は1人の顧客に属することを表します。
集約は白抜きのひし形、より強い全体と部分の関係（部分が全体と生存期間を共にする）である **コンポジション** は黒塗りのひし形で表します。

## 例題

**問** 呼出し元が「処理区分フラグ」を引数で渡し、呼出し先モジュールがその値で処理を切り替えている。このモジュール間の結合は何か。

**解き方** 制御情報（フラグ）を渡して相手の動作を制御しているので **制御結合** です。必要なデータ項目だけを渡すデータ結合に比べて結合度は強くなります。

## 試験対策のポイント

- **ip**: UMLという言葉と、ユースケース図・クラス図・アクティビティ図などが何を表すかを押さえます。
- **fe**: 凝集度・結合度の強弱の順序と具体例、クラス図の多重度の読み取り、汎化と集約の区別が頻出です。
- **ap**: シーケンス図・ステートマシン図の読み取り、オブジェクト指向の概念を設計の場面に当てはめる問題に備えます。
