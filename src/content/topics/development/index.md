システム開発は、利用者の要求を整理し、設計・実装・テストを経て、運用できるシステムとして引き渡すまでの一連の活動です。
「どの順番で進めるか（プロセス）」「どう作るか（設計）」「正しく動くことをどう確かめるか（テスト）」の3つの観点で整理すると理解しやすくなります。

## 全体像

| 観点 | 主な内容 | 関連する問い |
| --- | --- | --- |
| 開発プロセス | ウォーターフォール、アジャイル、DevOps など | どの順序・単位で作業を進めるか |
| 要件定義 | 業務要件・機能要件・非機能要件、要件の獲得手法、共通フレーム | 何を作るべきかをどう決めるか |
| 設計 | 構造化設計、オブジェクト指向、UML、モジュール分割 | どのような構造で作るか |
| テスト | テスト工程、テスト技法、回帰テスト | 要求どおりに動くことをどう確認するか |
| 開発管理 | 構成管理・変更管理、見積り（ファンクションポイント法）、CMMI | 開発作業そのものをどう管理・改善するか |

一般的な工程は「要件定義 → 設計（外部設計・内部設計）→ 実装（プログラミング）→ テスト → 移行・運用・保守」と進みます。
どの工程でどの成果物を作り、どのテストで検証するかの対応関係（V字モデル）は、プロセス・設計・テストをつなぐ考え方です。

## 学ぶ順序

1. **開発プロセスモデル** … 工程の流れと、代表的なモデルの特徴・向き不向きを押さえます。
2. **要件定義** … 開発の出発点として、利用者の要求を要件として整理する方法を学びます。
3. **設計手法とUML** … モジュール分割の良し悪し（凝集度・結合度）と、UMLの図の読み方を学びます。
4. **テスト** … テスト工程の対応関係と、ブラックボックス／ホワイトボックスの技法を学びます。
5. **ソフトウェア開発管理技術** … 成果物の版を管理する構成管理や、開発規模の見積り方法を学びます。

開発作業を計画どおりに進めるための管理手法は「マネジメント」分野のプロジェクトマネジメントで扱います。
