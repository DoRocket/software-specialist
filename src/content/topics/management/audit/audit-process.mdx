システム監査は、**監査計画の策定 → 監査の実施（予備調査・本調査・評価・結論）→ 監査報告 → フォローアップ** という流れで進みます。
ここでは各段階で監査人が何をし、何を残すのか、そして証拠を集めるための **監査技法** を整理します。

## 監査の流れ

<AuditProcessFlow />

### 監査計画

監査人は、有効かつ効率的に監査を行うため、監査の目的・テーマ、対象範囲、方法、実施時期、実施体制、スケジュールなどを決めた **監査計画** を立てます。
監査にかけられる時間や人員には限りがあるので、リスクの大きい領域に重点的に監査資源を配分する **リスクアプローチ** で計画します。

| 計画の種類 | 内容 |
| --- | --- |
| 中長期計画 | 複数年にわたる監査の方針・重点テーマを示す |
| 年度計画 | その年度に実施する監査の対象・時期・体制などを示す |
| 個別監査計画 | 個々の監査ごとに、具体的な監査手続・日程・担当者などを示す |

資料によっては、年度計画を「基本計画」、個別監査計画を「個別計画」と呼ぶこともあります。
計画は固定ではなく、監査の途中で状況が変われば見直します。

### 予備調査と本調査

- **予備調査** … 監査対象の実態を大まかにつかむ段階です。関連する文書の閲覧、アンケート、関係者へのヒアリングなどで業務やシステムの概要と問題になりそうな点を把握し、本調査で実施する **監査手続** を具体的に決めます。
- **本調査** … 予備調査で決めた監査手続を実施し、監査の結論を裏付ける **監査証拠** を入手する段階です。後述の監査技法を使います。

### 評価・結論

入手した監査証拠に基づいて、コントロールが適切に整備・運用されているかを評価し、**監査の結論** を形成します。
結論は、監査人の推測ではなく、**十分かつ適切な監査証拠** に裏付けられていなければなりません。

### 監査報告とフォローアップ

監査人は **監査報告書** を作成し、**監査の依頼者**（経営者など）に報告します。報告書には、監査の目的・範囲、監査の結論のほか、問題点を示す **指摘事項** と、その **改善提案** を記載します。
報告の後は、改善提案や、監査対象部門が作成した **改善計画** への措置が適切かつ適時に実施されているかを確認する **フォローアップ** を行い、結果をフォローアップ報告書にまとめます。

改善を **実施するのは監査対象部門** であり、監査人自身が改善を行うわけではない点が重要です。

## 監査証拠と監査調書

**監査証拠** は、監査人の結論を裏付けるために必要な情報です。例えば次のようなものがあります。

| 監査証拠の例 | 何を確かめるのに使うか |
| --- | --- |
| アクセスログ | 権限のない利用者がアクセスしていないか |
| トランザクションログ | 取引が漏れなく正しく処理されたか |
| 運用・保守の記録 | 手順どおりに運用・変更されているか |
| インシデント報告書 | インシデントが適切に報告・対応されたか |
| 進捗管理資料 | 開発プロジェクトが計画どおり管理されているか |

処理の流れを後から追跡できるようにした記録を **監査証跡** といいます。情報システムは、監査証拠を円滑に入手できるよう、監査証跡を残す仕組みを備えておくことが望まれます。
一方で、監査のためだけの文書作成を開発・運用の現場に求めて負担をかけないよう配慮することも望ましいとされています。

**監査調書** は、監査人が実施した手続、入手した証拠、評価の過程を、結論に至った筋道が分かるように整理して記録した文書です。
監査報告書を作成するときの基礎資料となり、監査結果の裏付けになります。監査人は監査調書を作成し、適切に **保管** します。

## 監査技法

本調査で監査手続を実施するための代表的な技法です。

| 監査技法 | 内容 |
| --- | --- |
| チェックリスト法 | 監査人があらかじめ作成したチェックリストに、監査対象部門などから回答を求める |
| ドキュメントレビュー法 | 文書や記録（規程、設計書、運用記録など）を収集・閲覧して確かめる |
| インタビュー法 | 関係者に直接質問して回答を得る。質問書・調査票を使うこともある |
| ウォークスルー法 | データの発生から入力・処理・出力・活用に至る一連の流れと、そこに組み込まれたコントロールを、書類上または実際に追跡して確かめる |
| 突合・照合法 | 関連する複数の記録を突き合わせる。また、記録された結果を原始資料（伝票など）までさかのぼって突き合わせる |
| 現地調査法 | 監査人が現場に出向き、作業やシステムの状況を自ら観察・調査する |
| 統計的サンプリング | 母集団から統計的な手法で標本を抽出して検証し、その結果から母集団の状態を推定する |

### コンピュータ支援監査技法（CAAT）

大量のデータや、目に見えない処理の中身を検証するには、コンピュータを使った監査技法 **CAAT**（Computer Assisted Audit Techniques）を使います。

| 技法 | 内容 |
| --- | --- |
| 監査ソフトウェア | 汎用の監査ソフトウェアで、データの抽出・集計・比較などを行う |
| データサンプリング・データ分析 | ログなどの大量のデータから標本を抽出したり、傾向や異常値を分析したりする |
| テストデータ法 | 監査人が用意したテストデータを監査対象のプログラムで処理させ、その結果を監査人が想定した結果と比較して、処理の正しさを確かめる |
| 監査モジュール法 | 監査対象のプログラムに監査用のモジュールを組み込み、本番の処理の中で条件に合う取引などを抽出・記録する |
| ペネトレーションテスト法 | 外部からの攻撃者の手口で実際にシステムへの侵入を試み、セキュリティ上の弱点がないかを確かめる |

このほか、過去の試験では次のような技法も出題されています。

| 技法 | 内容 |
| --- | --- |
| ITF法 | 本番のシステムに監査用の架空の口座などを設け、本番データと一緒にテストデータを処理させて結果を確かめる |
| スナップショット法 | プログラムの特定の箇所でその時点のデータを書き出し、処理の途中経過を確かめる |
| 並行シミュレーション法 | 監査人が用意した検証用のプログラムで本番と同じデータを処理し、本番の結果と比較する |

テストデータ法と並行シミュレーション法の違いは、「**データ** を監査人が用意する（プログラムは本番）」か、「**プログラム** を監査人が用意する（データは本番）」かです。

## 例題

**問1** 監査対象の業務で作成された出荷伝票と、販売管理システムに記録された出荷データを突き合わせて、入力漏れがないかを確かめた。用いた監査技法はどれか。

- ア インタビュー法
- イ ウォークスルー法
- ウ 突合・照合法
- エ 現地調査法

**解き方** 複数の記録（原始資料である伝票とシステムの記録）を突き合わせているので、正解は **ウ** です。

**問2** システム監査人が監査調書を作成する目的として、最も適切なものはどれか。

- ア 監査対象部門が改善計画を作成するときの手順書とするため
- イ 監査の結論に至った過程を記録し、監査報告書の作成の基礎資料と監査結果の裏付けとするため
- ウ 監査の依頼者に、監査報告書の代わりに提出するため

**解き方** 監査調書は監査人が実施した手続と入手した証拠、評価の過程を記録し、監査意見の根拠とする文書です。正解は **イ** です。

## 試験対策のポイント

- **ip**: 監査の流れ（計画 → 予備調査・本調査 → 評価・結論 → 報告 → フォローアップ）の順番と、監査報告書の提出先（監査の依頼者）を押さえます。
- **fe**: 監査証拠と監査調書の役割、フォローアップで監査人が行うこと（改善状況の確認であり、改善の実施ではない）が問われます。
- **ap**: 状況の説明から監査技法の名前を選ぶ問題が頻出です。特に CAAT のテストデータ法・監査モジュール法・ITF法・並行シミュレーション法は、「何を監査人が用意し、どこで処理するか」で見分けます。リスクアプローチに基づく計画や、どの監査証拠で何を確かめるかも問われます。
