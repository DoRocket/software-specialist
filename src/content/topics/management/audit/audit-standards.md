経済産業省は、システム監査に関する2つの基準を公表しています。**システム監査基準** は「監査人がどう監査を行うべきか」、**システム管理基準** は「組織が IT をどう管理すべきか」を示すものです。
2つの役割の違いと、システム監査基準が監査人に求める倫理・姿勢を押さえると、「監査人の行動として適切なものはどれか」という問題が解けるようになります。

## 前提となる用語

| 用語 | 意味 |
| --- | --- |
| 行為規範 | ある立場の人が、どう行動すべきかを定めたルール。システム監査基準は監査人の行為規範 |
| 判断尺度 | 監査対象が適切かどうかを判断する物差し（例: 「本番環境への変更は承認された変更要求に基づいて行う」） |
| コントロール | リスクを抑えるための管理の仕組み・手続。承認、職務分掌、アクセス制限、ログの点検など |
| 内部監査規程 | 内部監査の目的・権限・責任・報告の経路などを定めた社内規程 |

## 2つの基準の役割の違い

| | システム監査基準 | システム管理基準 |
| --- | --- | --- |
| 誰のためのものか | システム監査人 | 監査を受ける組織体（経営者・IT 部門など） |
| 何を示すか | 監査人の倫理、監査の体制整備・計画・実施・報告などの **行為規範** | IT ガバナンスと IT マネジメントを実践するための **実践規範** |
| 監査での使われ方 | 監査業務の品質を確保し、有効かつ効率的に監査を行うためのよりどころ | 監査対象が適切かを判断する **判断尺度**（監査上の判断尺度）の参照基準 |

例えると、システム監査基準は「審判が守るべきルール」、システム管理基準は「選手のプレーを評価するときの採点基準」に当たります。

システム管理基準は、IT ガバナンスに加えて、情報システムの企画・開発（アジャイル開発を含む）・運用・保守、外部サービスの利用など、IT マネジメントの各領域で組織が実施すべき事項を示しています。
監査人は、判断尺度を決めるときに管理基準を **客観的な参照基準** として用いることができます。ただし、組織の状況に合わせて項目を選んだり、他の基準（情報セキュリティ管理基準など）を使ったりしてもかまいません。

## 監査人に求められる倫理と姿勢

システム監査基準は、監査人に高い倫理観と次のような姿勢を求めています。

| 要求事項 | 内容 |
| --- | --- |
| 誠実性 | 監査人として誠実に業務を行い、倫理に反する行為をしない |
| 独立性 | 監査対象から独立した立場で監査を行う（下記） |
| 客観性 | 利害関係や先入観にとらわれず、証拠に基づいて公正に判断する |
| 専門的能力の保持と向上 | 監査に必要な知識・技能を持ち、継続的に高める |
| 正当な注意 | 専門職として求められる注意を払って監査を行う |
| 秘密の保持 | 監査で知り得た秘密を、正当な理由なく他に漏らしたり自らの利益に使ったりしない |

### 独立性

独立性は、監査の結論を信頼してもらうための前提です。試験では次の2つに分けて問われます。

- **外観上の独立性** … 監査対象と組織上・身分上の利害関係がないこと。例えば、監査対象部門に所属している人や、対象システムを開発した人は、そのシステムの監査人に適していません。
- **精神上の独立性** … 監査対象に対して公正かつ客観的な態度を保つこと。

内部監査部門は、監査対象の部門から独立させるため、経営者（社長など）の直属に置くのが一般的です。

### 専門的能力と他の専門家の利用

監査に必要な専門知識が足りない領域では、外部の専門家の支援を受けることがあります。その場合も、専門家の作業結果を監査の結論に用いるかどうかの判断と責任は監査人にあります。

## 体制の整備

監査の品質を一定に保つため、組織として監査の体制を整えることも求められます。

- **権限と責任の明確化** … 内部監査なら **内部監査規程**、外部に委託するなら **システム監査委託契約書** で、監査の目的・対象範囲・権限・責任を定めます。
- **ニーズの把握と品質の確保** … 監査の依頼者のニーズを把握し、監査の品質を評価・改善する仕組みを持ちます。

## 保証型監査と助言型監査

システム監査は、監査の目的に応じて次の2つに分けられます。

| | 保証を目的としたシステム監査 | 助言を目的としたシステム監査 |
| --- | --- | --- |
| 目的 | 監査対象のコントロールが判断尺度に照らして適切に整備・運用されていることを、一定の水準で **保証** する | コントロールの改善が必要な点を指摘し、**改善提案** を行う |
| 監査報告書の中心 | 保証の結論（意見） | 指摘事項と改善提案 |
| 主な使われ方 | 利害関係者や経営者に対して、管理の状況が適切であることを示す | 組織が自ら IT の管理を改善する |

2つを組み合わせて、保証を行ったうえで改善提案を添えることもあります。

## 監査人がしてよいこと・いけないこと

監査人の役割は **検証・評価して、保証や助言を行うこと** です。監査対象の業務そのものを行うと、自分の仕事を自分で評価することになり、独立性が損なわれます。

| してよい（監査人の役割） | してはいけない（独立性・倫理に反する） |
| --- | --- |
| 指摘事項を示し、改善提案を行う | 監査人自身がプログラムを修正するなど、改善を実施する |
| 改善の実施状況をフォローアップで確認する | 監査対象システムの運用業務を担当する |
| 監査報告の前に、指摘事項の事実関係を監査対象部門と確認する | 自分が開発・運用に関わったシステムを監査する |
| 監査の依頼者に監査報告書を提出する | 監査で知り得た情報を、正当な理由なく外部に漏らす |
| 判断尺度を、組織の状況に合わせて選ぶ | 証拠を集めずに推測で結論を出す |

## 実際の進め方

2つの基準は、監査の体制を整えるときと、1件ごとの監査を計画するときに使います。

1. **内部監査規程を定める** … 監査の目的、内部監査部門の位置付け（経営者の直属など）、監査人の権限（資料の閲覧、質問、立入り）、報告の経路、秘密の保持を書き、経営者の承認を得ます。外部に委託する場合は、同じ内容をシステム監査委託契約書で定めます。
2. **監査ごとに独立性を確かめる** … 担当する監査人が、監査対象の業務に最近関わっていないか、対象部門と利害関係がないかを、監査の着手前に確かめます。関わっていた期間の扱いは、社内のルールで決めておきます（下のワークシート）。
3. **能力が足りない領域を補う** … クラウド、自動化されたリリースの仕組み、セキュリティの診断など、専門知識が必要な領域は研修や外部の専門家で補います。専門家の作業結果を結論に使うかどうかは、監査人が判断します。
4. **監査の目的（保証か助言か）を決める** … 監査の依頼者のニーズを聞き、管理の状況を関係者に示したいのか（保証）、改善のきっかけにしたいのか（助言）を決めます。両方を組み合わせることもあります。
5. **判断尺度を作る** … システム管理基準などから、監査の目的と範囲に関係する項目を選び、組織の規程や実態に合わせて「何ができていれば適切か」を具体的に書きます。判断尺度は監査対象部門に事前に示しておくと、結論への納得が得られやすくなります。
6. **証拠に基づいて結論を出し、品質を確かめる** … 監査調書を監査部門の責任者がレビューし、結論が十分かつ適切な証拠に裏付けられているかを確かめます。監査の後には、依頼者や監査対象部門の意見を聞いて監査の進め方を改善します。
7. **秘密を守る** … 監査で入手した資料の保管場所・閲覧できる人・廃棄の時期を決め、監査以外の目的に使いません。

### ワークシート

監査人の独立性の確認表（監査ごとに記入して監査調書に綴じます）:

| 確認項目 | はい／いいえ | いいえの場合の対応 |
| --- | --- | --- |
| 監査対象の業務・システムの開発・運用に、社内ルールで定めた期間内に関わっていない | | 担当から外す |
| 監査対象部門の責任者と、親族などの特別な利害関係がない | | 担当から外す |
| 監査対象部門から、監査の結論に影響しうる依頼や利益を受けていない | | 内部監査部門の責任者に報告する |
| この監査の期間中、監査対象の業務を代行しない | | — |

判断尺度の作り方:

| 参照する基準 | 組織に合わせた判断尺度 | 確かめる証拠 |
| --- | --- | --- |
| システム管理基準などの該当する項目 | 社内規程・実態に合わせて「何ができていれば適切か」を具体的に書く | 記録・ログ・設定など |

### よくある失敗と対策

| 失敗 | 対策 |
| --- | --- |
| 人手が足りないので、対象システムを開発していた人を監査人にする | 着手前に独立性を確かめる。足りない場合は外部の監査人や他部門の協力を得る |
| 監査対象部門に頼まれ、監査人が設定の修正や手順書の作成を手伝う | 改善の実施は監査対象部門に任せ、監査人は改善提案とフォローアップにとどめる |
| システム管理基準の項目をそのまま全部チェックリストにする | 目的と範囲に関係する項目を選び、組織の実態に合わせて具体的にする |
| 判断尺度を示さずに監査し、結論に納得してもらえない | 判断尺度を計画の段階で監査対象部門に示しておく |
| 外部の専門家の報告をそのまま監査の結論にする | 専門家の作業の範囲と方法を確かめ、結論に使うかどうかを監査人が判断する |
| 保証なのか助言なのかがあいまいなまま報告する | 計画の段階で依頼者と監査の目的を合意し、報告書の冒頭に書く |

## 事例

架空の企業 **ツバメ情報システム** の内部監査室が、ヨヤクルの **変更管理**（本番環境へのプログラムの変更）を監査します。ヨヤクルは事前決済機能（[プロジェクトマネジメントの事例](../../project-management/schedule/)）のリリース後、毎週のように機能の変更をリリースしています（数値・状況は架空の設定です）。

**① 体制と独立性**: 内部監査室は内部監査規程で社長の直属とされ、全部門の資料を閲覧する権限があります。室員は室長と S さんの2名です。
S さんは2年前までヨヤクルの開発チームにいました。社内のルール（監査対象の業務に過去3年以内に関わった人は、その監査を担当しない）に照らして、S さんはこの監査から外し、別の領域の監査を担当してもらいました。

**② 専門家の利用**: ヨヤクルは、承認されたプログラムを自動で本番環境に反映する仕組み（リリースの自動化）を使っています。室長はこの仕組みの設定を評価する知識が足りないため、外部のシステム監査の専門家に設定の確認を依頼しました。専門家の確認の範囲と方法は室長が決め、結果を結論に使うかどうかも室長が判断します。

**③ 監査の目的**: 社長からは「事前決済を始めたので、変更管理がきちんと機能していることを、監査役や取引先に説明できるようにしたい」という要望がありました。そこで **保証を中心とした監査** とし、問題が見つかれば改善提案も添えることにしました。

**④ 判断尺度**: システム管理基準の変更管理などに関する考え方と、社内の変更管理規程を参照して、次の判断尺度を作り、監査の着手前にヨヤクル事業部に示しました。

| No. | 判断尺度 | 確かめる証拠 |
| --- | --- | --- |
| 1 | 本番環境への変更は、承認された変更要求に基づいて行われている | 変更要求と承認の記録、リリースの記録 |
| 2 | 変更はテスト環境で検証され、結果をレビューしたうえで本番に反映されている | テスト結果、レビューの記録 |
| 3 | 変更を作った開発者が、承認なしに本番に反映できない | リリースの仕組みの設定、権限の一覧 |
| 4 | 緊急の変更は、事後に速やかに承認を得ている | 緊急変更の記録と事後承認の記録 |

**⑤ 本調査と結論**: 直近6か月のリリース 60件から 25件を抽出し、No.1・2・4 を確かめました。通常の変更 22件はすべて判断尺度を満たしていましたが、緊急の変更 3件はいずれも事後承認の記録がありませんでした。
専門家の確認では、管理者の権限を持つ2名は承認の手順を飛ばして本番に反映できる設定になっていることが分かりました（No.3）。室長は、専門家が実際の設定画面と権限の一覧を確かめたことを調書で確認し、この結果を結論に使うと判断しました。

結論は「通常の変更については、判断尺度に照らして適切に整備・運用されている。ただし、緊急の変更（抽出した 3件すべてで事後承認の記録がない）と、管理者権限による承認の省略には改善が必要である」とし、改善提案として「緊急変更の事後承認の期限を規程に定め、承認の記録を週次で点検する」「管理者権限での反映には、もう1人の承認を必要とする設定にする」を挙げました。

**⑥ 監査人がしなかったこと**: 報告会でヨヤクル事業部長から「専門家の方に、ついでに設定を直してもらえないか」と頼まれましたが、室長は断りました。改善を監査の側で行うと、次の監査で自分たちの仕事を評価することになり、独立性が損なわれるためです。設定の変更はヨヤクル事業部が行い、内部監査室はフォローアップで確かめることにしました。

## 例題

**問1** システム監査人の行動のうち、独立性の観点から問題があるものはどれか。

- ア 監査で発見したアクセス権限の設定誤りについて、監査報告書で改善提案を行った。
- イ 監査対象のシステムの運用担当者が不足していたので、監査期間中に監査人がバッチ処理の運用を代行した。
- ウ 監査報告書の作成前に、指摘事項の内容に事実誤認がないか監査対象部門と確認した。
- エ 改善計画に基づく対応の状況を、フォローアップで確認した。

**解き方** イは監査人が監査対象の業務（運用）に関与しており、自らの業務を評価することになるため独立性を損ないます。正解は **イ** です。ア・エは監査人の本来の役割、ウは報告書の正確性を高めるための適切な手続です。

**問2** システム監査で、システム管理基準はどのように用いられるか。

- ア 監査人が守るべき行為規範として用いる。
- イ 監査対象が適切かどうかを判断する尺度の参照基準として用いる。
- ウ 監査報告書の様式として用いる。

**解き方** 監査人の行為規範はシステム監査基準です。システム管理基準は判断尺度の参照基準なので、正解は **イ** です。

## 試験対策のポイント

- **ip**: システム監査人が独立かつ客観的な立場であること、システム監査基準が経済産業省によるものであることを押さえます。
- **fe**: システム監査基準（監査人の行為規範）とシステム管理基準（判断尺度）の違い、正当な注意と秘密の保持、保証型と助言型の違いが問われます。
- **ap**: 具体的な場面で監査人の行動が適切かを判断する問題が中心です。「監査人が業務や改善の実施に関与していないか」「証拠に基づいているか」「独立性を損なう関係がないか」の3点で確かめます。
