組織が受ける監査は、システム監査だけではありません。何を対象にするか、法律で義務付けられているか、誰が行うかによって、さまざまな種類があります。
ここでは、システム監査と関わりの深い監査の種類と、監査で遵守状況を確かめる関連法規を整理します。

## 前提となる用語

| 用語 | 意味 |
| --- | --- |
| 監査役 | 会社法に基づいて置かれ、取締役の職務の執行などを監査する機関 |
| 審査 | 認証機関などが、組織が規格や制度の要求事項を満たしているかを確かめ、認証やマークの使用を認めるかを判断すること |
| 再委託 | 委託を受けた会社が、その作業の一部をさらに別の会社に委託すること |
| 偽装請負 | 契約は請負なのに、実態は発注者が受託者の要員に直接指揮命令している状態。労働者派遣法などの規制を逃れることになる |

## 監査の種類

### 対象による分類

| 種類 | 対象・目的 |
| --- | --- |
| 会計監査 | 財務諸表などの会計記録が適正に作成されているかを確かめる |
| 業務監査 | 会計以外の業務活動全般が、適正かつ効率的に行われているかを確かめる |
| システム監査 | 情報システムに係るリスクに適切に対応しているかを確かめる |
| 情報セキュリティ監査 | 情報資産を守るための情報セキュリティ対策が適切かを確かめる |

### 根拠・実施者による分類

| 分類 | 内容 | 例 |
| --- | --- | --- |
| 法定監査 | 法律で義務付けられている監査 | 金融商品取引法に基づく公認会計士・監査法人の監査、会社法に基づく会計監査人や監査役の監査 |
| 任意監査 | 組織が自らの判断で行う監査 | 多くのシステム監査、情報セキュリティ監査 |
| 内部監査 | 組織内の監査部門などが行う | 内部監査部門によるシステム監査 |
| 外部監査 | 組織の外部の専門家が行う | 監査法人、外部のシステム監査人 |

上場会社などでは、公認会計士（監査法人）による監査、監査役などによる監査、内部監査人による監査が並行して行われます（三様監査と呼ばれます）。
システム監査も、これらの監査と情報を共有し、重複や漏れがないよう連携・調整しながら行います。
内部監査の実施については、日本内部監査協会の **内部監査基準** や、IIA（内部監査人協会）の **専門職的実施の国際フレームワーク（IPPF）** が参照されます。

## システム関連のさまざまな監査

| 監査 | 目的 | 主な基準・制度 |
| --- | --- | --- |
| 情報セキュリティ監査 | 情報セキュリティ対策の整備・運用状況を、独立かつ専門的な立場から検証・評価する | 情報セキュリティ監査基準（監査人の行為規範）、情報セキュリティ管理基準（判断尺度）、クラウド情報セキュリティ管理基準（クラウドサービスの利用・提供を対象とする判断尺度） |
| 個人情報保護監査 | 個人情報が適切に取り扱われ、漏えいなどのリスクに対応しているかを確かめる | JIS Q 15001（個人情報保護マネジメントシステム）、プライバシーマーク制度 |
| コンプライアンス監査 | 法令や社内規程、行動指針が守られているかを確かめる | 行動指針、職務分掌、倫理、透明性の確保 |
| マネジメントシステム監査 | 品質・環境・情報セキュリティ・サービス・事業継続などのマネジメントシステムが、規格や組織の決めた要求事項に適合し、有効に運用されているかを確かめる | JIS Q 19011（マネジメントシステム監査のための指針） |

情報セキュリティ監査基準と情報セキュリティ管理基準も経済産業省が公表しており、「監査人の行為規範」と「判断尺度」という関係は、システム監査基準とシステム管理基準と同じです。
情報セキュリティ管理基準は、情報セキュリティマネジメントシステムの規格（JIS Q 27001・JIS Q 27002）をもとにしています。

**プライバシーマーク制度** は、JIS Q 15001 に基づいて個人情報を適切に取り扱う体制を整えている事業者を評価し、マークの使用を認める制度です。

マネジメントシステム監査は、誰が行うかで次のように分けられます。

| 区分 | 実施者 |
| --- | --- |
| 第一者監査 | 組織自身（内部監査） |
| 第二者監査 | 取引先など、組織に利害関係を持つ者 |
| 第三者監査 | 独立した外部の機関（認証機関による審査など） |

## 監査で遵守状況を確かめる関連法規

システム監査では、情報システムの構築・運用が関係する法令を守っているかも確かめます。違反があれば指摘事項として取り上げます。

| 分野 | 法規 | 監査で確かめることの例 |
| --- | --- | --- |
| 情報セキュリティ | 不正アクセス禁止法 | アクセス制御機能が適切に設けられているか |
| 情報セキュリティ | 刑法（電磁的記録不正作出及び供用、電子計算機損壊等業務妨害、電子計算機使用詐欺） | データの改ざんやシステムの不正利用を防ぐ統制があるか |
| 電子データの保存 | 電子帳簿保存法、電子署名法 | 帳簿・書類を電子データで保存する要件や、電子署名の扱いが守られているか |
| 個人情報 | 個人情報保護法、マイナンバー法 | 個人情報・特定個人情報の取得・利用・管理が適切か |
| 知的財産 | 著作権法、特許法、不正競争防止法 | ソフトウェアの不正コピーや、営業秘密の不適切な管理がないか |
| 労働 | 労働基準法、労働者派遣法 | 長時間労働がないか、請負契約の要員に発注者が直接指揮命令する（偽装請負）などがないか |
| 法定監査 | 金融商品取引法、会社法 | 財務報告に係る内部統制などが法定監査に対応できるよう整備されているか |

法令そのものの内容は「法務と知的財産」で詳しく扱います。

## 実際の進め方

組織は、自分で行う監査（内部監査、委託先への監査）と、外部から受ける監査・審査（会計監査、認証の審査、取引先からの確認）を並行して抱えています。ばらばらに対応すると、同じ資料を何度も作り、指摘の重複や漏れが起きるので、次のように調整します。

1. **年間の監査カレンダーを作る** … 1年間に行う・受ける監査を、時期・種類（第一者・第二者・第三者、法定・任意）・実施者・対象とともに一覧にします。
2. **監査どうしで情報を共有する** … 内部監査部門は、監査役や会計監査人と定期的に打ち合わせ、監査の計画と結果を共有します（三様監査の連携）。ほかの監査で十分に確かめられている領域は、重複して深く見る必要があるかを検討します。
3. **証拠を共通の置き場に整える** … 規程、手順書、権限の棚卸しの記録、変更の記録などは、どの監査でも求められます。保管場所と最新版を決めておくと、監査ごとに作り直さずに済みます。
4. **関連法規のチェックリストを作る** … 「法令 → 関係する業務 → 確かめること → 証拠」の対応表を作り、法改正や新しい業務の開始のたびに更新します。
5. **委託先への監査（第二者監査）を行う** … 委託契約に、監査を行う権利（資料の閲覧、立入り）と、再委託の事前承諾などの義務を書いておきます。チェックリストで確かめ、結果を委託先に伝えて是正を求めます。
6. **取引先からの監査・確認を受ける** … 質問票への回答には、回答を裏付ける証拠を添えられるようにします。指摘を受けたら、改善計画を作って期限までに対応します。

### ワークシート

監査カレンダーの型:

| 時期 | 監査・審査 | 区分 | 実施者 | 対象 | 社内の窓口 |
| --- | --- | --- | --- | --- | --- |
| | | 第一者／第二者／第三者、法定／任意 | | | |

関連法規のチェックリストの型:

| 法令 | 関係する業務 | 確かめること | 証拠 | 結果 |
| --- | --- | --- | --- | --- |
| | | | | 適合／指摘 |

### よくある失敗と対策

| 失敗 | 対策 |
| --- | --- |
| 監査ごとに同じ資料を依頼され、現場が疲弊する | 監査カレンダーで時期を調整し、共通の証拠の置き場を作る。監査どうしで結果を共有する |
| 認証の審査に通ったので、内部監査は不要と考える | 認証の審査は規格への適合を確かめるもので、範囲や目的が内部監査と異なる。リスクに応じて内部監査の対象を決める |
| 委託先に監査を申し入れたが、契約に根拠がなく断られる | 委託契約に監査の権利と、再委託の事前承諾などの義務を定めておく |
| 請負契約の委託先の要員に、現場の担当者が直接指示している | 指示の窓口を委託先の責任者に決め、キックオフで説明する。チャットなどの記録も監査で確かめる |
| 関連法規のチェックリストを作ったまま更新しない | 新しい業務・システムの開始時と法改正時に見直す |
| 取引先の質問票に「実施している」とだけ回答し、確認を求められて答えられない | 回答ごとに裏付けとなる記録を用意しておく |

## 事例

架空の企業 **ツバメ情報システム** が、ヨヤクルの事前決済機能（[プロジェクトマネジメントの事例](../../project-management/schedule/)）を始めた年度に関わった監査・審査を整理します（数値・状況は架空の設定です）。

**① 監査カレンダー**: ツバメは非上場で、ヨヤクルとケアノートで個人情報を扱うため、プライバシーマークを取得しています。

| 時期 | 監査・審査 | 区分 | 実施者 | 対象 |
| --- | --- | --- | --- | --- |
| 通年 | 監査役による監査 | 法定 | 監査役 | 取締役の職務の執行など |
| 第1四半期 | ヨヤクルの顧客データの監査（[監査の進め方](../audit-process/) の事例） | 第一者・任意 | 内部監査室 | アクセス権管理 |
| 第2四半期 | 決済代行会社 P社 からの、接続事業者としてのセキュリティ対策の確認 | 第二者 | P社 | 質問票と資料の確認 |
| 第2四半期 | ヨヤクルの変更管理の監査（[監査基準](../audit-standards/) の事例） | 第一者・任意 | 内部監査室 | 変更管理 |
| 第3四半期 | プライバシーマークの更新の審査 | 第三者 | 審査機関 | 個人情報保護の体制と運用 |
| 第3四半期 | 委託先 K社 への監査 | 第二者（ツバメが実施） | 内部監査室・開発部 | 委託先の情報セキュリティ |

**② 監査どうしの連携**: P社 の質問票には「アクセス権の定期的な見直しを行っているか」という項目がありました。第1四半期の内部監査で指摘を受けて半年ごとの棚卸しが始まっていたので、その実施記録を証拠として回答しました。内部監査室は四半期ごとに監査役と打ち合わせ、指摘事項とフォローアップの状況を共有しています。

**③ 関連法規のチェック**: 事前決済のプロジェクトに関係する法令について、内部監査室が次のように確かめました。

| 法令 | 関係する業務 | 確かめること | 結果 |
| --- | --- | --- | --- |
| 個人情報保護法 | 店舗の顧客データの取扱い、委託先への作業の委託 | 安全管理措置と、委託先の監督が行われているか。K社 の開発に本番の顧客データを渡していないか | 適合。K社 には架空のテストデータだけを渡していた |
| 労働者派遣法 | K社 の要員が結合テストの期間に常駐 | 発注者の社員が K社 の要員に直接作業を指示していないか（偽装請負） | **指摘**。結合テストの1週目に、ツバメの開発者が K社 の開発者にチャットで直接作業を指示していた記録があった |
| 著作権法 | K社 が作った店舗管理画面のプログラム | 著作権の帰属や利用の条件が契約で定められているか | 適合。契約で著作権をツバメに譲渡すると定めていた |

労働者派遣法に関する指摘は、プロジェクトの中で「指示は K社 の責任者を通す」ルールを改めて確認した後は直接の指示がないこと（[資源のマネジメント](../../project-management/resource/) の事例）をチャットの記録で確かめたうえで、再発防止として「委託先を使うプロジェクトのキックオフ資料に、指示の窓口のルールを必ず入れる」ことを開発部に提案しました。

**④ 委託先への監査（第二者監査）**: ヨヤクルの第2段階の開発も K社 に委託するため、契約で定めた監査の権利に基づき、K社 の情報セキュリティの状況を確かめました。チェックリストは「入退室の管理」「開発用 PC の管理」「ソースコードの保管」「要員の教育」「再委託」の5分野です。
その結果、K社 が結合テストの一部を別の会社に再委託していたのに、契約で定めた事前の承諾を得ていなかったことが分かりました。ツバメは K社 に是正を求め、再委託先の情報セキュリティの状況の報告と、今後は事前に承諾を得ることを約束してもらいました。

## 例題

**問** 情報セキュリティ監査において、監査対象の情報セキュリティ対策が適切かどうかを判断する尺度として用いるものはどれか。

- ア 情報セキュリティ監査基準
- イ 情報セキュリティ管理基準
- ウ システム監査基準
- エ JIS Q 19011

**解き方** 情報セキュリティ監査基準は監査人の行為規範、JIS Q 19011 はマネジメントシステム監査の進め方の指針です。判断尺度として用いるのは情報セキュリティ管理基準なので、正解は **イ** です。

## 試験対策のポイント

- **ip**: 会計監査・業務監査・システム監査・情報セキュリティ監査の対象の違いを押さえます。
- **fe**: 法定監査と任意監査、内部監査と外部監査の区別、情報セキュリティ監査基準と情報セキュリティ管理基準の役割、プライバシーマーク制度が問われます。
- **ap**: 他の監査との連携、各種マネジメントシステム監査の位置付けに加え、監査の場面で関係する法規（偽装請負、ソフトウェアの不正コピーなど）を指摘できるかが問われます。
