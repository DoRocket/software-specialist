コストの対象群は、プロジェクトに必要なコストを見積もって予算を作り、実績を監視して予算内に収めるためのプロセスです。
ソフトウェアの規模や工数の見積り技法（ファンクションポイント法・COCOMO など）は [ソフトウェア開発管理技術](../../../development/software-management/) で扱ったので、ここではプロジェクト全体の予算の組み立て方と、EVM を使った予測を中心に学びます。

## コストの対象群のプロセス

| プロセス | 内容 | 主なアウトプット |
| --- | --- | --- |
| コストの見積り | 活動やワークパッケージごとに必要な資源のコストを見積もる | コスト見積り |
| 予算の作成 | 見積りを積み上げ、時間軸に沿って配分した承認済みの予算を作る | 予算（コストベースライン） |
| コストの管理 | 実コストと予算を比べ、差異の原因を分析して是正処置をとる | 実コスト、予想コスト、変更要求 |

## コストの見積り技法

| 技法 | 考え方 | 長所 | 短所 |
| --- | --- | --- | --- |
| 類推見積り | 過去の類似プロジェクトの実績コストを基に、規模や難しさの違いを補正する | 早く、手間が少ない。初期段階で使える | 類似性の判断に頼るため精度は低め |
| パラメトリック見積り | 過去データから得た統計的な関係（単価 × 数量など）で計算する | 根拠となるデータが良ければ精度が高い | 使うモデルや単価が実態に合わないと外れる |
| ボトムアップ見積り | WBS のワークパッケージや活動ごとに見積もり、積み上げる | 精度が高い | 詳細な WBS が必要で、手間がかかる |
| 三点見積り | 楽観値・最可能値・悲観値から期待値を求める | 不確かさを見積りに反映できる | 3つの値を用意する必要がある |

プロジェクトの初期は情報が少ないので類推見積りで概算し、計画が詳しくなるにつれてボトムアップ見積りで精度を上げる、という使い分けが一般的です。
三点見積りの計算方法は [時間のマネジメント](../schedule/) と同じです。

### 例題（パラメトリック見積り）

過去の実績から、画面1本あたりの開発工数は 0.5人月、要員の単価は 1人月あたり 100万円と分かっている。画面 40本のシステムの開発コストを見積もれ。

**解き方** 工数は $40 \times 0.5 = 20$ 人月、コストは $20 \times 100 =$ **2,000万円** です。
「1本あたりの工数」のような係数（パラメータ）が実績から得られていることが前提です。

## 予算の作成とコストベースライン

承認されたコストの計画値を **コストベースライン** といい、EVM の PV（計画価値）の基準になります。
時間軸に沿って累積すると、初めは緩やかに、中盤で急に、終盤でまた緩やかに増える **S字カーブ** になるのが一般的です。

予算は、見積りに **予備（リザーブ）** を加えて段階的に組み立てます。

| 予備 | 備える対象 | 管理する人 |
| --- | --- | --- |
| コンティンジェンシー予備 | 特定済みのリスク（起こるかもしれないと分かっている事象）への対応 | プロジェクトマネージャ。コストベースラインに **含める** |
| マネジメント予備 | 特定されていない、予見できない事象 | 経営層など。コストベースラインに **含めず**、使うには承認が必要 |

$$
\def\arraystretch{2.2}
\begin{array}{ll}
\text{コストベースライン} &{}= \text{ワークパッケージのコスト見積りの合計} + \text{コンティンジェンシー予備} \\
\text{プロジェクト予算} &{}= \text{コストベースライン} + \text{マネジメント予備}
\end{array}
$$

### 例題（予算の構成）

ワークパッケージのコスト見積りの合計が 1,800万円、特定済みリスクに備えるコンティンジェンシー予備が 200万円、マネジメント予備が 100万円である。コストベースラインとプロジェクト予算を求めよ。

**解き方** コストベースラインは $1{,}800 + 200 =$ **2,000万円**、プロジェクト予算は $2{,}000 + 100 =$ **2,100万円** です。
EVM の BAC（完成時総予算）はコストベースラインの総額で、マネジメント予備は含みません。

## コストの管理と EVM による予測

EVM の基本指標（PV・EV・AC、SV・CV、SPI・CPI）は [プロジェクトマネジメント](../) で扱いました。
コストの管理では、現時点の評価にとどまらず、**このまま進むと最終的にいくらかかるか** を予測して手を打ちます。

| 指標 | 意味 |
| --- | --- |
| BAC（完成時総予算） | コストベースラインの総額 |
| EAC（完成時総コスト見積り） | 完成までにかかると予測される総コスト |
| ETC（残作業コスト見積り） | 今から完成までにかかると予測されるコスト（$\text{EAC} - \text{AC}$） |
| VAC（完成時差異） | $\text{BAC} - \text{EAC}$。負なら予算超過の見込み |
| TCPI（残作業効率指数） | 予算内に収めるために、残作業で必要なコスト効率 |

EAC の求め方は、今後の進み方をどう仮定するかで変わります。

| 仮定 | 計算式 |
| --- | --- |
| これまでの差異は一時的で、残作業は当初の予算どおりに進む | $\text{EAC} = \text{AC} + (\text{BAC} - \text{EV})$ |
| 今後も現在のコスト効率（CPI）が続く | $\text{EAC} = \text{AC} + \dfrac{\text{BAC} - \text{EV}}{\text{CPI}} = \dfrac{\text{BAC}}{\text{CPI}}$ |
| 今後はコスト効率とスケジュール効率の両方が影響する | $\text{EAC} = \text{AC} + \dfrac{\text{BAC} - \text{EV}}{\text{CPI} \times \text{SPI}}$ |

残作業の予算 $\text{BAC} - \text{EV}$ を、仮定した効率で割り戻して実コストに換算している、と考えると覚えやすくなります。

### 例題（EAC と TCPI）

BAC が 1,000万円のプロジェクトで、ある時点の PV が 500万円、EV が 400万円、AC が 500万円だった。

1. 今後も現在の CPI が続くとした場合の EAC と VAC を求めよ。
2. 残作業は当初予算どおりに進むとした場合の EAC を求めよ。
3. 予算 1,000万円に収めるために必要な TCPI を求めよ。

**解き方** まず効率指数を求めます。$\text{CPI} = \dfrac{400}{500} = 0.8$、$\text{SPI} = \dfrac{400}{500} = 0.8$ です。

1. $\text{EAC} = \dfrac{1{,}000}{0.8} =$ **1,250万円**、$\text{VAC} = 1{,}000 - 1{,}250 =$ **−250万円**（250万円の超過見込み）
2. $\text{EAC} = 500 + (1{,}000 - 400) =$ **1,100万円**
3. 残作業の予算は $1{,}000 - 400 = 600$ 万円、使える残りの予算は $1{,}000 - 500 = 500$ 万円なので、

$$
\text{TCPI} = \frac{\text{BAC} - \text{EV}}{\text{BAC} - \text{AC}} = \frac{600}{500} = 1.2
$$

これまで 0.8 だったコスト効率を、残作業では **1.2** に上げなければ予算内に収まりません。TCPI が 1 を大きく超える場合、予算どおりの完了は現実的でないと判断し、予算の見直し（変更要求）を検討します。

参考までに、CPI と SPI の両方が影響する仮定では $\text{EAC} = 500 + \dfrac{600}{0.8 \times 0.8} = 500 + 937.5 = 1{,}437.5$ 万円となり、どの仮定を置くかで予測が大きく変わることが分かります。

## 試験対策のポイント

- **fe**: 見積り技法の名前と考え方の対応（特に類推見積りとパラメトリック見積りの区別）、コストベースラインの意味、EVM の指標計算が問われます。EAC は「今後も CPI が続く」場合の $\text{BAC} \div \text{CPI}$ を確実に計算できるようにします。
- **ap**: コンティンジェンシー予備とマネジメント予備の違い（ベースラインに含むか、誰が管理するか）、仮定の違いによる EAC の計算、TCPI から対策を判断する問題が出題されます。
