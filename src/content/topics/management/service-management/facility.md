どれほど信頼性の高いサーバを用意しても、電気が止まる、部屋が高温になる、地震で建物が揺れる、部外者が入り込む、といった事態が起きればサービスは止まります。
**ファシリティマネジメント** は、コンピュータやネットワークを支える **施設（建物）と設備（電源・空調など）** を、安全・快適・低コストな状態に保つための管理です。
後半では、設備の点検計画の立て方と、データセンタやクラウドを選ぶときの確認項目を、架空の IT 企業の事例で見ます。

## 前提となる用語

| 用語 | 意味 |
| --- | --- |
| kW と kWh | kW（キロワット）はある瞬間の電力、kWh（キロワット時）は電力を使った量。10 kW の機器を 1 時間動かすと 10 kWh |
| 設備台帳 | 設備ごとに、設置場所・容量・製造年・保守契約・点検の記録・更新の予定をまとめた一覧 |
| ハザードマップ | 地震・洪水・土砂災害などの被害が想定される区域を示した地図。拠点の立地を評価するときに使う |
| 第三者認証・監査報告書 | 外部の機関が、事業者の管理の仕組みを基準に照らして評価した結果。データセンタやクラウドの事業者を、自分で立ち入らずに評価する材料になる |

## 仕組み

### ファシリティマネジメントの考え方

ファシリティマネジメントは、建物や設備を「壊れたら直すもの」ではなく **経営資源** として捉え、企画・管理・活用を通じて最適な状態に保つ考え方です。
データセンタなどの施設基盤では、次の観点のバランスをとります。

| 観点 | 内容 | 例 |
| --- | --- | --- |
| 安全性 | 災害・事故・不正侵入から設備と人を守る | 免震装置、消火設備、入退室管理 |
| 信頼性 | 電源・空調・回線が止まらないようにする | UPS、自家発電装置、電源や回線の冗長化 |
| 快適性 | 機器と作業者にとって適切な環境を保つ | 温度・湿度の管理、作業スペースの確保 |
| 経済性 | 建設から廃棄までの費用（ライフサイクル費用）を抑える | 修繕計画、省エネルギー化 |

### 電気設備

| 設備 | 役割 | ポイント |
| --- | --- | --- |
| UPS（無停電電源装置） | 停電や瞬時電圧低下（瞬低）のとき、内蔵の **蓄電池** から電力を供給する | 供給できるのは蓄電池の容量で決まる **短時間**。その間に自家発電装置へ切り替えるか、システムを安全に停止（シャットダウン）する |
| 自家発電装置（自家発電設備） | 燃料でエンジンを動かして発電し、**長時間の停電** に備える | 起動して電力を安定して供給できるまでに時間がかかるので、それまでを UPS でつなぐ。燃料の備蓄量で運転できる時間が決まる |
| 電源の冗長化 | 電力会社からの受電を 2 系統にする、UPS や配電経路を二重化する | 1 か所の故障や保守作業で全体が止まらないようにする |

停電が起きたときの流れは「停電 → UPS が即座に給電 → 自家発電装置が起動 → 自家発電装置からの給電に切替え」です。
UPS だけでは長時間の停電に耐えられず、自家発電装置だけでは起動までの間に電源が途切れる、という互いの弱点を補い合う組合せです。

**サージ** は、落雷などで電源線や通信線に瞬間的に発生する異常に高い電圧・電流です。機器を壊すおそれがあるので、**サージ防護デバイス（SPD）** や **アレスタ**（避雷器）を設置して、過電圧を大地へ逃がします。

### 建物と防災

| 対策 | 内容 |
| --- | --- |
| 耐震構造 | 柱や壁を強くして、地震の揺れに **耐える** 建物にする |
| 免震構造（免震装置） | 建物と地盤の間に免震装置を入れ、地震の揺れを建物に **伝えにくくする**。サーバラックの転倒や機器の損傷を防ぎやすい |
| 消火設備 | コンピュータ室では、水で機器を損傷しないよう **不活性ガス消火設備** や **ハロゲン化物消火設備** などのガス系の消火設備を使うことが多い。ガス系の消火設備は人体に危険なため、放出前に人を退避させる仕組みが必要 |
| 防災防犯設備 | 火災報知器、漏水検知器、監視カメラなど |

データセンタの設備の信頼性（電源・空調などの冗長性）を段階で格付けする **ティア（Tier）基準** があり、数字が大きい段階ほど冗長性が高く、止まりにくい施設であることを示します。

### 空調設備

サーバは大量の熱を出すので、空調が止まると短時間で室温が上がり、機器が停止・故障します。

| 用語 | 内容 |
| --- | --- |
| コールドアイル | サーバラックの **前面（吸気側）同士** を向かい合わせた通路。空調機からの冷気をここに送る |
| ホットアイル | サーバラックの **背面（排気側）同士** を向かい合わせた通路。機器の排熱が集まり、空調機に戻る |
| エアフロー | 空気の流れ。冷気と排気が混ざらないように設計すると冷却の効率が上がる |

コールドアイルとホットアイルを交互に並べ、さらに通路を囲って冷気と暖気を分離すると、空調の消費電力を減らせます。

### 通信設備

| 用語 | 内容 |
| --- | --- |
| MDF（主配線盤） | 建物の外から引き込んだ通信回線を、建物内の配線へ接続する主となる配線盤 |
| IDF（中間配線盤） | MDF からの配線を、各フロアなどに分配するための中間の配線盤 |

通信回線も、異なる通信事業者や異なる引込み経路を使って冗長化しておくと、1 つの回線障害でサービスが止まるのを防げます。

### 入退室管理

データセンタやサーバ室への **物理的な侵入** を防ぐ対策です。

| 対策 | 内容 |
| --- | --- |
| 入退室の認証と記録 | IC カードや生体認証で入室できる人を限定し、入退室の記録を残す |
| 共連れの防止 | 認証した人の後ろについて、認証せずに入室する（共連れ）のを防ぐ |
| アンチパスバック | 入室の記録がない IC カードでは退室できない（又は退室の記録がないと再入室できない）ようにして、共連れや IC カードの貸し借りを防ぐ |
| インターロック | 二重の扉で、一方の扉が閉じないともう一方の扉が開かないようにする。一度に 1 人ずつしか通れないので共連れを防げる |
| 施錠管理・監視カメラ | ラックや部屋の施錠、鍵の管理、映像による監視と記録 |

利用者の認証技術（IC カード、生体認証など）の詳しい仕組みは [認証技術](../../../security/authentication/) で扱います。

なお、自社の機器を事業者のデータセンタに設置して運用してもらう形態を **ハウジング**、事業者が用意したサーバを借りて使う形態を **ホスティング** といいます。どちらも、設備の管理を専門の事業者に任せられます。

### 施設・設備の維持保全

設備は使い続けるうちに劣化します。故障してから直す **事後保全** だけでなく、点検や部品交換を計画的に行って故障を防ぐ **予防保全** を組み合わせ、施設・設備を適正な状態に保ちます。
水道光熱費・保守費・修繕費などを含めた **ライフサイクル費用** を抑えるため、修繕計画を立てて施設・設備の長寿命化を図ります。

### グリーン IT

**グリーン IT** は、地球環境に配慮した IT の活用です。

| 考え方 | 内容 | 例 |
| --- | --- | --- |
| IT 自身の省エネ（Green of IT） | IT 機器やデータセンタの消費電力を減らす | 省電力の機器、仮想化によるサーバ台数の削減、空調の効率化 |
| IT による省エネ（Green by IT） | IT を使って社会全体のエネルギー消費を減らす | テレワークによる通勤の削減、ペーパーレス化 |

データセンタのエネルギー効率を表す代表的な指標が **PUE（Power Usage Effectiveness）** です。

$$
\text{PUE} = \frac{\text{データセンタ全体の消費電力}}{\text{IT 機器の消費電力}}
$$

全体の消費電力には、IT 機器のほかに空調・照明・電源設備の損失などが含まれるので、PUE は必ず 1 以上になり、**1 に近いほど効率がよい**（IT 機器以外に使う電力が少ない）ことを示します。
応用情報のシラバスには、このほか GEC などのデータセンタのエネルギー効率指標も挙がっています。

## 実際の進め方

### 設備の点検計画

設備は「壊れたら直す」では、壊れた瞬間にサービスが止まります。予防保全のために、設備台帳を作り、点検の頻度と内容を決めて記録を残します。点検項目の一般的な例です（具体的な項目と頻度は、設備のメーカーの推奨や保守契約に従って決めます）。

| 頻度 | 対象 | 確認すること |
| --- | --- | --- |
| 毎日（監視で自動化することが多い） | 空調・室内環境 | 室温・湿度が管理値の範囲か（サーバの吸気温度は、機器の仕様や、米国の業界団体 ASHRAE が示す推奨範囲 18〜27℃ などを参考に管理値を決める）。漏水検知器の警報がないか |
| 毎日 | UPS・分電盤 | 警報の有無、負荷率（容量に対してどれだけ使っているか） |
| 毎月 | 自家発電装置 | 試運転で起動できるか。燃料の残量 |
| 毎月 | 入退室管理 | 入退室記録の確認、退職者・異動者の権限の削除 |
| 毎年など定期 | UPS の蓄電池 | 劣化の状態。実際に停電させる試験で、何分給電できるか（保持時間）を測る |
| 毎年など定期 | 自家発電装置 | 負荷をかけた運転で、実際に必要な電力を出せるか |
| 毎年など定期 | 消火設備・防災設備 | 作動の確認、ガス系消火設備の放出前の退避の手順の訓練 |

点検の結果は設備台帳に記録し、劣化の傾向（UPS の保持時間が年々短くなっている、など）を見て、更新の時期を計画します。
停電試験のように実際に止めて確かめる点検は、サービスへの影響があるので、変更管理の手続で日時を決め、計画停止として告知します。

### データセンタ・クラウドを選ぶときの確認項目

自社で設備を持たず、データセンタ（ハウジング・ホスティング）やクラウドサービスを使う場合も、設備の管理がなくなるわけではありません。**設備の管理を事業者に任せ、自社はその事業者が十分な管理をしているかを確認する** 立場に変わります。

| 観点 | 確認すること |
| --- | --- |
| 立地 | ハザードマップで地震・洪水などの想定。本番とバックアップの拠点が同じ災害で被災しない距離か |
| 電源 | 受電の系統数、UPS と自家発電装置の構成、燃料の備蓄で何時間運転できるか、燃料補給の契約 |
| 空調・建物 | 空調の冗長性、免震・耐震の構造、消火設備の方式 |
| 通信 | 回線の引込み経路や通信事業者が複数あるか |
| セキュリティ | 入退室管理（認証・記録・共連れ防止）、監視カメラ、作業の立会い |
| 信頼性の水準 | 設備の冗長性の格付け（ティア）、事業者の SLA |
| 第三者の評価 | 情報セキュリティなどの第三者認証の取得状況、外部監査の報告書を入手できるか |
| 環境 | PUE などのエネルギー効率 |

### よくある失敗と対策

| 失敗 | 対策 |
| --- | --- |
| UPS を設置したまま蓄電池の劣化を確かめず、停電時に数分で止まる | 定期的に停電試験で保持時間を測り、劣化していれば交換する |
| UPS の保持時間内にサーバを安全に停止させる仕組みがない | UPS からの信号で自動的にシャットダウンする設定を入れ、試験で確かめる |
| 自家発電装置はあるが、燃料が少ない・試運転をしていない | 燃料の備蓄量と補給の契約を決め、定期的に負荷をかけて試運転する |
| サーバを増やし続け、電源容量や空調能力の限界に気づかない | 設備台帳で電源の負荷率と室温を監視し、容量・能力管理の対象に含める |
| クラウドだから設備は関係ないと考え、リージョンの立地や事業者の管理を確かめない | 立地と第三者の評価を確かめ、事業継続の計画と合わせてリージョンを選ぶ |

## 事例

架空の企業 **ツバメ情報システム** の設備の見直しです（数値・状況は架空の設定です）。
予約・顧客管理 SaaS **「ヨヤクル」** はパブリッククラウドで稼働していますが、本社には、受託開発の検証サーバ、社内のファイルサーバ、電話の設備を置いたサーバ室が残っています。

**① ヨヤクル（クラウド）の設備の確認**: 電源・空調・入退室などの設備はクラウド事業者が管理しているので、自社では立ち入って点検できません。そこで、事業者が公開している第三者認証の取得状況と外部監査の報告書を入手し、使っている東日本と西日本のリージョンが、同じ地震や水害で同時に被災しにくい場所にあることを確認しました（リージョンの使い方は [サービス継続と事業継続](../continuity/) の事例）。

**② 本社サーバ室の点検**: 設備台帳を作って年次の停電試験を行ったところ、問題が見つかりました。

| 点検項目 | 結果 | 判断 |
| --- | --- | --- |
| UPS の保持時間 | 導入時は 15 分 → 今回 6 分 | 全サーバの自動シャットダウンに 8 分かかるので、**停電時に安全に止められない**。蓄電池の交換が必要 |
| 自家発電装置 | なし | 停電が UPS の保持時間を超えると、サーバ室は停止する |
| 室温 | 夏の午後に吸気温度が管理値の上限を超える日があった | 空調 1 台が故障すると冷却が足りない |
| 入退室 | 鍵を総務で貸し出し、記録は紙 | 誰がいつ入ったかを確かめにくい |

**③ 選択肢の比較**: 蓄電池の交換と空調の増設で本社に残す案と、近くの事業者のデータセンタへ機器を移す（ハウジング）案を比べました。データセンタは、上の確認項目で、受電 2 系統、自家発電装置（燃料備蓄 48 時間、補給契約あり）、IC カードと生体認証による入退室管理、PUE 1.4 であることを確かめました。

本社のサーバ室の消費電力は、IT 機器 12 kW、空調など 9.6 kW でした。PUE と、データセンタに移した場合の消費電力の差は次のとおりです（1 年は $24 \times 365 = 8{,}760$ 時間）。

$$
\def\arraystretch{2.2}
\begin{array}{ll}
\text{本社の PUE} &{}= \dfrac{12 + 9.6}{12} = \dfrac{21.6}{12} = 1.8 \\
\text{移転後の電力} &{}= 12 \times 1.4 = 16.8 \text{ kW} \\
\text{年間の削減量} &{}= (21.6 - 16.8) \times 8{,}760 \\
&{}= 4.8 \times 8{,}760 = 42{,}048 \text{ kWh}
\end{array}
$$

（費用の比較は、データセンタの利用料金で行います。電力の料金をどう請求するかは契約によって異なるので、ここでは環境への効果として電力量の差を示しています。）

**④ 判断**: 停電への備えと入退室管理の水準が大きく上がること、電力量が年に約 4 万 kWh 減ることから、検証サーバとファイルサーバはデータセンタへ移し、電話の設備はクラウドの電話サービスに切り替えることにしました。移すまでの 3 か月間は、UPS の蓄電池だけを先に交換し、停電試験で保持時間がシャットダウンに必要な 8 分を十分に上回ることを確かめてから運用しました。
移転後は、データセンタの事業者から毎月受け取る設備の稼働報告（電源・空調の異常の有無）と入退室の記録を確認することを、自社の点検計画に組み込みました。

## 例題

**例題1** あるデータセンタでは、IT 機器の消費電力が 800 kW、空調・照明などその他の設備の消費電力が 400 kW である。PUE はいくつか。また、空調の効率化でその他の設備の消費電力を 240 kW に減らすと、PUE はいくつになるか。

**解き方**

1. 現在: $\text{PUE} = \dfrac{800 + 400}{800} = \dfrac{1{,}200}{800} =$ **1.5**
2. 改善後: $\text{PUE} = \dfrac{800 + 240}{800} = \dfrac{1{,}040}{800} =$ **1.3**

分母は IT 機器の電力だけ、分子はデータセンタ全体の電力である点に注意します。

**例題2** 停電が発生したとき、自家発電装置が起動して給電を始めるまでの間もサーバを動かし続けたい。設置すべき装置はどれか。また、落雷による過電圧から機器を守るために設置すべき装置はどれか。

**解き方** 停電の直後から短時間の給電を行うのは **UPS** です。落雷による過電圧（サージ）を逃がすのは **サージ防護デバイス（アレスタ）** です。

## 試験対策のポイント

- **ip**: UPS（停電時に短時間給電し、安全に停止させる）、自家発電装置（長時間の停電に備える）、サージ防護（落雷対策）の役割と、グリーン IT の意味を押さえます。
- **fe**: UPS と自家発電装置の組合せ、免震と耐震の違い、コールドアイル・ホットアイルの配置、入退室管理（共連れ、アンチパスバック、インターロック）が問われます。
- **ap**: 電源・回線・空調の冗長化、コンピュータ室の消火設備の選定と安全上の注意、ライフサイクル費用を考えた維持保全、PUE の計算と省エネ対策の評価が問われます。
