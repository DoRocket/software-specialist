**ヒューマンインタフェース** は、人とシステムの接点となる部分です。画面の部品の選び方や操作方法、情報の並べ方ひとつで、システムの使いやすさは大きく変わります。
ここでは GUI の部品、使いやすさを表す **ユーザビリティ** と **UX**、誰もが使えることを目指す **アクセシビリティ** と **ユニバーサルデザイン** の考え方を学びます。

## 仕組み

### GUI の部品

**GUI**（Graphical User Interface）は、アイコンやウィンドウなどの視覚的な表示とマウス・タッチ操作によって、直感的に操作できるインタフェースです。

| 部品 | 特徴・使いどころ |
| --- | --- |
| ラジオボタン | 複数の選択肢から **1 つだけ** 選ぶ（性別、支払方法など） |
| チェックボックス | 複数の選択肢から **いくつでも** 選ぶ / ある項目のオン・オフを切り替える |
| リストボックス | 一覧から選ぶ。選択肢が多いときに使い、スクロールで表示する |
| プルダウンメニュー | クリックすると選択肢が下に開く。画面の場所をとらない（都道府県の選択など） |
| テキストボックス | 自由な文字列を入力する（氏名、住所など） |
| ポップアップメニュー | 右クリックなどで、その場に操作の候補を表示する |
| ツールチップ | マウスポインタを重ねた（ホバー）ときに説明を小さく表示する |
| アコーディオン | 見出しをクリックすると内容が開閉する。FAQ などで情報を折りたたむ |

タッチパネルでは、**タップ**（軽く触れる）、**スワイプ**（なでるように動かす）、**フリック**（素早く払う）、**ピンチ**（2 本の指で拡大・縮小）、**ロングプレス**（長押し）などの操作を組み合わせる **マルチタッチインタフェース** が使われます。
音声で操作する **VUI**（Voice User Interface）や、身振りで操作するジェスチャーインタフェースもあります。

### ユーザビリティと UX

**ユーザビリティ** は「特定の利用者が、特定の利用状況で、目的を達成するために用いる際の、**有効さ・効率・満足度** の度合い」（JIS Z 8521 / ISO 9241-11）と定義される、使いやすさの指標です。
一方、**UX**（User Experience）は、製品やサービスを利用する前後を含めた **体験全体** を指し、使いやすさに加えて楽しさや満足感も含む、より広い概念です。

| 考え方・手法 | 内容 |
| --- | --- |
| 人間中心設計 | 利用者の利用状況を把握し、要求を明確にし、設計案を作って利用者による評価を繰り返す設計プロセス（JIS Z 8530 / ISO 9241-210） |
| UX デザインの五段階モデル | 戦略 → 要件 → 構造 → 骨格 → 表層 の順に、抽象的なものから具体的なものへ設計を進める |
| シグニファイア | 「ここを押せる」「ここを引く」など、適切な操作を利用者に気づかせる手掛かり |

### ユーザビリティ評価

| 手法 | 内容 |
| --- | --- |
| ヒューリスティック評価 | **専門家** が経験則（ヒューリスティクス）に照らして問題点を洗い出す。利用者を集めずに実施できる |
| ユーザビリティテスト | **実際の利用者** にタスクを実行してもらい、その様子を観察して問題点を見つける |
| 思考発話法 | 利用者に、考えていることを声に出しながら操作してもらう |
| 回顧法 | 操作を終えた後に、利用者に操作中の考えを振り返って話してもらう |
| A/B テスト | 2 つの案を利用者に無作為に割り当てて提示し、成果（クリック率など）を比較する |

### アクセシビリティとユニバーサルデザイン

| 用語 | 意味 |
| --- | --- |
| アクセシビリティ | 高齢者や障害のある人を含め、**利用できるかどうか**（情報やサービスへの到達のしやすさ）。日本では JIS X 8341、Web では国際的なガイドライン WCAG がある |
| ユニバーサルデザイン | 年齢・文化・障害の有無・能力の違いにかかわらず、**最初からできる限り多くの人が使えるように** 設計する考え方 |
| バリアフリー | 既存の障壁（バリア）を、特定の人のために **後から取り除く** 考え方 |

ユニバーサルデザインには、「誰でも公平に使える」「使い方が簡単ですぐわかる」「うっかりミスや危険につながりにくい」など **7 原則** があります。
情報システムでは、音声読み上げへの対応、色だけに頼らない表示、操作を取り消せる Undo 機能、意味が一目でわかる **ピクトグラム** の利用などが例です。

### 画面設計と Web デザイン

画面は、入力の流れが自然になるよう項目を並べ、色の使い方や操作方法を統一し、操作ガイダンスを表示するように設計します。
誤った入力を受け付けないために、次のような **入力チェック** を行います。

| チェック | 内容 |
| --- | --- |
| ニューメリックチェック | 数値であるべき項目に数字以外が入っていないか |
| フォーマットチェック | 日付の形式や桁数など、決められた形式どおりか |
| リミットチェック（範囲チェック） | 値が上限・下限の範囲内か（月が 1〜12 など） |
| 組合せチェック | 複数の項目の組合せに矛盾がないか（2 月 30 日がないか など） |
| 照合チェック | マスタファイルなどに登録されたデータと一致するか |
| チェックディジット（チェックキャラクター） | コードに付けた検査用の数字で、入力ミスを検出する |

Web デザインでは、**CSS**（スタイルシート）でサイト全体のデザインを統一し、複数の Web ブラウザで同じように表示されること（クロスブラウザ）に配慮します。
画面の幅に応じてレイアウトを自動的に切り替える **レスポンシブ Web デザイン**（CSS の **メディアクエリ** で実現する）や、スマートフォンでの表示を優先して設計する **モバイルファースト** が一般的です。

## 例題

**例題1** 会員登録画面に次の項目を設ける。最も適切な GUI 部品をそれぞれ答えなさい。

1. 会員種別（一般 / 学生 / シニアのうち 1 つ）
2. 興味のある分野（複数選択可）
3. 居住する都道府県（47 項目から 1 つ）

**解き方**

1. 少数の選択肢から 1 つだけ選ぶので **ラジオボタン**
2. いくつでも選べるので **チェックボックス**
3. 選択肢が多く、画面の場所をとらないほうがよいので **プルダウンメニュー**（またはリストボックス）

**例題2** 生年月日の「月」の入力欄に 13 が入力されたときに誤りを検出できる入力チェックはどれか。

**解き方**: 値が 1〜12 の範囲に収まっているかを確かめればよいので、**リミットチェック（範囲チェック）** です。
「4 月 31 日」のように、月と日の **組合せ** で初めて誤りがわかる場合は組合せチェックになります。

## 試験対策のポイント

- **ITパスポート**: GUI 部品の使い分け（ラジオボタンとチェックボックスの違いは定番）、タッチ操作の名称、ユニバーサルデザイン・アクセシビリティ・ユーザビリティの意味、レスポンシブ Web デザインが中心です。
- **基本情報技術者**: 入力チェックの種類、ユーザビリティ評価の手法（ヒューリスティック評価とユーザビリティテストの違い）、人間中心設計、UX デザインの五段階モデルが問われます。
- **応用情報技術者**: ユニバーサルデザインの 7 原則の適用例、思考発話法・回顧法・認知的ウォークスルーなど評価手法の使い分け、Web アクセシビリティ（WCAG）への配慮など、設計判断の観点で問われます。
- ユニバーサルデザインは「最初から全員のために」、バリアフリーは「後から障壁を取り除く」と対比で覚えます。
