**マルチメディア** とは、文字に加えて音声・静止画・動画などのさまざまな情報をデジタル化し、コンピュータ上で統合して扱うことです。
音や画像は本来アナログの情報なので、ビット列に変換する仕組みと、そのデータ量の求め方を理解することが重要です。データ量が大きいため、用途に応じた **圧縮** も欠かせません。

## 仕組み

### 画像の表現

ディスプレイやデジタル画像は、**画素（ピクセル）** と呼ばれる点の集まりで表現されます。

| 用語 | 意味 |
| --- | --- |
| 画素（ピクセル） | 画像を構成する最小の点。1 画素ごとに色の情報を持つ |
| 解像度 | 画像のきめ細かさ。画面では「横 × 縦の画素数」（例: 1920 × 1080）、プリンタやスキャナでは 1 インチあたりの点の数 **dpi**（画面では **ppi**）で表す |
| 色深度（階調） | 1 画素の色を表すビット数。$n$ ビットなら $2^n$ 色を表現できる |

RGB 各 8 ビット（256 階調）、合計 24 ビットで表す方式を **フルカラー** といい、$2^{24} =$ 約 1,677 万色を表現できます。

画素の集まりで表す画像を **ラスターデータ**（ビットマップデータ）、線や図形を座標と数式で表す画像を **ベクターデータ** といいます。
ベクターデータは拡大しても輪郭がギザギザにならないため、ロゴや図面に向きます。

### 色の表現

| 方式 | 3 原色 | 混色の性質 | 用途 |
| --- | --- | --- | --- |
| RGB | 光の 3 原色（Red・Green・Blue） | **加法混色**: 混ぜるほど明るくなり、3 色を重ねると **白** | ディスプレイ |
| CMY / CMYK | 色の 3 原色（Cyan・Magenta・Yellow） | **減法混色**: 混ぜるほど暗くなり、3 色を重ねると理論上 **黒** | 印刷 |

印刷では CMY を重ねてもきれいな黒になりにくいため、黒（K）のインクを加えた **CMYK** を使います。
色は **色相**（色合い）・**明度**（明るさ）・**彩度**（鮮やかさ）の 3 要素でも表されます。

### 音声のデジタル化（PCM）

アナログの音声信号をデジタルデータに変換する代表的な方式が **PCM**（パルス符号変調）です。次の 3 段階で行います。

| 手順 | 内容 |
| --- | --- |
| 標本化（サンプリング） | 一定の時間間隔で信号の値を取り出す。1 秒間に取り出す回数が **標本化周波数**（Hz） |
| 量子化 | 取り出した値を、決められた段階数の整数値に近似する。段階数を表すビット数が **量子化ビット数** |
| 符号化 | 量子化した値を 2 進数のビット列に変換する |

元の信号に含まれる最高周波数の **2 倍以上** の標本化周波数で標本化すれば、元の信号を復元できます（標本化定理）。
音楽 CD は標本化周波数 44.1kHz、量子化ビット数 16 ビット、ステレオ（2 チャネル）です。

$$
\begin{aligned}
&\text{音声のデータ量（ビット）} \\
&\qquad = \text{標本化周波数} \times \text{量子化ビット数} \times \text{チャネル数} \times \text{秒数} \\[10pt]
&\text{画像のデータ量（ビット）} \\
&\qquad = \text{横の画素数} \times \text{縦の画素数} \times \text{色深度} \\[10pt]
&\text{動画のデータ量（ビット）} \\
&\qquad = \text{1 フレームのデータ量} \times \text{フレームレート} \times \text{秒数}
\end{aligned}
$$

動画は静止画（**フレーム**）を連続して表示したもので、1 秒あたりのフレーム数を **フレームレート**（fps）といいます。

### 圧縮方式

| 種類 | 内容 | 例 |
| --- | --- | --- |
| 可逆圧縮 | 伸長すると **完全に元のデータに戻る** | ZIP、PNG、GIF、ランレングス法、ハフマン法 |
| 非可逆圧縮 | 人間が気づきにくい情報を捨てて圧縮率を高める。**完全には元に戻らない** | JPEG、MP3、MPEG |

- **ランレングス法**: 同じ値の連続を「値 + 個数」で表す。例: `AAAABBBCC` → `A4B3C2`
- **ハフマン法**: 出現頻度の高い記号に短い符号、低い記号に長い符号を割り当てる

プログラムや文書のように 1 ビットでも変わると困るデータには可逆圧縮を、写真・音楽・動画には非可逆圧縮を使うのが基本です。

### 主なファイル形式

| 分類 | 形式 | 特徴 |
| --- | --- | --- |
| 静止画 | JPEG | フルカラー、**非可逆圧縮**。写真向き。圧縮率を調整できる |
| | PNG | フルカラー、**可逆圧縮**。透過に対応。図やスクリーンショット向き |
| | GIF | **256 色** まで、可逆圧縮。簡単なアニメーションや透過に対応 |
| | BMP | 基本的に無圧縮のビットマップ形式 |
| 音声 | WAV | 主に非圧縮の PCM データを格納する |
| | MP3 / AAC | 非可逆圧縮。音楽配信や携帯プレーヤーで使われる |
| | MIDI | 音そのものではなく、**音の高さ・長さ・楽器などの演奏情報** を記録する。データ量が非常に小さい |
| 動画 | MPEG-1 / MPEG-2 / MPEG-4 | 非可逆圧縮。MPEG-1 は Video CD、MPEG-2 は DVD やデジタル放送、MPEG-4 はネット配信やモバイル向け |
| | H.264 / H.265（HEVC） | 高圧縮率の動画符号化方式。H.265 は H.264 より高い圧縮効率を持ち、4K / 8K 放送などで使われる |

動画の圧縮では、1 枚の画像内の圧縮に加え、**前後のフレームとの差分** だけを記録することで大幅にデータ量を減らしています。

### マルチメディアの応用

| 用語 | 意味 |
| --- | --- |
| VR（仮想現実） | ヘッドマウントディスプレイなどで、コンピュータが作り出した仮想空間に入り込んだような体験を提供する |
| AR（拡張現実） | 現実の風景に、コンピュータが作り出した情報（文字や 3D 映像）を重ねて表示する |
| MR（複合現実） | 現実空間と仮想空間を融合し、仮想の物体を現実の物体のように扱えるようにする |
| メタバース | インターネット上に構築された、多数の人が参加できる 3 次元の仮想空間 |

テレビの高解像度化も進み、**4K** は 3840 × 2160 画素、**8K** は 7680 × 4320 画素です。

## 例題

**例題1** 横 1920 画素、縦 1080 画素で、1 画素を 24 ビットで表す画像のデータ量は約何 M バイトか（1M バイト $= 10^6$ バイトとする）。

**解き方**

1. 画素数: $1920 \times 1080 = 2{,}073{,}600$ 画素
2. 1 画素は 24 ビット $=$ 3 バイト → $2{,}073{,}600 \times 3 = 6{,}220{,}800$ バイト $\approx$ **約 6.2M バイト**

**例題2** 標本化周波数 44.1kHz、量子化ビット数 16 ビット、ステレオ（2 チャネル）で 1 分間録音した音声のデータ量は約何 M バイトか。圧縮は行わないものとする。

**解き方**

1. 1 秒あたり: $44{,}100 \times 16 \times 2 = 1{,}411{,}200$ ビット $= 176{,}400$ バイト
2. 1 分間: $176{,}400 \times 60 = 10{,}584{,}000$ バイト $\approx$ **約 10.6M バイト**

**例題3** 例題1 の画像をフレームとし、30 フレーム/秒で 10 秒間の動画を作成する。これを $\dfrac{1}{100}$ に圧縮したときのデータ量は約何 M バイトか。

**解き方**

1. フレーム数: $30 \times 10 = 300$ フレーム
2. 圧縮前: $6{,}220{,}800 \times 300 = 1{,}866{,}240{,}000$ バイト
3. 圧縮後: $1{,}866{,}240{,}000 \div 100 = 18{,}662{,}400$ バイト $\approx$ **約 18.7M バイト**

ビットとバイトの換算（8 ビット = 1 バイト）を忘れないことが最大のポイントです。

## 試験対策のポイント

- **ITパスポート**: JPEG・PNG・GIF・MP3・MPEG などの形式と可逆 / 非可逆の区別、RGB（加法混色）と CMYK（減法混色）、解像度・dpi の意味、VR / AR / MR の違いが頻出です。
- **基本情報技術者**: 画像・音声のデータ量の計算、PCM の標本化・量子化・符号化の手順、ランレングス法やハフマン法の仕組みが問われます。伝送時間の計算と組み合わせた問題にも備えます。
- **応用情報技術者**: 標本化周波数・量子化ビット数の変更がデータ量や品質に与える影響、用途に応じた形式・圧縮方式の選択、動画のフレーム間圧縮の考え方など、比較・応用の観点が加わります。
- MIDI は「音そのものではなく演奏情報」である点がひっかけとしてよく使われます。
