**DNS（Domain Name System）** は、`www.example.com` のような **ドメイン名** と **IPアドレス** を対応付ける仕組みです。
人間には覚えやすい名前を使い、機器同士は IPアドレスで通信できるようにします。名前から IPアドレスを求めることを **名前解決** といいます。

## ドメイン名の階層構造

ドメイン名は右から左へ、大きな範囲から小さな範囲へと階層になっています。

```
www . example . co . jp .
 │      │       │    │   └ ルート
 │      │       │    └ トップレベルドメイン（TLD）
 │      │       └ 第2レベルドメイン
 │      └ 第3レベルドメイン（組織名）
 └ ホスト名
```

各階層の情報は、その階層を管理する **権威DNSサーバ（コンテンツサーバ）** が分散して保持しています。
上位のサーバは「下位のドメインはどのサーバが管理しているか」を知っており、これをたどることで目的の情報にたどり着きます。

## 名前解決の流れ

1. PC（**スタブリゾルバ**）が、設定された **フルサービスリゾルバ（キャッシュDNSサーバ）** に `www.example.co.jp` の IPアドレスを問い合わせる
2. フルサービスリゾルバは、キャッシュに答えがなければ **ルートサーバ** に問い合わせ、`jp` を管理するサーバを教えてもらう
3. 同様に `jp` → `co.jp` → `example.co.jp` の権威DNSサーバへと順にたどる（反復問合せ）
4. `example.co.jp` の権威DNSサーバから IPアドレスを得て PC に返し、結果を **TTL** の間キャッシュする

PC からフルサービスリゾルバへの「最終的な答えをください」という問合せを **再帰問合せ** と呼びます。

## 主なリソースレコード

| レコード | 内容 |
| --- | --- |
| A | ドメイン名に対応する **IPv4** アドレス |
| AAAA | ドメイン名に対応する **IPv6** アドレス |
| CNAME | 別名（エイリアス）。正式なドメイン名を示す |
| MX | そのドメイン宛てのメールを受け取る **メールサーバ** |
| NS | そのドメインを管理する権威DNSサーバ |
| PTR | IPアドレスからドメイン名を求める（**逆引き**）ための情報 |
| SOA | ゾーンの管理情報（管理者、シリアル番号など） |
| TXT | 任意の文字列。SPF（送信ドメイン認証）などで使う |

名前から IPアドレスを求めるのが **正引き**、IPアドレスから名前を求めるのが **逆引き** です。

## 通信プロトコル

DNS の問合せは通常 **UDP の 53 番ポート** を使います。応答が大きい場合やサーバ間のゾーン転送には **TCP の 53 番** を使います。

## DNS に関するセキュリティ

| 脅威・対策 | 内容 |
| --- | --- |
| DNSキャッシュポイズニング | キャッシュDNSサーバに偽の応答を覚えさせ、利用者を偽サイトへ誘導する攻撃 |
| DNSSEC | 応答にデジタル署名を付け、改ざんされていないことを検証できるようにする対策 |
| 送信元ポートのランダム化 | 偽の応答を当てにくくし、キャッシュポイズニングを困難にする |
| オープンリゾルバ対策 | 外部の誰からでも再帰問合せを受け付ける状態は DDoS（DNSリフレクション攻撃）に悪用されるため、問合せ元を制限する |

## 試験対策のポイント

- **ITパスポート**: DNS の役割（ドメイン名 ↔ IPアドレスの対応付け）を説明できること。
- **基本情報**: A / MX / CNAME などのレコードの意味、UDP 53 番を使うこと。
- **応用情報**: キャッシュポイズニングと対策（DNSSEC、ポートランダム化）、メールの送信ドメイン認証（SPF など）とのつながりが問われる。
