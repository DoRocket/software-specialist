アプリケーション層には用途ごとに多くのプロトコルがあります。ここでは試験で頻出のものを用途別に整理します。
ポート番号は [TCP と UDP](../../transport/tcp-udp/) の表もあわせて確認してください。

## Web

| プロトコル | 内容 |
| --- | --- |
| HTTP | Webブラウザと Webサーバの間で、HTML や画像などをやり取りする。要求（リクエスト）と応答（レスポンス）の繰り返し |
| HTTPS | HTTP を **TLS** で暗号化したもの。通信の盗聴・改ざんを防ぎ、サーバ証明書で接続先の真正性を確認する |

HTTP 自体は状態を持たない（ステートレスな）プロトコルのため、ログイン状態などの管理には **Cookie** やセッションIDを使います。

### 主な HTTP メソッドとステータスコード

| メソッド | 用途 |
| --- | --- |
| GET | リソースの取得 |
| POST | データの送信（フォームの送信など） |
| PUT / DELETE | リソースの更新・削除 |

| ステータスコード | 意味 |
| --- | --- |
| 200 番台 | 成功（200 OK） |
| 300 番台 | リダイレクト（301 恒久的な移動 など） |
| 400 番台 | クライアントエラー（404 Not Found、403 Forbidden など） |
| 500 番台 | サーバエラー（500 Internal Server Error、503 Service Unavailable など） |

## 電子メール

| プロトコル | 役割 | 特徴 |
| --- | --- | --- |
| SMTP | **送信・転送** | メールソフト → メールサーバ、メールサーバ → メールサーバへの送信に使う |
| POP3 | **受信** | メールをサーバから **端末にダウンロード** して読む。基本的に受信後はサーバから削除する |
| IMAP4 | **受信** | メールを **サーバ上で管理** したまま読む。複数の端末で同じ状態（既読・フォルダ）を共有できる |
| MIME | 拡張 | 日本語や画像・添付ファイルなどを電子メールで扱えるようにする規格 |
| S/MIME | 暗号化・署名 | 公開鍵暗号を使ってメール本文の暗号化とデジタル署名を行う |

> 送信は SMTP、受信は POP3 か IMAP。スマートフォンと PC の両方で同じメールを読むなら IMAP が向いています。

## ファイル転送・遠隔操作・その他

| プロトコル | 内容 |
| --- | --- |
| FTP | ファイル転送。制御用（21番）とデータ転送用（20番）で別のコネクションを使う。通信は暗号化されない |
| SSH | 遠隔地のコンピュータに **暗号化** された通信路でログインし操作する。SFTP や SCP でファイル転送にも使う |
| Telnet | 遠隔ログイン。通信が **暗号化されない** ため、現在は SSH が推奨される |
| NTP | ネットワーク上の機器の **時刻を同期** する。ログの時刻をそろえるために重要 |
| SNMP | ネットワーク機器の状態を **監視・管理** する。管理対象（エージェント）が異常を通知する機能（トラップ）もある |

## 試験対策のポイント

- **ITパスポート**: 「メール送信は SMTP、受信は POP3/IMAP」「POP と IMAP の違い」「HTTPS は通信を暗号化する」が頻出。
- **基本情報**: 各プロトコルの役割に加え、TCP/UDP の別と代表的なポート番号もセットで覚える。
- **応用情報**: TLS の仕組み（証明書による認証と鍵交換）、メールの送信ドメイン認証、ファイアウォールで許可すべき通信の設計などに発展する。
