**Ethernet（イーサネット）** は、有線LANで最も広く使われているデータリンク層・物理層の規格です（IEEE 802.3）。
機器の識別には **MACアドレス** を使います。

## MACアドレス

ネットワークインタフェース（NIC）ごとに割り当てられる **48ビット** の識別子です。

```
00-1A-2B-3C-4D-5E   （8ビットずつ16進数2桁 × 6組で表記。区切りは - や : ）
└──┬───┘ └──┬───┘
  OUI     製造者が割り当てる番号
（上位24ビット: 製造者番号）
```

| 項目 | 内容 |
| --- | --- |
| 長さ | 48ビット（6バイト） |
| 上位24ビット | **OUI**（ベンダ識別子）。IEEE が製造者ごとに割り当てる |
| 下位24ビット | 製造者が製品ごとに一意になるよう割り当てる |
| ブロードキャストアドレス | `FF-FF-FF-FF-FF-FF`（同一ネットワーク内の全機器宛て） |

IPアドレスが「ネットワーク上の論理的な住所」で設定により変わるのに対し、MACアドレスは機器に割り当てられた「物理アドレス」と呼ばれます
（ただし、ソフトウェアで変更したり、スマートフォンなどがプライバシー保護のためランダムなアドレスを使ったりすることもあります）。

## Ethernet フレームの構造（Ethernet II）

| フィールド | サイズ | 内容 |
| --- | --- | --- |
| プリアンブル（SFD含む） | 8バイト | 受信側の同期用の信号パターン |
| 宛先MACアドレス | 6バイト | |
| 送信元MACアドレス | 6バイト | |
| タイプ | 2バイト | 上位プロトコルの種類（IPv4 = 0x0800、ARP = 0x0806、IPv6 = 0x86DD） |
| データ | 46〜1,500バイト | IPパケットなど。最大 1,500 バイトを **MTU** という |
| FCS | 4バイト | CRC による誤り検出用の値 |

受信側は FCS を検査し、誤りがあるフレームは **破棄** します（データリンク層では再送しません。再送は TCP などの上位層の役割です）。

## アクセス制御方式 CSMA/CD

複数の機器が1本の伝送路を共有する（半二重の）Ethernet で使われた方式です。

1. **CS（Carrier Sense）**: 送信前に伝送路が空いているか確認する
2. **MA（Multiple Access）**: 空いていれば送信する（複数の機器が同じ伝送路を使う）
3. **CD（Collision Detection）**: 送信中に衝突（コリジョン）を検知したら送信を中止し、**ランダムな時間** 待って再送する

現在主流のスイッチを使った **全二重通信** では送信と受信が別の線で行われ衝突が起きないため、CSMA/CD は実質的に使われていません。
無線LANでは衝突を検知できないため、衝突を「回避」する CSMA/CA が使われます（[無線LAN](../wireless-lan/) 参照）。

## 主な規格

| 規格 | 通信速度 | 主な伝送媒体 |
| --- | --- | --- |
| 10BASE-T | 10Mビット/秒 | ツイストペアケーブル |
| 100BASE-TX | 100Mビット/秒 | ツイストペアケーブル（カテゴリ5以上） |
| 1000BASE-T | 1Gビット/秒 | ツイストペアケーブル（カテゴリ5e以上） |
| 10GBASE-T | 10Gビット/秒 | ツイストペアケーブル（カテゴリ6A以上） |

名称は「速度 + BASE（ベースバンド方式） + 媒体の種類」を表しています。T はツイストペアケーブル、
1000BASE-SX / LX などは光ファイバを使う規格です。

## 実務での見え方

### 自分の PC の MACアドレスとリンク状態を見る

MACアドレスは、OS のネットワーク設定画面のほか、次のコマンドで確認できます（`#` の後は説明。インタフェース名 `en0`・`eth0` は例です）。

```
ipconfig /all       # Windows: 「物理アドレス」の欄
ifconfig en0        # macOS: ether の行
ip link             # Linux: link/ether の行
```

Linux の `ip link` では、例えば次のように表示されます（形式を示すための例です）。

```
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc ... state UP ...
    link/ether 00:1a:2b:3c:4d:5e brd ff:ff:ff:ff:ff:ff
```

`mtu 1500` が上で説明した MTU、`link/ether` が自分の MACアドレス、`brd` がブロードキャストアドレスです。
`UP` や `LOWER_UP` は、インタフェースが有効でケーブルの先とつながっている（リンクしている）ことを表します。

OS の設定画面には **リンク速度**（例: 1.0Gbps）も表示されます。PC とスイッチは接続時に、互いに対応する最も速い速度と全二重・半二重を自動で決めます（オートネゴシエーション）。
1000BASE-T 対応の機器どうしなのに 100Mbps でつながっている場合は、ケーブルを疑います。1000BASE-T は 4対の線をすべて使うため、
カテゴリの低いケーブルや一部の線の断線・劣化があると、2対で動く 100BASE-TX の速度に落ちてつながることがあります。

### ケーブルを選ぶ・引く

- ケーブルの外被には **カテゴリ**（CAT5e・CAT6・CAT6A など）が印字されています。1Gビット/秒なら CAT5e 以上、10Gビット/秒を見込むなら CAT6A 以上が目安です。
- ツイストペアケーブルで Ethernet を使えるのは、機器から機器まで **最大 100m** です。これより遠いフロア間や建物間は、光ファイバの規格を使います。
- 床下や天井裏に引いたケーブルは交換しにくいので、新しく引くときは将来の速度も考えて少し上のカテゴリを選ぶことが多いです。

### MACアドレスを使った管理と、その注意点

- 機器台帳に主な機器の MACアドレスを記録しておくと、マネージドスイッチの MACアドレステーブルから「その機器がどのポートにつながっているか」をたどれます。
- DHCP で特定の機器にいつも同じ IPアドレスを配る設定（予約）や、許可した機器だけを無線LAN に接続させる設定でも MACアドレスを使います。
- ただし最近の OS やスマートフォンは、Wi-Fi に接続するときにネットワークごとに異なるランダムな MACアドレスを使う機能を持っています。この機能が有効だと、MACアドレスで端末を識別する設定が期待どおりに働かないことがあります。

## 事例

[みなと事務所](../../)（社員30名・2フロア）の有線LAN での例です。

- **配線**: 4階の制作チームの席は大きなファイルを扱うので、Wi-Fi ではなく有線にしました。各席から4階の L2スイッチまでは 30m 程度で、100m 以内に収まります。将来 10Gビット/秒にする可能性を考え、ケーブルは CAT6A を選びました。
- **トラブル**: 制作チームの1台だけ「NAS への保存がほかの席より遅い」と相談がありました。設定画面のリンク速度が 100Mbps になっていたため、机の下で踏まれて傷んでいた LANケーブルを交換すると 1.0Gbps でつながり、保存時間も他の席と同じになりました。2Gバイトのファイルなら、伝送効率 70% として 100Mbps では約229秒、1Gbps では約23秒と、10倍の差になります（計算は [伝送時間と通信速度の計算](../../performance/) の方法）。
- **台帳**: NAS・複合機・AP の MACアドレスを台帳に記録しています。4階の複合機が見つからなくなったときは、4階スイッチの MACアドレステーブルで複合機の MACアドレスを探し、つながっているポートのランプとケーブルを確かめました。

## 試験対策のポイント

- **ITパスポート**: 「MACアドレスは機器（NIC）固有の番号」「IPアドレスとの違い」を説明できること。
- **基本情報**: MACアドレスが 48 ビットであること、CSMA/CD の動作（衝突検知→ランダム時間後に再送）、
  L2スイッチが MACアドレスで転送先を決めることを押さえる。
- **応用情報**: MTU とフラグメント、VLAN タグ（IEEE 802.1Q）なども含め、フレームのサイズや中継の仕組みが問われる。
