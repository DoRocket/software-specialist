**無線LAN** は電波を使って LAN を構成する技術で、IEEE 802.11 シリーズとして標準化されています。
相互接続性が認証された製品には「Wi-Fi」の名称が使われます。

## 構成要素

| 用語 | 説明 |
| --- | --- |
| アクセスポイント（AP） | 無線端末を収容し、有線LANと中継する機器 |
| インフラストラクチャモード | アクセスポイントを介して通信する一般的な形態 |
| アドホックモード | アクセスポイントを介さず端末同士が直接通信する形態 |
| SSID（ESSID） | 無線ネットワークを識別する名前。端末は接続先の SSID を指定する |
| ステルス機能（SSID 隠蔽） | アクセスポイントが SSID を通知（ビーコン）しないようにする機能。通信を傍受されれば SSID は分かるため、それだけでは十分な対策にならない |
| MACアドレスフィルタリング | 登録した MACアドレスの端末だけ接続を許可する。MACアドレスは偽装可能なため補助的な対策 |

## 主な規格

| 規格 | 周波数帯 | 最大通信速度（規格値） | 名称 |
| --- | --- | --- | --- |
| IEEE 802.11b | 2.4GHz | 11Mビット/秒 | |
| IEEE 802.11a | 5GHz | 54Mビット/秒 | |
| IEEE 802.11g | 2.4GHz | 54Mビット/秒 | |
| IEEE 802.11n | 2.4GHz / 5GHz | 600Mビット/秒 | Wi-Fi 4 |
| IEEE 802.11ac | 5GHz | 約6.9Gビット/秒 | Wi-Fi 5 |
| IEEE 802.11ax | 2.4GHz / 5GHz（Wi-Fi 6E は 6GHz も） | 約9.6Gビット/秒 | Wi-Fi 6 / 6E |

- **2.4GHz帯** は障害物に強く遠くまで届くが、電子レンジや Bluetooth などと干渉しやすい。
- **5GHz帯** は干渉が少なく高速だが、障害物に弱い。

## アクセス制御方式 CSMA/CA

無線では自分の送信中に他の電波を検知することが難しく、衝突を「検知」できません。そこで衝突を **回避（Collision Avoidance）** します。

1. 送信前に電波が使われていないか確認する（キャリアセンス）
2. 空いていても、すぐには送らず **ランダムな待ち時間** をおいてから送信する
3. 受信側は正しく受け取れたら **ACK（確認応答）** を返す。ACK が返らなければ再送する

さらに、互いの電波が届かない端末同士の衝突（隠れ端末問題）を防ぐため、
送信前に RTS/CTS という制御フレームで送信権を確保する方式もあります。

## セキュリティ

| 方式 | 暗号化 | 評価 |
| --- | --- | --- |
| WEP | RC4 | 脆弱性があり **使用すべきでない** |
| WPA | TKIP（RC4 ベース） | WEP の改良版だが現在は非推奨 |
| WPA2 | **AES**（CCMP） | 広く普及。長く標準的に使われてきた |
| WPA3 | AES（パスワード認証に **SAE** を採用） | 最新の方式。辞書攻撃への耐性が向上 |

認証方式には、共通のパスフレーズを使う **パーソナルモード（PSK／SAE）** と、
**IEEE 802.1X** と RADIUS サーバで利用者ごとに認証する **エンタープライズモード** があります。

## 実務での見え方

### 接続の状態を確かめる

接続している SSID・規格・チャネル・信号の強さ・リンク速度は、次の方法で確認できます（`#` の後は説明。インタフェース名 `wlan0` は例です）。

```
netsh wlan show interfaces     # Windows: SSID、無線の種類、認証、チャネル、受信/送信速度、シグナル
                               # macOS: option キーを押しながらメニューバーの Wi-Fi アイコンをクリック
iw dev wlan0 link              # Linux（iw がある場合）: 接続先、信号の強さ（dBm）、ビットレート
nmcli dev wifi                 # Linux（NetworkManager の場合）: 周りのアクセスポイントとチャネル・信号
```

Windows の `netsh wlan show interfaces` では、例えば次のような項目が並びます（項目名や値は OS の版や機器で異なります。形式を示すための例です）。

```
    SSID                   : minato-staff
    無線の種類             : 802.11ax
    認証                   : WPA3-パーソナル
    チャネル               : 36
    受信速度 (Mbps)        : 576
    送信速度 (Mbps)        : 576
    シグナル               : 82%
```

ここに出る速度は、その時点の電波の状態で決まる **無線区間のリンク速度** です。
上の表の最大通信速度は規格上の理論値で、実際にデータを送れる速度（実効速度）は、リンク速度よりもかなり低くなるのが普通です。
電波は AP につながる端末で分け合い、CSMA/CA の待ち時間や ACK もあるためです。

### 設置を考えるときの観点

- **範囲と台数**: AP の台数は「電波が届く範囲」と「同時につなぐ端末の数」の両方から決める。会議室のように人が集まる場所は、届いていても混み合いやすい。
- **チャネル**: 隣り合う AP には重ならないチャネルを割り当てる。2.4GHz帯は互いに重ならないチャネルが少ない（例: 1・6・11 の3つ）ので干渉しやすく、5GHz帯の方が選べるチャネルが多い。周りの事務所の Wi-Fi も同じ電波を使っている点に注意する。
- **電源**: 天井に付ける AP は、LANケーブルで電力も送る **PoE**（Power over Ethernet）に対応したスイッチから給電することが多い。
- **ネットワークの分け方**: 社員用と来客用は SSID を分け、それぞれ別の VLAN（ネットワーク）に収容する。来客用は社内への通信を止め、端末どうしの通信も遮断する機能（名称は製品によって異なる）を使う。
- **認証**: パーソナルモードは手軽だが、退職者が出るたびにパスフレーズを変えて全員の端末を設定し直す必要がある。人数が増えたらエンタープライズモード（IEEE 802.1X）を検討する。

### 「遅い・切れる」ときの確かめ方

1. 同じ場所で有線LAN では問題ないかを確かめ、無線区間の問題かどうかを切り分ける
2. 信号の強さ（シグナル）を見る。AP から遠い・壁が多い場所では弱くなる
3. 2.4GHz帯につながっていないか、周りに同じチャネルの AP が多くないかを見る
4. その AP に何台つながっているかを AP の管理画面で見る

## 事例

[みなと事務所](../../)（社員30名・2フロア・来客用 Wi-Fi あり）の無線LAN の設計です。

| 項目 | 社員用「minato-staff」 | 来客用「minato-guest」 |
| --- | --- | --- |
| 収容する VLAN | VLAN 10（192.168.10.0/24） | VLAN 30（192.168.30.0/24） |
| セキュリティ | WPA3-パーソナル（古い端末のため WPA2 も併用できる設定） | WPA2/WPA3-パーソナル。パスフレーズは毎月変更し、受付に掲示 |
| 通信の範囲 | 社内の NAS・複合機とインターネット | インターネットのみ。端末どうしの通信も遮断 |

- AP は各階の天井に2台ずつ、計4台。PoE 対応の L2スイッチから給電しています。
- 5GHz帯は4台とも別のチャネルにし、2.4GHz帯は 1・6・11 チャネルを割り振りました。
- 4階の会議室で「Web会議の映像が止まる」と相談がありました。会議室の PC は AP から壁2枚離れていて 2.4GHz帯でつながり、シグナルが 30% 程度でした。会議室の近くへ AP を1台移したところ、5GHz帯でつながるようになり改善しました。
- 社員の入れ替わりが増えてきたため、パスフレーズの変更の手間をなくす目的で、IEEE 802.1X（エンタープライズモード）への移行を検討しています。

## 試験対策のポイント

- **ITパスポート**: SSID、ESSID ステルス、MACアドレスフィルタリング、WPA2/WPA3 といったセキュリティ対策の用語と効果。
  「SSID を隠すだけでは不十分」という観点が問われやすい。
- **基本情報**: CSMA/CA と CSMA/CD の違い（衝突を回避するか検知するか）。
- **応用情報**: IEEE 802.1X による認証、企業 LAN での無線アクセスポイントの設計・セキュリティ対策。
