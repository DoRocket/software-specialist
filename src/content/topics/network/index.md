コンピュータネットワークは、複数の機器が **共通の約束事（プロトコル）** に従ってデータを送受信する仕組みです。
現在のインターネットや社内LANのほとんどは **TCP/IP** というプロトコル群で動いています。

## この分野の全体像

ネットワークは「役割ごとに層（レイヤ）に分けて考える」のが基本です。
各層は下の層のサービスを使い、上の層にサービスを提供します。

| 層（TCP/IPモデル） | 主な役割 | 代表的な技術 | このサイトでの位置 |
| --- | --- | --- | --- |
| アプリケーション層 | アプリケーション固有のやり取り | HTTP, DNS, DHCP, SMTP | アプリケーション層 |
| トランスポート層 | アプリケーション間の通信、信頼性 | TCP, UDP, ポート番号 | トランスポート層 |
| インターネット層 | ネットワークをまたいだ宛先までの配送 | IP, ICMP, ARP, ルーティング | インターネット層 |
| ネットワークインタフェース層 | 同じネットワーク内の隣接機器への伝送 | Ethernet, 無線LAN, MACアドレス | データリンク層 |

## おすすめの学習順序

1. **OSI参照モデルとTCP/IP** … 層の考え方と、各技術がどの層に属するかの地図を持つ
2. **データリンク層** … Ethernet と MACアドレスで「隣の機器に届ける」仕組みを知る
3. **インターネット層** … IPアドレス（クラス・サブネット・プライベートアドレス・IPv6）とルーティング
4. **トランスポート層** … TCP と UDP の違い、ポート番号
5. **アプリケーション層** … DNS・DHCP・メールやWebのプロトコル
6. **ネットワーク機器** と **伝送時間の計算** … 層の知識を機器や計算問題に結び付ける

ITパスポートでは用語と役割、基本情報では仕組みと計算（サブネット・伝送時間）、
応用情報ではそれらを組み合わせた設計・トラブルシュートの観点まで問われます。

## 各記事の事例で使う架空のオフィス

この分野の各記事の「事例」では、次の **架空の事務所「みなと事務所」** を共通の舞台にして、
その記事の技術が現場でどう使われるかを示します。アドレスは文書用に予約された範囲（203.0.113.0/24、198.51.100.0/24、2001:db8::/32）と
プライベートアドレス、ドメイン名は例示用の `.example` を使っており、実在のネットワークとは関係ありません。

| 項目 | 内容 |
| --- | --- |
| 規模 | 社員30名。事務所ビルの3階（営業・総務 18名）と4階（制作チーム 12名）の2フロア |
| インターネット回線 | 光回線 1本（ベストエフォート 1Gビット/秒）。ISP から固定のグローバルIPv4アドレスを1個（203.0.113.10）と、IPv6 のプレフィックス 2001:db8:1200:1000::/56 を割り当てられている |
| ルータ | 3階のラックに1台。インターネットとの出入口で、NAPT・パケットフィルタ・DHCPサーバ・DNSキャッシュを兼ね、VLAN 間の中継も行う |
| スイッチ | 各階に VLAN 対応の L2スイッチ（24ポート）を1台ずつ。3階と4階のスイッチは LANケーブル1本で接続 |
| 無線LAN | 各階にアクセスポイント（AP）2台。社員用 SSID「minato-staff」と来客用 SSID「minato-guest」を出している |
| ネットワークの区分 | 社員用 192.168.10.0/24（VLAN 10）、サーバ・プリンタなどの機器用 192.168.20.0/24（VLAN 20）、来客用 192.168.30.0/24（VLAN 30）。各ネットワークの `.1` がルータ |
| 主な機器 | ファイルサーバ（NAS）192.168.20.10、複合機 3階 192.168.20.21・4階 192.168.20.22 |
| 外部のサービス | 自社サイト www.minato.example（レンタルサーバ 198.51.100.20）、メールはクラウドのメールサービスを利用 |

来客用 Wi-Fi はインターネットにだけ出られ、社員用・機器用のネットワークには入れないようにルータで制限しています。
ここに出てくる用語（VLAN、NAPT、DHCP など）は、それぞれの記事で説明します。
