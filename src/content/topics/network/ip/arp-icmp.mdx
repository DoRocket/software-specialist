IP がパケットを届けるには、いくつかの補助的なプロトコルが必要です。代表が **ARP** と **ICMP** です。

## ARP（Address Resolution Protocol）

IP でパケットを送るとき、実際に同じネットワーク上の相手（または次のルータ）にフレームを届けるには、相手の **MACアドレス** が必要です。
ARP は **IPアドレスから MACアドレスを求める** プロトコルです。

### 動作の流れ

1. PC-A が「IPアドレス 192.168.1.20 の機器の MACアドレスを教えて」という **ARP要求** を **ブロードキャスト** で送る
2. 同じネットワーク内の全機器が受け取るが、該当する IPアドレスを持つ PC-B だけが自分の MACアドレスを入れた **ARP応答** を **ユニキャスト** で返す
3. PC-A は結果を **ARPテーブル（ARPキャッシュ）** に一定時間保存し、以後の通信に使う

宛先が別のネットワークにある場合は、宛先そのものではなく **デフォルトゲートウェイ（ルータ）の MACアドレス** を ARP で求めて、ルータにフレームを渡します。

> IPv6 では ARP の代わりに ICMPv6 の **近隣探索（NDP）** が同じ役割を果たします。

### 関連する攻撃

ARP 応答には認証がないため、偽の ARP 応答で通信を自分に向けさせる **ARPスプーフィング（ARPポイズニング）** という攻撃があります。

## ICMP（Internet Control Message Protocol）

IP 通信における **エラーの通知や制御・診断のためのメッセージ** を運ぶプロトコルです。IP は自身でエラーを報告しないため、ICMP がその役割を補います。

| 主なメッセージ | 内容 |
| --- | --- |
| エコー要求 / エコー応答 | 相手に到達できるかを確認する（ping が使う） |
| 宛先到達不能（Destination Unreachable） | 宛先ネットワークやポートに到達できないことを通知 |
| 時間超過（Time Exceeded） | TTL が 0 になりパケットが破棄されたことを通知 |
| リダイレクト | より適切なルータがあることを送信元に通知 |

### ping と traceroute

- **ping**: ICMP エコー要求を送り、エコー応答が返るかで **疎通確認** を行う。往復時間も分かる。
- **traceroute（Windows では tracert）**: TTL を 1, 2, 3… と増やしながらパケットを送り、
  各ルータから返る **時間超過** メッセージを使って **宛先までの経路（経由するルータ）** を調べる。

**TTL（Time To Live）** は IP ヘッダのフィールドで、ルータを1つ通過するたびに 1 減り、0 になるとパケットは破棄されます。
経路がループしてもパケットが永久に回り続けないための仕組みです。

## 試験対策のポイント

- **基本情報**: ARP の目的（IP → MAC）と、要求がブロードキャスト・応答がユニキャストであること。ping が ICMP を使うこと。
- **応用情報**: traceroute の原理（TTL と時間超過）、ARP スプーフィングなど、トラブルシュートやセキュリティの文脈で問われる。
