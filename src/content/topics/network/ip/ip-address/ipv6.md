**IPv6** は、IPv4 アドレスの枯渇に対応するために作られた次世代のインターネットプロトコルです。
アドレス長は **128ビット** で、約 $3.4 \times 10^{38}$ 個という事実上使い切れない数のアドレスを持ちます。

## 表記方法

128ビットを **16ビットずつ 8 つ** に区切り、それぞれを **16進数4桁** で表してコロン（:）でつなぎます。

```
2001:0db8:0000:0000:0000:ff00:0042:8329
```

### 省略ルール

1. 各ブロックの **先頭の 0 は省略** できる
   `0db8` → `db8`、`0042` → `42`、`0000` → `0`
2. **0 のブロックが連続する部分は `::` に置き換えられる**。ただし **1つのアドレスで1回だけ**

```
2001:0db8:0000:0000:0000:ff00:0042:8329
→ 2001:db8:0:0:0:ff00:42:8329     (ルール1)
→ 2001:db8::ff00:42:8329          (ルール2)
```

`::` を2回使うと、それぞれ何ブロック分の 0 なのか復元できなくなるため禁止されています。

## 主なアドレスの種類

| 種類 | プレフィックス | 説明 |
| --- | --- | --- |
| グローバルユニキャストアドレス | 2000::/3 | インターネット上で一意（IPv4のグローバルアドレスに相当） |
| リンクローカルアドレス | fe80::/10 | 同一リンク内でのみ有効。インタフェースごとに自動設定される |
| ユニークローカルアドレス | fc00::/7 | 組織内で使う（IPv4のプライベートアドレスに相当） |
| ループバックアドレス | ::1 | 自分自身 |
| マルチキャストアドレス | ff00::/8 | 複数の宛先グループ向け |

IPv6 には **ブロードキャストアドレスがありません**。同様の用途にはマルチキャストを使います。

## IPv4 との主な違い

| 項目 | IPv4 | IPv6 |
| --- | --- | --- |
| アドレス長 | 32ビット | 128ビット |
| 表記 | 10進数をピリオド区切り | 16進数をコロン区切り |
| ヘッダ | 可変長（オプションあり） | **40バイト固定長**。拡張ヘッダで機能を追加し、ルータの処理を簡素化 |
| アドレス自動設定 | 主に DHCP | **SLAAC（ステートレスアドレス自動設定）** も可能 |
| MACアドレスの解決 | ARP | ICMPv6 の **近隣探索（NDP）** |
| セキュリティ | IPsec はオプション | IPsec への対応を前提に設計（実装の必須性は規格改定で緩和） |
| 経路途中での分割（フラグメント） | ルータが行える | 送信元だけが行う |

## IPv4 からの移行技術

IPv4 と IPv6 には互換性がないため、共存させる技術が使われます。

- **デュアルスタック**: 1台の機器が IPv4 と IPv6 の両方を扱う
- **トンネリング**: IPv6 パケットを IPv4 パケットに包んで（カプセル化して）IPv4 網を通す（逆も同様）
- **トランスレーション**: IPv4 と IPv6 のヘッダを相互変換する

## 実務での見え方

### 自分の PC の IPv6 アドレスを見る

IPv6 が使えるネットワークにつながっていれば、`ipconfig`（Windows）・`ifconfig`（macOS）・`ip -6 addr`（Linux）で IPv6 アドレスが表示されます。
Linux の `ip -6 addr` では、例えば次のように表示されます（形式を示すための例です）。

```
inet6 2001:db8:1200:1010:3c1a:9f2e:41b7:8c05/64 scope global temporary dynamic
inet6 2001:db8:1200:1010:21a:2bff:fe3c:4d5e/64 scope global dynamic
inet6 fe80::21a:2bff:fe3c:4d5e/64 scope link
```

ここから次のことが読み取れます。

- **1つのインタフェースに複数のアドレス** が付くのが普通です。`fe80::` で始まるリンクローカルアドレスは常にあり、そのうえにグローバルユニキャストアドレス（`2001:db8:...`）が付きます。
- `temporary` は、外部との通信で使う **一時アドレス** です。インタフェースID（後半64ビット）を一定時間ごとに変えて、同じ端末だと追跡されにくくします。
- LAN のプレフィックス長は **/64** が基本です。前半64ビットがネットワーク（ルータが通知するプレフィックス）、後半64ビットがインタフェースIDで、SLAAC はこの /64 を前提にしています。インタフェースID は、MACアドレスから作る方式や乱数で作る方式があり、OS によって異なります。
- Windows や macOS では、リンクローカルアドレスの後ろに `%12` や `%en0` のような印が付くことがあります。リンクローカルアドレスはどのリンクでも同じ形になりうるので、どのインタフェースのものかを示しています。

### コマンドとアドレスの書き方

```
ping -6 2001:db8:1200:1010::1      # Windows・Linux（macOS は ping6 を使う）
tracert -6 www.minato.example      # Windows（macOS・Linux は traceroute6 など）
nslookup -type=AAAA www.minato.example   # IPv6 アドレス（AAAA レコード）を調べる
```

- URL に IPv6 アドレスを直接書くときは、ポート番号の `:` と区別するため `http://[2001:db8::1]:8080/` のように角かっこで囲みます。
- 名前に IPv4 と IPv6 の両方のアドレスがあるとき、多くの OS は IPv6 を先に試し、うまくいかなければ IPv4 に切り替えます。「一部のサイトだけ遅い」ときは、`ping -4` と `ping -6` で IPv4 と IPv6 を分けて確かめると切り分けやすくなります。

### 設計・運用での注意

- ISP からは /48 や /56 などのプレフィックスを受け取り、その中から LAN ごとに /64 を切り出して使います。/56 なら $2^{64-56} = 256$ 個の LAN に割り当てられます。
- IPv6 では NAT を使わず、端末にグローバルアドレスが直接付くのが一般的です。外から始まる通信を止めるのは NAT ではなく **ルータのファイアウォール（パケットフィルタ）** の役目になります。
- IPv4 のフィルタだけを設定して IPv6 のフィルタを忘れると、IPv4 では止めたはずの通信が IPv6 で通ってしまいます。**IPv4 と IPv6 の両方に同じ方針のルール** を書く必要があります。

## 事例

[みなと事務所](../../../)（社員30名・来客用 Wi-Fi あり）は、ISP から `2001:db8:1200:1000::/56` を割り当てられています。
/56 の中で4ブロック目の下位8ビット（`1000`〜`10ff` の下2桁）を自由に使えるので、IPv4 の第3オクテットと同じく **VLAN 番号に見た目をそろえて** /64 を割り当てました（`10` などは16進数ですが、読みやすさのために10進数の VLAN 番号と同じ並びにしています）。

| ネットワーク | IPv4 | IPv6 | アドレスの付け方 |
| --- | --- | --- | --- |
| 社員用（VLAN 10） | 192.168.10.0/24 | 2001:db8:1200:1010::/64 | SLAAC（ルータが通知するプレフィックスから端末が自動で作る） |
| 機器用（VLAN 20） | 192.168.20.0/24 | 使わない（IPv4 のみ） | — |
| 来客用（VLAN 30） | 192.168.30.0/24 | 2001:db8:1200:1030::/64 | SLAAC |

導入したとき、ルータのフィルタは IPv4 の「来客用から社員用・機器用への通信は拒否」だけが設定されていて、IPv6 のルールがありませんでした。
確認のため来客用 Wi-Fi につないだ試験用の端末から、社員用の PC の IPv6 アドレスに `ping -6` を打つと応答が返ってきたため、
IPv6 にも「来客用から社員用への通信は拒否」「インターネットから始まる通信は拒否」のルールを追加し、応答が返らないことを確かめました。
機器用のネットワークは IPv6 を使わないことで、守る対象を減らしています。

## 試験対策のポイント

- **ITパスポート**: 「IPv6 は 128 ビット」「IPv4 アドレス枯渇への対策」であることを押さえる。
- **基本情報**: 表記と省略ルール（`::` は1回だけ）、IPv4 との違い。
- **応用情報**: リンクローカルアドレス、近隣探索、移行技術など、IPv4 との共存環境での動作が問われる。
