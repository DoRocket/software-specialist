IPv4アドレスは約43億個しかなく、世界中の機器すべてに一意のアドレスを割り当てることはできません。
そこで、**組織内（LAN）では自由に使えるプライベートアドレス** を使い、インターネットに出るときだけ **グローバルアドレス** に変換する仕組みが広く使われています。

## グローバルアドレスとプライベートアドレス

| 種類 | 特徴 |
| --- | --- |
| グローバルIPアドレス | インターネット上で一意。管理団体（日本では JPNIC など）から ISP 等を通じて割り当てられる |
| プライベートIPアドレス | 組織内で自由に使える。インターネット上では使えない（ルーティングされない） |

## プライベートアドレスの範囲（RFC 1918）

| 範囲 | CIDR表記 | 旧クラスとの対応 |
| --- | --- | --- |
| 10.0.0.0 〜 10.255.255.255 | 10.0.0.0/8 | クラスA 1個 |
| 172.16.0.0 〜 172.31.255.255 | 172.16.0.0/12 | クラスB 16個 |
| 192.168.0.0 〜 192.168.255.255 | 192.168.0.0/16 | クラスC 256個 |

家庭用ルータの「192.168.1.1」などはこの範囲のアドレスです。

## NAT と NAPT

### NAT（Network Address Translation）

プライベートアドレスとグローバルアドレスを **1対1** で変換します。
同時にインターネットへ出られる端末数は、持っているグローバルアドレスの数までに限られます。

### NAPT（Network Address Port Translation）

IPアドレスに加えて **ポート番号も変換** することで、**1つのグローバルアドレスを複数の端末で共有** します。
IPマスカレードとも呼ばれ、家庭用ルータで一般に使われているのはこちらです。

```
[PC-A 192.168.1.10:50001] ─┐                     ┌─> 203.0.113.5:60001 ─┐
                            ├─ NAPTルータ（変換表）─┤                      ├─> Webサーバ
[PC-B 192.168.1.11:50001] ─┘                     └─> 203.0.113.5:60002 ─┘
```

ルータは変換表（どの内部アドレス:ポートを、どの外部ポートに対応させたか）を保持し、
戻ってきたパケットの宛先ポート番号から元の端末を判別して転送します。

## NAT のメリットと注意点

- **メリット**: グローバルアドレスの節約。内部のアドレス構成を外部から隠せる。
- **注意点**: 外部から内部の機器へ直接通信を開始することは基本的にできない（公開サーバにはポートフォワーディング等の設定が必要）。
  IPアドレスやポート番号をデータ中に含むプロトコルでは、変換によって通信に問題が起きることがある。

## 実務での見え方

### 「自分のアドレス」は2つある

PC で `ipconfig`（Windows）・`ifconfig`（macOS）・`ip addr`（Linux）を実行して見えるのは、LAN の中での **プライベートアドレス** です。
一方、接続元のアドレスを表示する Webサイトにアクセスすると、ルータが NAPT で変換した後の **グローバルアドレス** が表示されます。
2つが違うのは、間に NAPT ルータがあるからです。

```
# 表示の例（形式は OS によって異なります）
PC で見えるアドレス:              192.168.10.105    ← プライベートアドレス
Webサイトから見える接続元アドレス: 203.0.113.10      ← ルータの WAN側のグローバルアドレス
```

### 覚えておきたい特別な範囲

RFC 1918 の3つ以外にも、次の範囲は現場でよく見かけます。

| 範囲 | 見かける場面 |
| --- | --- |
| 169.254.0.0/16 | **リンクローカルアドレス**。DHCP でアドレスを受け取れなかったとき、OS が自動で付けることがある。この値になっていたら DHCP の失敗を疑う |
| 100.64.0.0/10 | ISP が自社の中で NAT をもう一段行う（キャリアグレード NAT）ために使う共有アドレス。ルータの WAN側がこの範囲なら、自分のルータでポートフォワーディングを設定しても、外から始まる通信は通常届かない |
| 127.0.0.0/8 | ループバック（自分自身）。`ping 127.0.0.1` は自分の PC の TCP/IP の動作確認になる |

### 外から社内に入る通信の扱い

- NAPT ルータは、内側から始まった通信の戻りだけを変換表で通すので、外から突然届いたパケットは基本的に内側へ届きません。
- 外部に公開したいサーバがあるときは、「外部の 443番ポート宛ては内部の 192.168.20.10 の 443番へ」のような **ポートフォワーディング**（静的 NAPT）をルータに設定します。ただし、その機器がインターネットから直接攻撃を受けるようになるので、社内向けの機器（NAS など）は公開せず、VPN で社内に入ってから使うのが一般的です。
- 変換表の項目は、通信がないまま一定時間たつと消されます。長時間なにも送らない接続が切れるときは、この時間切れが原因のことがあります。

## 事例

[みなと事務所](../../../)（社員30名・来客用 Wi-Fi あり）は、ISP から固定のグローバルアドレス 203.0.113.10 を1個だけ割り当てられています。
社内の3つのネットワーク（192.168.10.0/24・192.168.20.0/24・192.168.30.0/24）はすべてプライベートアドレスで、インターネットへはルータの NAPT で出ます。

社員2人と来客1人が同時に自社サイト（198.51.100.20）を開いたとき、ルータの変換表は例えば次のようになります（ポート番号は説明のための例です）。

| 内部のアドレス:ポート | 変換後のアドレス:ポート | 宛先 |
| --- | --- | --- |
| 192.168.10.105:52814 | 203.0.113.10:40001 | 198.51.100.20:443 |
| 192.168.10.123:52814 | 203.0.113.10:40002 | 198.51.100.20:443 |
| 192.168.30.150:61000 | 203.0.113.10:40003 | 198.51.100.20:443 |

社員2人の PC がたまたま同じ送信元ポート 52814 を使っていても、変換後のポートが違うので、戻りのパケットを正しく振り分けられます。

運用では、次の点を決めています。

- **公開サーバは置かない**: 自社サイトはレンタルサーバ上にあるので、事務所のルータにはポートフォワーディングを設定していません。
- **在宅勤務から NAS を使う**: NAS をインターネットに公開せず、ルータの VPN 機能で社内に入ってから使います。社内のネットワークを家庭用ルータの初期値に多い 192.168.1.0/24 や 192.168.0.0/24 にしなかったのは、自宅のネットワークとの重なりを避けるためです。
- **接続元アドレスでの制限に頼りすぎない**: クラウドのメールサービスの管理画面には「接続元が 203.0.113.10 のときだけ許可」という制限を設定しました。ただし、来客用 Wi-Fi の通信も同じ 203.0.113.10 に変換されて出ていくため、この制限だけでは「社員の端末から」とは言えません。管理画面には多要素認証も必ず組み合わせています。

## 試験対策のポイント

- **ITパスポート**: 「プライベートIPアドレスは組織内で自由に使え、インターネットとの通信には NAT でグローバルアドレスに変換する」という役割を説明できること。
- **基本情報**: プライベートアドレスの3つの範囲、NAT と NAPT の違い（ポート番号も変換するか）。
- **応用情報**: NAPT の変換表の動き、DMZ に置いた公開サーバへの静的 NAT（ポートフォワーディング）の設定などが、ネットワーク構成の問題で問われる。
