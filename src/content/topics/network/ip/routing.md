**ルーティング** とは、パケットを宛先ネットワークへ届けるために、次にどのルータへ渡すかを決めることです。
ルータは **ルーティングテーブル（経路表）** を参照して転送先を決めます。

## ルーティングテーブル

| 宛先ネットワーク | 次の転送先（ネクストホップ） | 出力インタフェース | メトリック |
| --- | --- | --- | --- |
| 192.168.1.0/24 | 直接接続 | eth0 | 0 |
| 192.168.2.0/24 | 10.0.0.2 | eth1 | 1 |
| 192.168.2.128/25 | 10.0.0.3 | eth1 | 1 |
| 0.0.0.0/0 | 10.0.0.1 | eth1 | — |

- **0.0.0.0/0** は **デフォルトルート** です。どの経路にも一致しないパケットはここに送られます。
  端末の設定でいう「デフォルトゲートウェイ」は、このデフォルトルートの転送先にあたります。
- **メトリック** は経路の「遠さ・コスト」を表す値で、複数の経路があるとき小さい方を選びます。

### ロンゲストマッチ

宛先に一致する経路が複数ある場合、**プレフィックス長が最も長い（より詳細な）経路** を優先します。

> 上の表で宛先が 192.168.2.200 の場合、192.168.2.0/24 と 192.168.2.128/25 の両方に一致しますが、
> より長い /25 が選ばれ、10.0.0.3 に転送されます。

## 静的ルーティングと動的ルーティング

| 方式 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| 静的（スタティック）ルーティング | 管理者が経路を手作業で設定する | 設定が単純、ルータの負荷が小さい | 構成変更や障害時に自動で切り替わらない |
| 動的（ダイナミック）ルーティング | ルータ同士がルーティングプロトコルで経路情報を交換する | 障害時に迂回経路へ自動で切り替わる | 設定・処理が複雑 |

## 主なルーティングプロトコル

| プロトコル | 方式 | 経路選択の基準 | 主な用途 |
| --- | --- | --- | --- |
| RIP | ディスタンスベクタ型 | **ホップ数**（経由するルータの数）。最大15で、16は到達不能 | 小規模ネットワーク |
| OSPF | リンクステート型 | **コスト**（回線の帯域などから算出） | 組織内の中〜大規模ネットワーク |
| BGP | パスベクタ型 | 経由する AS（自律システム）の経路情報とポリシー | ISP 間など **AS 間** のルーティング |

- **ディスタンスベクタ型** は、隣接ルータと「どの宛先まで何ホップか」を定期的に交換します。仕組みが単純な反面、障害時に経路が収束するまで時間がかかります。
- **リンクステート型** は、各ルータがネットワーク全体の接続状態（トポロジ）を共有し、それぞれが最短経路を計算します（ダイクストラ法）。収束が速く大規模向きです。
- 組織（AS）内で使うプロトコル（RIP, OSPF）を **IGP**、AS 間で使うもの（BGP）を **EGP** と呼びます。

## 実務での見え方

### PC にもルーティングテーブルがある

ルーティングテーブルはルータだけのものではありません。PC やスマートフォンも、自分のテーブルを見て「直接届けるか、デフォルトゲートウェイに渡すか」を決めています。

```
route print       # Windows（netstat -r でも可）
netstat -rn       # macOS
ip route          # Linux
```

Linux の `ip route` では、例えば次のように表示されます（形式を示すための例です）。

```
default via 192.168.10.1 dev eth0 proto dhcp metric 100
192.168.10.0/24 dev eth0 proto kernel scope link src 192.168.10.105 metric 100
```

- 1行目の `default` が **デフォルトルート**（0.0.0.0/0）で、転送先 `192.168.10.1` がデフォルトゲートウェイです。`proto dhcp` は DHCP で受け取った設定であることを表します。
- 2行目は自分がつながっているネットワーク（**直接接続**）で、この範囲の宛先にはルータを通さず直接送ります。

Windows の `route print` では「ネットワーク宛先」「ネットマスク」「ゲートウェイ」「インターフェイス」「メトリック」の列が並び、`0.0.0.0` / `0.0.0.0` の行がデフォルトルートです。
Linux では `ip route get 198.51.100.20` のように宛先を指定すると、その宛先にどの経路が選ばれるかを表示できます。

### 経路をたどる: tracert / traceroute

`tracert`（Windows）・`traceroute`（macOS・Linux）は、宛先までに経由するルータを順に表示します。
IPヘッダの TTL を 1, 2, 3… と増やしながら送り、TTL が 0 になったルータから返る ICMP の時間超過メッセージで、途中のルータを知る仕組みです（[ARP と ICMP](../arp-icmp/) 参照）。

```
# Windows の tracert の表示の例（形式を示すための例です）
  1    <1 ms    <1 ms    <1 ms  192.168.10.1
  2     3 ms     2 ms     3 ms  203.0.113.1
  3     *        *        *     要求がタイムアウトしました。
  4    12 ms    11 ms    12 ms  198.51.100.20
```

`*` はそのルータから応答が返らなかったことを示します。応答を返さない設定のルータもあるので、その先で宛先まで届いていれば問題とは限りません。
逆に、ある段から先がずっと `*` なら、そのあたりで経路が途切れている可能性があります。

### 現場でよくある構成とトラブル

- **小規模な拠点**: ルータ1台に、社内のネットワーク（直接接続）と、ISP に向けた静的なデフォルトルートだけ、という構成がほとんどです。動的ルーティングは、拠点が多い・回線を二重化している、といった場合に使います。
- **デフォルトゲートウェイの誤り**: 同じネットワークの機器とは通信できるのに、インターネットや別のネットワークには届かない、という症状になります。
- **戻りの経路がない**: 新しいネットワークやルータを追加して「行き」の経路だけ設定すると、相手からの「戻り」のパケットが届かず通信できません。経路は **両方向** に必要です。
- **集約しやすい割当て**: 拠点ごとに連続したアドレスのまとまりを割り当てておくと、経路集約でルーティングテーブルを短くできます（[サブネットマスクとCIDR](../ip-address/subnet/) の例題3）。

## 事例

[みなと事務所](../../)（社員30名・2フロア）のルータのルーティングテーブルは、次のとおりです。

| 宛先ネットワーク | 次の転送先 | 出力インタフェース |
| --- | --- | --- |
| 192.168.10.0/24（社員用） | 直接接続 | VLAN 10 |
| 192.168.20.0/24（機器用） | 直接接続 | VLAN 20 |
| 192.168.30.0/24（来客用） | 直接接続 | VLAN 30 |
| 0.0.0.0/0 | 203.0.113.1（ISP のルータ） | WAN |

社員の PC（192.168.10.105）が NAS（192.168.20.10）にファイルを保存するときは、

1. PC が自分のテーブルを見る。192.168.20.10 は自分のネットワーク（192.168.10.0/24）ではないので、デフォルトゲートウェイ 192.168.10.1 に渡す
2. ルータが自分のテーブルを見る。192.168.20.0/24 は直接接続なので、VLAN 20 に出して NAS に届ける
3. NAS からの返事は、NAS のデフォルトゲートウェイ 192.168.20.1 を通って逆の順にたどる

という流れになります。自社サイト（198.51.100.20）宛ては、ルータで 0.0.0.0/0 に一致して ISP へ送られます。

**分室の追加**: 近くのビルに社員5名の分室を開き、分室のネットワークを 192.168.40.0/24 として、インターネット経由の拠点間 VPN でつなぎました。

| ルータ | 追加した静的経路 |
| --- | --- |
| 本社のルータ | 192.168.40.0/24 → VPN（分室） |
| 分室のルータ | 192.168.0.0/19 → VPN（本社）。本社の 3つのネットワーク（第3オクテット 10・20・30）は 0〜31 の範囲に入るので1行に集約できる |

最初は本社側の経路だけを設定したため、本社から分室の PC に `ping` しても応答がありませんでした。
分室のルータが本社のネットワークへの戻りの経路を知らず、返事をデフォルトルートでインターネットへ送ってしまっていたためです。
分室側にも経路を追加して解決しました。集約した 192.168.0.0/19 には分室自身の 192.168.40.0/24（第3オクテット 40 は 32〜63 の範囲）は含まれないことも、2進数で確かめています。

## 試験対策のポイント

- **基本情報**: ルーティングテーブルを読んで転送先を答える問題（デフォルトルート・ロンゲストマッチ）、RIP と OSPF の基準の違い。
- **応用情報**: 経路集約、冗長経路の設計、障害時の経路切替えなど、ネットワーク構成図とルーティングテーブルを組み合わせた問題が出る。
