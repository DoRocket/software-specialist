通信に必要な機能は非常に多いため、**役割ごとに層（レイヤ）に分割** して設計します。
層ごとに独立させることで、例えば「有線LANを無線LANに変えても、上位のWebブラウザは何も変えなくてよい」という分業が可能になります。
その分け方の代表が **OSI参照モデル（7層）** と **TCP/IPモデル（4層）** です。

## OSI参照モデル

ISO（国際標準化機構）が定めた、通信機能を7つの層に分けた **概念モデル** です。

| 層 | 名称 | 役割 | 代表例 |
| --- | --- | --- | --- |
| 第7層 | アプリケーション層 | アプリケーションごとの通信サービスを提供 | HTTP, SMTP, FTP, DNS |
| 第6層 | プレゼンテーション層 | 文字コード・圧縮・暗号化などデータ表現の変換 | （TLS や MIME の一部機能） |
| 第5層 | セッション層 | 通信の開始から終了までの管理（同期・対話制御） | — |
| 第4層 | トランスポート層 | 端末間（エンドツーエンド）の信頼性確保・アプリの識別 | TCP, UDP |
| 第3層 | ネットワーク層 | 異なるネットワーク間の経路選択と中継 | IP, ICMP |
| 第2層 | データリンク層 | 隣接する機器間の伝送制御・誤り検出 | Ethernet, PPP |
| 第1層 | 物理層 | ビット列と電気・光・電波信号の変換、コネクタ形状 | 10BASE-T, 光ファイバ |

> 覚え方の例: 下から「物・デ・ネ・ト・セ・プ・ア」

## TCP/IPモデル

インターネットで実際に使われているプロトコル群（TCP/IP）の階層構造です。OSIの7層をより実用的に4層にまとめています。

| TCP/IPモデル | 対応するOSI参照モデルの層 | 主なプロトコル |
| --- | --- | --- |
| アプリケーション層 | 第5〜7層 | HTTP, HTTPS, SMTP, POP3, IMAP, DNS, DHCP, FTP, SSH |
| トランスポート層 | 第4層 | TCP, UDP |
| インターネット層 | 第3層 | IP, ICMP, ARP（※） |
| ネットワークインタフェース層 | 第1〜2層 | Ethernet, 無線LAN（IEEE 802.11） |

※ ARP は IPアドレスとMACアドレスを対応付けるプロトコルで、第2層と第3層の橋渡しをします。教材によって所属する層の扱いが異なります。

## カプセル化とデータの単位（PDU）

送信側では上位層のデータに各層が **ヘッダ** を付け加えながら下の層へ渡し（カプセル化）、
受信側では下位層から順にヘッダを取り外して上位層へ渡します。

| 層 | データの呼び方 | 宛先を示す情報 |
| --- | --- | --- |
| トランスポート層 | セグメント（TCP）／データグラム（UDP） | ポート番号 |
| ネットワーク層（インターネット層） | パケット | IPアドレス |
| データリンク層 | フレーム | MACアドレス |
| 物理層 | ビット | — |

## 実務での見え方

### 実際の通信も層の入れ子になっている

**パケットキャプチャ**（流れる通信を記録して中身を表示するソフト。代表例は Wireshark）で Webページを1つ開くときの通信を記録すると、
1つのフレームが層ごとのヘッダに分けて表示されます。次は表示のされ方の例です（実際は行が並んで表示されます。ここでは入れ子が分かるよう字下げしています）。

```
Ethernet II, Src: (送信元のMACアドレス), Dst: (宛先のMACアドレス)       ← データリンク層
  Internet Protocol Version 4, Src: 192.168.10.105, Dst: 198.51.100.20  ← インターネット層
    Transmission Control Protocol, Src Port: 52814, Dst Port: 443     ← トランスポート層
      Transport Layer Security                                         ← アプリケーション層（HTTPS）
```

上の表の「宛先を示す情報」が、それぞれの層のヘッダに実際に入っていることが分かります。

### つながらないときは下の層から確かめる

上の層は下の層が動いていることを前提にしているので、障害の切り分けは **下の層から順に** 確かめるのが基本です。
逆に、ある層の確認が成功すれば、それより下の層はその経路では動いていると判断できます。

| 層 | 確かめること | 方法・コマンドの例 |
| --- | --- | --- |
| 物理層 | ケーブルが挿さってリンクランプが点いているか、Wi-Fi に接続しているか | 機器のランプ、OS のネットワーク設定画面 |
| データリンク層 | 同じネットワークの機器（ルータなど）の MACアドレスが分かるか | `arp -a` |
| インターネット層 | IPアドレスが正しく付いているか、ルータや外部の IPアドレスに届くか | `ipconfig`・`ip addr`・`ifconfig`、`ping`、`tracert`・`traceroute` |
| トランスポート層 | 相手のポート（例: HTTPS の 443番）に接続できるか | Windows の PowerShell で `Test-NetConnection 名前 -Port 443`、macOS・Linux で `nc -vz 名前 443` |
| アプリケーション層 | 名前解決できるか、アプリの設定やエラーの内容 | `nslookup`・`dig`、ブラウザのエラー表示 |

手元の PC では、例えば次の順に確かめます（`#` の行は説明です。コマンドは OS によって異なります）。

```
# 1. 自分の IPアドレスとデフォルトゲートウェイを確認する
ipconfig                 # Windows
ifconfig                 # macOS
ip addr ; ip route       # Linux

# 2. デフォルトゲートウェイ（ルータ）に届くか
ping 192.168.10.1        # macOS・Linux は止めるまで続くので ping -c 4 192.168.10.1 のように回数を指定

# 3. 名前を使わず、インターネット上の IPアドレスに届くか
ping 198.51.100.20

# 4. 名前から IPアドレスを調べられるか
nslookup www.minato.example
```

3 が成功して 4 が失敗すれば DNS、2 が失敗すれば PC とルータの間（ケーブル・Wi-Fi・IPアドレスの設定）、
というように、どこまで届いたかで原因の層を絞り込めます。
なお、`ping` が使う ICMP を受け付けない設定のサーバもあるため、`ping` の失敗だけで「つながらない」と決めつけず、他の確認と組み合わせます。

## 事例

この分野では、[ネットワーク](../) のページで紹介した **架空の「みなと事務所」**（社員30名・2フロア・来客用 Wi-Fi あり）を通しで使います。
まず、事務所の構成要素を層で整理しておくと、各記事の内容がどこに当たるかが分かります。

| 層 | みなと事務所で該当するもの |
| --- | --- |
| アプリケーション層 | ブラウザと自社サイト、NAS のファイル共有、メール、DHCP（アドレスの自動配布）、DNS（名前解決） |
| トランスポート層 | Web の 443番/TCP、DNS の 53番/UDP など、アプリごとのポート番号 |
| インターネット層 | ルータ、192.168.10.0/24 などのネットワークと IPアドレス |
| データリンク層 | 各階の L2スイッチ、VLAN、無線LAN（IEEE 802.11） |
| 物理層 | LANケーブル、光回線、AP の電波 |

ある月曜の朝、4階の社員Aさんから「自社サイトが開けない」と連絡がありました。同じ4階の他の社員は見られるので、範囲は Aさんの PC に絞れます。総務の担当者は下の層から確かめました。

1. **物理層**: Wi-Fi は「minato-staff に接続済み」と表示されている。
2. **インターネット層**: `ipconfig` で IPv4アドレスは 192.168.10.123、デフォルトゲートウェイは 192.168.10.1 と、正しい範囲の値が付いている。`ping 192.168.10.1` も `ping 198.51.100.20` も応答がある。ここまでで物理層〜インターネット層とルータの経路は問題ないと分かる。
3. **アプリケーション層**: `nslookup www.minato.example` がタイムアウトする。詳しく見ると、DNSサーバが手動で古い値（以前の事務所で使っていたもの）に設定されていた。

DNSサーバの設定を「自動取得」（DHCP から受け取る）に戻すと表示できるようになりました。
「どこまでは届くか」を層ごとに確かめたことで、ケーブルやルータを疑って時間を使わずに済んでいます。
層で考えると、回線の問題なら ISP、社内LAN の問題なら自社、アプリの問題ならそのサービスの提供元、というように **問い合わせ先の切り分け** もしやすくなります。

## 試験対策のポイント

- **ITパスポート**: 「IPアドレスはどの層か」「HTTPはどの層か」など、代表的なプロトコルと層の対応を覚える。
- **基本情報**: 層と **ネットワーク機器**（リピータ=第1層、L2スイッチ=第2層、ルータ=第3層…）の対応が頻出。PDUの呼び名もセットで。
- **応用情報**: 各層のヘッダが持つ情報（MACアドレス・IPアドレス・ポート番号）を踏まえて、
  ファイアウォールやNAPTが「どの層の情報を見て/書き換えて」動くのかを説明できるようにする。
