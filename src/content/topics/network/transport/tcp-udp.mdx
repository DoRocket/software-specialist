**TCP**（Transmission Control Protocol）と **UDP**（User Datagram Protocol）は、トランスポート層の代表的なプロトコルです。
アプリケーションは、用途に応じてどちらを使うかを選びます。

## 比較

| 項目 | TCP | UDP |
| --- | --- | --- |
| 接続 | **コネクション型**（通信前に接続を確立する） | **コネクションレス型**（いきなり送る） |
| 信頼性 | 高い。確認応答・再送・順序制御を行う | なし。届いたか・順序が正しいかを保証しない |
| 速度・負荷 | 制御が多い分オーバーヘッドが大きい | 制御が少なく高速・低負荷 |
| ヘッダ長 | 20バイト〜（オプションで可変） | **8バイト固定** |
| 宛先 | 1対1（ユニキャスト）のみ | ブロードキャスト・マルチキャストにも使える |
| 主な用途 | Web（HTTP/HTTPS）、メール（SMTP, POP3, IMAP）、ファイル転送（FTP）、SSH | DNS の問合せ、DHCP、NTP、音声通話（VoIP）、動画のライブ配信 |

音声通話やライブ配信では、遅れて届いたデータを再送しても役に立たないため、
多少の欠落を許容してでも遅延の小さい UDP が選ばれます。

### その他の制御

| 仕組み | 内容 |
| --- | --- |
| シーケンス番号と確認応答（ACK） | 送ったデータに番号を付け、受信側は「どこまで受け取ったか」を返す。順序の並べ替えにも使う |
| 再送制御 | 一定時間内に ACK が返らなければ再送する |
| フロー制御（ウィンドウ制御） | 受信側が受け取れる量（ウィンドウサイズ）を通知し、ACK を待たずにその範囲までまとめて送ることで効率を上げつつ、受信側があふれないようにする |
| 輻輳（ふくそう）制御 | ネットワークの混雑を検知したら送信量を減らし、混雑を悪化させないようにする |

## ポート番号

ポート番号は 0〜65535 の 16 ビットの値で、通信相手のアプリケーションを識別します。
**IPアドレス + ポート番号** の組で通信の端点が決まります。

| 範囲 | 名称 | 用途 |
| --- | --- | --- |
| 0〜1023 | ウェルノウンポート | 代表的なサービス用に予約 |
| 1024〜49151 | 登録済みポート | 特定のアプリケーション用に登録 |
| 49152〜65535 | 動的・プライベートポート | クライアント側が一時的に使う |

### 代表的なウェルノウンポート

| ポート番号 | プロトコル | TCP/UDP |
| --- | --- | --- |
| 20, 21 | FTP（20: データ転送、21: 制御） | TCP |
| 22 | SSH | TCP |
| 23 | Telnet | TCP |
| 25 | SMTP | TCP |
| 53 | DNS | UDP（ゾーン転送や大きな応答では TCP） |
| 67, 68 | DHCP（67: サーバ、68: クライアント） | UDP |
| 80 | HTTP | TCP |
| 110 | POP3 | TCP |
| 123 | NTP | UDP |
| 143 | IMAP | TCP |
| 443 | HTTPS | TCP（HTTP/3 では UDP 上の QUIC） |

メール送信では、利用者のメールソフトからサーバへの送信に **サブミッションポート（587）** を使い、
**SMTP-AUTH** で利用者を認証する運用が一般的です（迷惑メール対策の **OP25B** と組み合わせる）。

## 試験対策のポイント

- **ITパスポート**: TCP は信頼性重視、UDP はリアルタイム性重視、という使い分け。ポート番号がアプリケーションの識別に使われること。
- **基本情報**: 3ウェイハンドシェイク、TCP/UDP それぞれを使う代表的なプロトコル、代表的なポート番号（80, 443, 25, 110, 53 など）。
- **応用情報**: ファイアウォールのフィルタリングルール（送信元/宛先ポートの指定）、NAPT のポート変換、ウィンドウ制御による スループットの考え方などが問われる。
