攻撃手法は「どの弱点を狙い、どのセキュリティ要素（CIA）を損なうか」で整理すると理解しやすくなります。
ここでは試験で頻出の手口と、それぞれの代表的な対策をまとめます。

## マルウェア

悪意のあるソフトウェアの総称です。

| 種類 | 特徴 |
| --- | --- |
| ウイルス | 他のプログラムに寄生して感染を広げる |
| ワーム | 単独で動作し、ネットワークを通じて自己複製・拡散する |
| トロイの木馬 | 有用なソフトを装って侵入し、裏で不正な動作をする |
| ランサムウェア | ファイルを暗号化するなどして使えなくし、復旧と引換えに金銭を要求する |
| スパイウェア / キーロガー | 利用者の情報やキー入力を盗み取って送信する |
| ボット | 感染した PC を外部の C&C サーバから遠隔操作できるようにする |

**対策**: OS・ソフトウェアの更新（脆弱性の修正）、マルウェア対策ソフトの導入と定義ファイルの更新、不審な添付ファイルを開かない、ランサムウェアに備えた **オフライン（ネットワークから切り離した）バックアップ**。

## フィッシング

実在の金融機関や EC サイトなどを装ったメールや SMS で偽サイトへ誘導し、ID・パスワードやクレジットカード情報を入力させて盗む手口です。

**対策**: メールのリンクから直接ログインしない、URL やサーバ証明書を確認する、多要素認証の導入、送信ドメイン認証（SPF・DKIM・DMARC）による送信元詐称の検知。

## Web アプリケーションへの攻撃

| 攻撃 | 手口 | 主な対策 |
| --- | --- | --- |
| SQL インジェクション | 入力欄に SQL の一部を入力し、意図しない SQL 文を実行させる | **プレースホルダ（バインド機構）** の利用、特殊文字のエスケープ、DB アカウントの権限最小化 |
| クロスサイトスクリプティング（XSS） | 悪意のあるスクリプトを Web ページに埋め込み、閲覧者のブラウザで実行させる（Cookie の窃取など） | 出力時の **エスケープ（サニタイジング）**、Cookie への HttpOnly 属性付与 |
| クロスサイトリクエストフォージェリ（CSRF） | ログイン中の利用者に罠ページを踏ませ、本人の意図しない処理（送金・投稿など）を正規サイトへ送信させる | 推測困難な **トークン** をフォームに埋め込み照合する、重要処理前の再認証、Cookie の SameSite 属性 |

### SQL インジェクションの例

次のように入力値を文字列連結で SQL 文に組み込むと危険です。

```sql
-- アプリケーションが組み立てる SQL
SELECT * FROM 利用者 WHERE id = '入力値' AND pw = '入力値';

-- id 欄に「' OR '1'='1' --」と入力されると
SELECT * FROM 利用者 WHERE id = '' OR '1'='1' --' AND pw = '';
```

`--` 以降はコメントとして無視され、`'1'='1'` は常に真なので、パスワードを知らなくても全利用者の行が返ります。
プレースホルダを使うと、入力値は SQL 文の構造とは切り離されて「値」としてのみ扱われるため、この攻撃を防げます。

XSS と CSRF はどちらも罠ページなどを経由しますが、XSS は **閲覧者のブラウザでスクリプトを実行させる** 攻撃、CSRF は **正規サイトに本人の権限でリクエストを送らせる** 攻撃という違いがあります。

## DoS 攻撃 / DDoS 攻撃

大量のリクエストやパケットを送り付けてサーバやネットワークを過負荷にし、サービスを停止させる攻撃で、**可用性** を損ないます。

- **DoS**（Denial of Service）: 1台から攻撃する。
- **DDoS**（Distributed DoS）: ボットに感染させた多数の機器（ボットネット）から一斉に攻撃する。送信元が多数あるため、特定の送信元を遮断するだけでは防ぎにくい。
- **SYN フラッド**: TCP の接続確立（3ウェイハンドシェイク）で SYN だけを大量に送り、サーバの接続待ちの資源を使い果たさせる。
- **リフレクション攻撃**: 送信元 IP アドレスを攻撃対象に偽装して DNS などに問い合わせ、応答を対象に集中させる。応答が要求より大きくなるものは **増幅攻撃** とも呼ばれる。

**対策**: ファイアウォールや IPS による異常な通信の遮断、通信量の制限、CDN や ISP の DDoS 対策サービスの利用、サーバの冗長化。

## 標的型攻撃

特定の組織を狙い、業務に関係がありそうな件名・本文のメールでマルウェア付きの添付ファイルや URL を開かせ、侵入後に組織内部で感染を広げて機密情報を盗み出す攻撃です。
長期間にわたって潜伏しながら継続するものは **APT**（Advanced Persistent Threat）とも呼ばれます。
攻撃対象がよく閲覧する Web サイトを改ざんして待ち伏せる **水飲み場型攻撃** もこの一種です。

**対策**: 不審メールへの教育・訓練、入口対策（メールフィルタ）だけでなく **出口対策**（外部への不審な通信の検知・遮断）、ログ監視、ネットワークの分離による多層防御。

## ソーシャルエンジニアリング

技術ではなく **人間の心理や習慣の隙** を突いて情報を盗む手口です。

| 手口 | 内容 |
| --- | --- |
| なりすまし電話 | 上司や保守担当者を装い、パスワードなどを聞き出す |
| ショルダーハッキング | 背後からのぞき見して画面や入力を盗み見る |
| トラッシング | ごみ箱に捨てられた書類や媒体から情報を得る |
| ビジネスメール詐欺（BEC） | 取引先や経営者を装ったメールで偽の口座へ送金させる |

**対策**: 規程と手順の整備（電話でパスワードを教えない、送金先変更は別経路で確認する等）、従業員教育、のぞき見防止フィルタ、シュレッダーや媒体の確実な廃棄。

## 試験対策のポイント

- **ITパスポート**: 事例文から攻撃名を答える問題が中心です。ランサムウェア、フィッシング、ソーシャルエンジニアリング（ショルダーハッキング・トラッシング）、標的型攻撃の特徴を区別できるようにします。
- **基本情報**: SQL インジェクション・XSS・CSRF の手口と対策の対応付けが頻出です。「SQL インジェクション → プレースホルダ」「XSS → 出力時のエスケープ」「CSRF → トークン」と結び付けて覚えます。DoS と DDoS の違いも問われます。
- **応用情報**: 午後問題で、ログや通信の記録から攻撃を特定し、入口・内部・出口の多層的な対策を提案する力が問われます。リフレクション攻撃や水飲み場型攻撃など、手口の仕組みまで説明できるようにしておきます。
