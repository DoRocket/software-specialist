技術的セキュリティ対策は、ネットワーク機器やソフトウェアの機能で不正アクセスやマルウェアを防ぎ、発見する仕組みです。
1つの対策ですべてを防ぐことはできないため、性質の異なる対策を重ねる **多層防御** が基本になります。

## ファイアウォール

ネットワークの境界に置き、あらかじめ決めたルールに従って **通信を許可・遮断** する仕組みです。

| 方式 | 判断に使う情報 | 特徴 |
| --- | --- | --- |
| パケットフィルタリング | IP アドレス、プロトコル、ポート番号（ネットワーク層・トランスポート層） | 高速。通信の中身は見ない |
| ステートフルパケットインスペクション | 上記に加え、通信の状態（どちらから開始した通信か） | 内側から始めた通信への **応答だけ** を自動的に通せる |
| アプリケーションゲートウェイ | アプリケーション層のデータ | プロキシとして中継し、内容まで検査できるが処理は重い |

ルールは **上から順に** 照合され、最初に一致したルールが適用されます。最後にすべてを拒否するルールを置き、明示的に許可した通信だけを通すのが原則です。

| 番号 | 送信元 | 宛先 | プロトコル / 宛先ポート | 動作 |
| --- | --- | --- | --- | --- |
| 1 | すべて | DMZ の Web サーバ | TCP / 443 | 許可 |
| 2 | すべて | DMZ のメールサーバ | TCP / 25 | 許可 |
| 3 | 内部 LAN | すべて | TCP / 443 | 許可 |
| 4 | すべて | すべて | すべて | 拒否 |

### 例題

**問** 上のルールで、インターネット上の PC から内部 LAN のファイルサーバ宛ての TCP / 443 のパケットはどう扱われるか。

**解き方** ルール1・2は宛先が DMZ のサーバ、ルール3は送信元が内部 LAN なので一致しません。ルール4に一致し **拒否** されます。インターネットから内部 LAN へ直接入る通信は通さない設計になっています。

## DMZ

**DMZ**（DeMilitarized Zone: 非武装地帯）は、インターネットと内部 LAN の間に設ける緩衝区域で、Web サーバ・メールサーバ・DNS サーバなどの **外部に公開するサーバ** を置きます。

上のルール表を使って、どの通信が通過し、どの通信が遮断されるかを順に見てみましょう。

<FirewallDmz />

- インターネット → DMZ: 公開サービスに必要な通信だけ許可
- インターネット → 内部 LAN: 拒否
- DMZ → 内部 LAN: 原則拒否（公開サーバが乗っ取られても、被害を内部に広げないため）

## IDS / IPS と WAF

| 対策 | 役割 | 検査する範囲 |
| --- | --- | --- |
| IDS（侵入検知システム） | 不正な通信や挙動を **検知して管理者に通知** する。通信は止めない | ネットワーク型（NIDS）とホスト型（HIDS）がある |
| IPS（侵入防止システム） | 検知に加えて **通信を自動的に遮断** する。通信経路上（インライン）に置く | ネットワーク上の通信 |
| WAF（Web Application Firewall） | HTTP の内容を検査し、SQL インジェクションや XSS などの **Web アプリケーションへの攻撃** を検知・遮断する | アプリケーション層（HTTP） |

ファイアウォールは Web サーバ宛ての 443 番ポートの通信を許可すると、その中身までは検査しません。WAF はその隙間を補うものですが、根本的な対策はアプリケーションの脆弱性を修正することです。

検知方式には、既知の攻撃パターン（シグネチャ）と照合する **シグネチャ型（不正検出）** と、平常時の状態からのずれを異常とみなす **アノマリ型（異常検出）** があります。アノマリ型は未知の攻撃も検知できる可能性がある一方、誤検知が増えがちです。
正常な通信を攻撃と誤って判定することを **フォールスポジティブ（誤検知）**、攻撃を見逃すことを **フォールスネガティブ（検知漏れ）** といいます。

## VPN

**VPN**（Virtual Private Network）は、共用のネットワーク上に暗号化などで保護された仮想的な専用線をつくる技術です。インターネットを使う **インターネット VPN** と、通信事業者の閉域網を使う **IP-VPN** があります。

| 方式 | 動作する層 | 特徴・主な用途 |
| --- | --- | --- |
| IPsec-VPN | ネットワーク層 | IP パケットを暗号化。**拠点間接続** に多い。改ざん検知・認証を行う **AH** と、暗号化を行う **ESP** があり、鍵交換には IKE を使う |
| TLS-VPN（SSL-VPN） | トランスポート層より上 | TLS で暗号化。Web ブラウザなどで使え、**外出先からのリモートアクセス** に向く |

IPsec には、データ部分だけを暗号化する **トランスポートモード** と、元の IP パケット全体を暗号化して新しいヘッダを付ける **トンネルモード** があり、拠点間 VPN ではトンネルモードが使われます。

## プロキシと検疫ネットワーク

- **フォワードプロキシ**: 内部の PC に代わって外部の Web サーバへアクセスする。URL フィルタリングによる有害サイトの遮断、アクセスログの取得、内部 IP アドレスの隠蔽に使う。
- **リバースプロキシ**: 外部からのアクセスを公開サーバの手前で代理受付し、背後のサーバへ中継する。負荷分散、TLS 通信の終端、WAF 機能の組込みなどに使う。
- **検疫ネットワーク**: 社内 LAN に接続しようとする PC を一時的に隔離されたネットワークにつなぎ、OS の更新やマルウェア定義ファイルが最新かを検査する。不適合な PC は修正を済ませてから接続を許可する。持出し PC からの感染持込みを防げる。

## マルウェア対策

| 検出手法 | 内容 |
| --- | --- |
| パターンマッチング法 | マルウェア定義ファイル（シグネチャ）と照合する。既知のマルウェアに確実だが **未知のものは検出できない** |
| ビヘイビア法（振る舞い検知） | プログラムを動かし、ファイルの大量暗号化など不審な動作を監視して検出する |
| ヒューリスティック法 | マルウェアに特有の命令の並びや挙動の特徴から推定する。未知のマルウェアにも対応できる |
| サンドボックス | 隔離した仮想環境で実際に実行させ、挙動を観察して判定する |

端末上の挙動を常時記録し、侵入後の検知と対応（隔離・調査）を支援する **EDR** も広く使われます。
ランサムウェアに備えたバックアップでは、データを **3つ** 持ち、**2種類** の媒体に保存し、**1つ** は別の場所に置く **3-2-1 ルール** が推奨されます。

## ログ管理

ログは、攻撃の検知、被害範囲の調査、責任追跡性の確保に欠かせません。

- **取得**: 認証の成功・失敗、アクセスログ、ファイアウォールやプロキシの通信ログなどを記録する。
- **時刻の同期**: 複数の機器のログを突き合わせられるよう、NTP で時刻をそろえる。
- **改ざん防止**: 攻撃者はログを消して痕跡を隠そうとするため、別のログサーバへ転送して保管し、アクセス権を限定する。
- **分析**: **SIEM** で複数の機器のログを集約し、相関分析して攻撃の兆候を検知する。

このほか、ファイアウォール・IPS・マルウェア対策などを1台にまとめた **UTM**（統合脅威管理）や、攻撃者をおびき寄せて手口を観察する「おとり」のシステムである **ハニーポット** もあります。

## 実際の進め方

ここでは、ファイアウォール（小規模な組織ではルータのパケットフィルタ機能）のルールを作り、運用の中で見直していく手順を示します。

### ルールを設計する手順

1. **必要な通信を洗い出す**: 業務ごとに「誰が（送信元）」「どこへ（宛先）」「何のために（プロトコル・ポート番号）」を一覧にする。分からない通信は、ログや機器の説明書で確かめる。
2. **ゾーンに分ける**: インターネット、公開サーバ（DMZ）、社員用、サーバ・機器用、来客用のように、同じ扱いをする範囲ごとにまとめる。
3. **許可する通信だけを書く**: 送信元・宛先・ポート番号をできるだけ絞って許可し、最後に **すべて拒否** のルールを置く（明示的に許可したものだけを通す）。
4. **順序を決める**: 上から順に照合されるので、**条件の狭い（具体的な）ルールを上**、広いルールを下に置く。広いルールが上にあると、その下のルールは一度も使われない。
5. **ログの設定をする**: 最後の拒否ルールと、外部から入ってくる通信の許可ルールはログを残す。攻撃の兆候や設定の漏れに気付く手がかりになる。
6. **変更の手順を決める**: 追加・変更は申請と承認を経て台帳に記録し、変更の前後で通信できるか・できないかを確かめる。一時的なルールには期限を付ける。

### ルール台帳（ワークシート）

| 番号 | 送信元 | 宛先 | プロトコル / ポート | 動作 | 目的 | 申請者・登録日 | 期限 | 直近の一致件数 | 最終確認日 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| （例）3 | 社員用 | NAS | TCP / 445 | 許可 | ファイル共有 | 総務課長・2年前 | なし | 多い | 今年4月 |

多くの機器は、ルールごとに一致した件数（ヒット数）を表示できます。長いあいだ一致がないルールは、不要になった可能性があります。

### 定期的な見直しで確かめること

| 確かめること | 見つかったときの対応 |
| --- | --- |
| 目的や申請者が分からないルール | 関係者に確かめ、不要なら削除する。分からないまま残さない |
| 期限の過ぎた一時的なルール（保守作業用など） | 削除する。必要なら期限を付けて申請し直す |
| 送信元・宛先が「すべて」の許可ルール | 必要な範囲に絞る |
| 上のルールに隠れて一度も使われないルール | 順序を見直すか、削除する |
| インターネットから機器の管理画面へ入れるルール | 原則として削除し、管理は社内か VPN 経由で行う |
| 一致件数が長期間 0 のルール | 業務で使っていないか確かめ、不要なら削除する |

### 外から見えるポートを確かめる

設定を変えたら、意図どおりに閉じているかを **外部から** 確かめます。社内からではフィルタの外側の見え方は確かめられないので、スマートフォンのテザリングなど社外の回線につないだ PC から試します（Windows の PowerShell の例）。

```text
PS> Test-NetConnection 203.0.113.10 -Port 8443
...
TcpTestSucceeded : False
```

`False` なら、その宛先・ポートには外部から接続できません。このような確認は、**自組織が管理する機器に対してだけ**、管理者の了解を得て行います。他者のシステムに無断で接続を試すことはしません。

### よくある失敗と対策

| 失敗 | 起きること | 対策 |
| --- | --- | --- |
| 「とりあえず全部許可」を一時的に入れて戻し忘れる | 分けたはずのネットワークの間で、何でも通る状態が続く | 一時的なルールには期限を付け、作業の完了確認に「ルールを戻した」を入れる |
| 保守業者のために管理画面をインターネットに公開する | 世界中から管理画面にログインを試される | 保守は VPN 経由にし、公開が必要なら送信元を業者の固定アドレスに絞る |
| 具体的なルールを広いルールの下に追加する | 追加したルールが効かない | 追加する位置を確かめ、変更後に実際の通信で試す |
| 拒否のログを残していない | 攻撃や設定漏れに気付けない | 最後の拒否ルールのログを残し、定期的に眺める |
| ルールの目的を記録しない | 何年か経つと、消してよいルールか誰にも分からなくなる | 台帳に目的・申請者・期限を書く |

| 9 | すべて | すべて | すべて | 拒否（ログあり） | 最後の拒否 | 約9,000 |

**2. 見つかった問題**

- **ルール 2**: 保守業者が2年前に一時的に設定したポート転送が残っていました。保守業者は最近1年使っておらず、一致した約1,800件のほとんどは海外のアドレスからの接続でした。NAS のログには、管理者アカウントへのログイン失敗が多数記録されていました。
- **ルール 3**: NAS の導入時に入れた「社員用 → 機器用 すべて許可」が残っていて、社員の誰でも NAS・複合機・スイッチの管理画面に接続できました。ルール 4・5 の一致件数が 0 なのは、すべてルール 3 に先に一致していたためです。

**3. 対応**

| 番号 | 対応 |
| --- | --- |
| 2 | 削除。保守業者には VPN のアカウントを発行し、作業のときだけ有効にする運用にした。NAS の管理者パスワードも変更 |
| 3 | 削除し、代わりに「総務課長の管理用 PC（192.168.10.10）→ 機器用 の管理画面（TCP / 443、SSH の TCP / 22）許可」をルール 4 の上に追加 |
| 9 | 拒否ログのうち、インターネットから管理画面へのポートを狙ったものを月1回確認する |

変更後、社員の PC から NAS のファイル共有（TCP 445）と印刷ができること、NAS の管理画面には接続できないことを確かめました。
さらにテザリングでつないだノート PC から `Test-NetConnection 203.0.113.10 -Port 8443` を実行し、`TcpTestSucceeded : False`（外部から接続できない）になったことを確認しました。
ルール 4・5 には翌月から一致件数が記録されるようになり、意図した通信がこれらのルールで許可されていることも確かめられました。

## 試験対策のポイント

- **ITパスポート**: DMZ に置くもの（公開サーバ）、IDS と IPS の違い（通知のみか遮断までか）、WAF・VPN・検疫ネットワークの目的を答えられるようにします。
- **基本情報**: ファイアウォールのルール表から通過するパケットを判定する問題が定番です。シグネチャ型とアノマリ型、フォールスポジティブとフォールスネガティブの区別、マルウェア検出手法も問われます。
- **応用情報**: 午後問題でネットワーク構成図を読み、ファイアウォールのルールの追加・修正、プロキシやリバースプロキシの配置、IPsec と TLS-VPN の使い分け、SIEM を用いたログ分析を考察する力が求められます。
