暗号化方式は、鍵の使い方によって **共通鍵暗号方式** と **公開鍵暗号方式** に大別されます。
共通鍵暗号は高速ですが鍵の受け渡しが課題で、公開鍵暗号はその課題を解決する代わりに処理が遅いという特徴があります。

## 基本用語

| 用語 | 意味 |
| --- | --- |
| 平文 | 暗号化する前の元のデータ |
| 暗号文 | 暗号化して第三者に読めなくしたデータ |
| 暗号化 / 復号 | 平文→暗号文 / 暗号文→平文 に戻すこと |
| 鍵 | 暗号化・復号の処理に使う秘密の値（ビット列） |
| 危殆化 | 計算機の性能向上や解読手法の発見により、暗号の安全性が低下すること |

## 共通鍵暗号方式

暗号化と復号に **同じ鍵（共通鍵）** を使います。秘密鍵暗号方式、対称鍵暗号方式とも呼ばれます。

- 送信者と受信者は同じ鍵を事前に共有し、第三者には秘密にしておく必要があります。
- 処理が高速で、大量のデータの暗号化に向いています。
- **鍵配送問題**: 鍵をどうやって安全に相手へ渡すかが課題です。

代表的な方式は **AES**（Advanced Encryption Standard）です。ブロック長は 128 ビット、鍵長は 128・192・256 ビットから選べます。かつて使われた DES は鍵長が 56 ビットと短く、現在は安全ではないとされています。

## 公開鍵暗号方式

**公開鍵** と **秘密鍵**（私有鍵）という対になる2つの鍵（鍵ペア）を使います。非対称鍵暗号方式とも呼ばれます。

- 一方の鍵で暗号化したものは、対になるもう一方の鍵でしか復号できません。
- 公開鍵は誰に知られてもよく、秘密鍵は持ち主だけが厳重に保管します。
- 公開鍵から秘密鍵を現実的な時間で求めることはできません。

**機密性のための暗号化** では、次のように使います。

1. 受信者 B が鍵ペアを作り、公開鍵を公開する。
2. 送信者 A は **B の公開鍵** で平文を暗号化して送る。
3. B は **自分（B）の秘密鍵** で復号する。秘密鍵を持たない第三者は復号できない。

代表的な方式は **RSA**（大きな数の素因数分解が困難であることを安全性の根拠とする）や、**楕円曲線暗号**（ECC: 楕円曲線上の離散対数問題を根拠とし、RSA より短い鍵長で同程度の安全性を得られる）です。

## 方式の比較

| 項目 | 共通鍵暗号 | 公開鍵暗号 |
| --- | --- | --- |
| 鍵 | 暗号化・復号で同じ鍵 | 暗号化と復号で異なる鍵（鍵ペア） |
| 処理速度 | 高速 | 低速 |
| 鍵の配送 | 安全な配送手段が必要 | 公開鍵は公開してよい |
| n 人で相互に通信するときの鍵の数 | n(n−1)/2 個 | 2n 個（n 組の鍵ペア） |
| 代表例 | AES | RSA、楕円曲線暗号 |

## 例題: 必要な鍵の数

**問題**: 100 人が互いに、他の誰にも内容を知られずに1対1で通信したい。共通鍵暗号方式と公開鍵暗号方式では、それぞれ鍵は何個必要か。

**解き方**:

- 共通鍵暗号: 2人の組合せごとに1つの鍵が必要なので、100 人から 2 人を選ぶ組合せの数になります。
  100 × 99 ÷ 2 = **4,950 個**
- 公開鍵暗号: 1人につき公開鍵と秘密鍵の1組（2個）があればよいので、
  100 × 2 = **200 個**

人数が増えるほど共通鍵暗号の鍵の数は急激に増え、管理が難しくなることがわかります。

## ハイブリッド暗号方式

共通鍵暗号の速さと、公開鍵暗号の鍵配送のしやすさを組み合わせた方式です。

1. 送信者が、その通信だけで使う共通鍵（セッション鍵）をランダムに生成する。
2. **データ本体** はセッション鍵を使って共通鍵暗号で暗号化する。
3. **セッション鍵** は受信者の公開鍵で暗号化して送る。
4. 受信者は自分の秘密鍵でセッション鍵を復号し、そのセッション鍵でデータ本体を復号する。

TLS や S/MIME など、実際の多くのプロトコルがこの考え方を利用しています（TLS では鍵交換に Diffie-Hellman 系の方式を使うのが現在の主流です）。

## 試験対策のポイント

- **ITパスポート**: 「公開鍵暗号で機密性を確保するときは、**受信者の公開鍵** で暗号化し **受信者の秘密鍵** で復号する」が最頻出です。共通鍵暗号が高速であることも押さえます。
- **基本情報**: 鍵の数の計算（n(n−1)/2 と 2n）が定番の計算問題です。AES と RSA がそれぞれどちらの方式かも問われます。
- **応用情報**: ハイブリッド暗号の手順、RSA と楕円曲線暗号の安全性の根拠、鍵長と危殆化、前方秘匿性（PFS）など、方式の選択理由を説明できるようにします。
