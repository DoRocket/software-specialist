暗号化方式は、鍵の使い方によって **共通鍵暗号方式** と **公開鍵暗号方式** に大別されます。
共通鍵暗号は高速ですが鍵の受け渡しが課題で、公開鍵暗号はその課題を解決する代わりに処理が遅いという特徴があります。

## 基本用語

| 用語 | 意味 |
| --- | --- |
| 平文 | 暗号化する前の元のデータ |
| 暗号文 | 暗号化して第三者に読めなくしたデータ |
| 暗号化 / 復号 | 平文→暗号文 / 暗号文→平文 に戻すこと |
| 鍵 | 暗号化・復号の処理に使う秘密の値（ビット列） |
| 危殆化 | 計算機の性能向上や解読手法の発見により、暗号の安全性が低下すること |

## 共通鍵暗号方式

暗号化と復号に **同じ鍵（共通鍵）** を使います。秘密鍵暗号方式、対称鍵暗号方式とも呼ばれます。

- 送信者と受信者は同じ鍵を事前に共有し、第三者には秘密にしておく必要があります。
- 処理が高速で、大量のデータの暗号化に向いています。
- **鍵配送問題**: 鍵をどうやって安全に相手へ渡すかが課題です。

共通鍵暗号で文書を送る流れは次のとおりです。

<CryptoFlow mode="symmetric" />

代表的な方式は **AES**（Advanced Encryption Standard）です。ブロック長は 128 ビット、鍵長は 128・192・256 ビットから選べます。かつて使われた DES は鍵長が 56 ビットと短く、現在は安全ではないとされています。

## 公開鍵暗号方式

**公開鍵** と **秘密鍵**（私有鍵）という対になる2つの鍵（鍵ペア）を使います。非対称鍵暗号方式とも呼ばれます。

- 一方の鍵で暗号化したものは、対になるもう一方の鍵でしか復号できません。
- 公開鍵は誰に知られてもよく、秘密鍵は持ち主だけが厳重に保管します。
- 公開鍵から秘密鍵を現実的な時間で求めることはできません。

**機密性のための暗号化** では、次のように使います。

1. 受信者 B が鍵ペアを作り、公開鍵を公開する。
2. 送信者 A は **B の公開鍵** で平文を暗号化して送る。
3. B は **自分（B）の秘密鍵** で復号する。秘密鍵を持たない第三者は復号できない。

この流れを絵で辿ると次のようになります。暗号化と復号で、使う鍵が違うことに注目してください。

<CryptoFlow mode="public" />

代表的な方式は **RSA**（大きな数の素因数分解が困難であることを安全性の根拠とする）や、**楕円曲線暗号**（ECC: 楕円曲線上の離散対数問題を根拠とし、RSA より短い鍵長で同程度の安全性を得られる）です。

## 方式の比較

| 項目 | 共通鍵暗号 | 公開鍵暗号 |
| --- | --- | --- |
| 鍵 | 暗号化・復号で同じ鍵 | 暗号化と復号で異なる鍵（鍵ペア） |
| 処理速度 | 高速 | 低速 |
| 鍵の配送 | 安全な配送手段が必要 | 公開鍵は公開してよい |
| $n$ 人で相互に通信するときの鍵の数 | $\dfrac{n(n-1)}{2}$ 個 | $2n$ 個（$n$ 組の鍵ペア） |
| 代表例 | AES | RSA、楕円曲線暗号 |

## 例題: 必要な鍵の数

**問題**: 100 人が互いに、他の誰にも内容を知られずに1対1で通信したい。共通鍵暗号方式と公開鍵暗号方式では、それぞれ鍵は何個必要か。

**解き方**:

- 共通鍵暗号: 2人の組合せごとに1つの鍵が必要なので、100 人から 2 人を選ぶ組合せの数になります。
  $100 \times 99 \div 2 =$ **4,950 個**
- 公開鍵暗号: 1人につき公開鍵と秘密鍵の1組（2個）があればよいので、
  $100 \times 2 =$ **200 個**

人数が増えるほど共通鍵暗号の鍵の数は急激に増え、管理が難しくなることがわかります。

## ハイブリッド暗号方式

共通鍵暗号の速さと、公開鍵暗号の鍵配送のしやすさを組み合わせた方式です。

1. 送信者が、その通信だけで使う共通鍵（セッション鍵）をランダムに生成する。
2. **データ本体** はセッション鍵を使って共通鍵暗号で暗号化する。
3. **セッション鍵** は受信者の公開鍵で暗号化して送る。
4. 受信者は自分の秘密鍵でセッション鍵を復号し、そのセッション鍵でデータ本体を復号する。

TLS や S/MIME など、実際の多くのプロトコルがこの考え方を利用しています（TLS では鍵交換に Diffie-Hellman 系の方式を使うのが現在の主流です）。

## 実際の進め方

暗号は「どこで使われているか」を意識すると、方式の違いが実務と結び付きます。ここでは、暗号化を使う場面の整理、ノート PC のディスク暗号化、ファイルの送り方、公開鍵の鍵ペアの扱い方を示します。

### 暗号化を使う場面を整理する

| 守る場面 | 使う技術の例 | 中で使われる暗号 |
| --- | --- | --- |
| Web の通信 | HTTPS（TLS） | 鍵交換と証明書の検証に公開鍵暗号、データ本体は共通鍵暗号（AES など） |
| 社外から社内への接続 | VPN（IPsec・TLS） | 同上（鍵を共有してから共通鍵暗号で暗号化） |
| 機器の遠隔操作 | SSH | 同上。ログインの認証に公開鍵の鍵ペアを使える |
| PC・スマートフォンの保存データ | ディスク暗号化（Windows の BitLocker、macOS の FileVault など） | 共通鍵暗号（AES） |
| バックアップ | 暗号化機能付きの外付けディスク、バックアップソフトの暗号化 | 共通鍵暗号 |
| 社外へ送るファイル | アクセス制限付きの共有リンク、S/MIME など | TLS、公開鍵暗号と共通鍵暗号の組合せ |

大量のデータを暗号化する場面では、ほぼ必ず高速な **共通鍵暗号** が使われ、公開鍵暗号は鍵の受け渡しや相手の確認に使われます。

### ノート PC のディスクを暗号化する

1. **対象を決める**: 社外に持ち出す PC から優先する。
2. **暗号化を有効にする**: OS の設定から有効にする。暗号化の鍵は TPM（PC に組み込まれた、鍵を安全に保管する部品）やログインのパスワードで守られる。
3. **回復キーを保管する**: 故障や設定変更でログインできなくなったときに使う **回復キー** を、PC とは別の場所（管理用のサービスや、鍵のかかる保管庫）に保管する。回復キーを失うと、持ち主でもデータを取り出せなくなる。
4. **状態を確かめる**: すべての対象 PC で暗号化が完了していることを確かめ、台帳に記録する。

状態は、設定画面のほか次のコマンドでも確かめられます（表示は例で、OS の言語や版によって異なります）。

```text
# Windows（管理者として実行したコマンドプロンプト）
> manage-bde -status C:
    Conversion Status:    Fully Encrypted
    Percentage Encrypted: 100.0%
    Encryption Method:    XTS-AES 128
    Protection Status:    Protection On

# macOS（ターミナル）
$ fdesetup status
FileVault is On.
```

`XTS-AES 128` は、AES（鍵長 128 ビット）をディスクの暗号化に向いた使い方（XTS モード）で使っていることを示します。

### ファイルを社外へ送るとき

パスワード付きの ZIP ファイルをメールで送り、続けて **同じ経路** でパスワードを送る方法は、メールを盗み見できる者にはファイルとパスワードの両方が渡るため、鍵配送の問題を解決していません。
暗号化された添付ファイルは受信側でマルウェアの検査ができないため、攻撃者がマルウェアを送り込む手口にも使われています。
代わりに、次のような方法をとります。

- 社内で管理するクラウドストレージに置き、**相手のアカウントだけが開ける共有リンク** を送る。期限を付け、送り終えたら共有を止める。
- どうしても暗号化したファイルを送る場合は、パスワードを電話など **別の経路** で伝える。
- 継続して機密情報をやり取りする相手とは、S/MIME のように相手の公開鍵（証明書）を使う方法を検討する。

### 公開鍵の鍵ペアを扱う（SSH の例）

機器の管理で使う SSH では、パスワードの代わりに鍵ペアでログインできます。鍵ペアは自分の PC で作ります。

```text
$ ssh-keygen -t ed25519 -C "admin-pc"
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/user/.ssh/id_ed25519):
Enter passphrase (empty for no passphrase):
Enter same passphrase again:
Your identification has been saved in /home/user/.ssh/id_ed25519
Your public key has been saved in /home/user/.ssh/id_ed25519.pub
```

- `id_ed25519.pub` が **公開鍵** で、ログイン先の機器に登録する。誰に見られてもよい。
- `id_ed25519` が **秘密鍵** で、自分の PC から出さない。パスフレーズを付けて、盗まれてもすぐには使えないようにする。
- `ed25519` は楕円曲線を使う方式です。古い機器では RSA にしか対応していない場合があるので、機器の対応を確かめて選びます。

SSH のログインでは、機器が送る値に対して PC が秘密鍵で **署名** を作り、機器は登録済みの公開鍵で検証します。これは暗号化ではなくデジタル署名の使い方です（[ハッシュ関数とデジタル署名](../hash-and-signature/) を参照）。

### 鍵の管理ルール

| 場面 | ルール |
| --- | --- |
| 生成 | 鍵は使う本人（または機器）が生成する。他人が作った秘密鍵を受け取って使わない |
| 保管 | 秘密鍵・共通鍵・回復キーは、暗号化したデータとは別の場所に保管する |
| 共有 | 秘密鍵は複数人で共有しない。人ごとに鍵ペアを作り、それぞれの公開鍵を登録する |
| 廃止 | 退職・PC の廃棄・漏えいの疑いがあるときは、登録した公開鍵を削除し、必要なら鍵を作り直す |
| 方式の見直し | 危殆化した方式（DES など）や短い鍵長を使っていないか、定期的に確かめる |

### よくある失敗と対策

| 失敗 | 起きること | 対策 |
| --- | --- | --- |
| 回復キーを PC の中や PC と一緒のかばんに入れる | 紛失したときに、拾った人が回復キーで復号できてしまう | 回復キーは管理用のサービスや保管庫など、PC とは別の場所に置く |
| 回復キーを記録しないまま暗号化する | 故障や OS の更新でログインできなくなったとき、データを取り出せない | 暗号化と同時に回復キーを保管し、台帳に保管場所を記録する |
| 暗号化したファイルとパスワードを同じメールで送る | 盗み見した者が両方を入手できる | 共有リンクを使うか、パスワードを別の経路で伝える |
| 秘密鍵を複数人で共有する・パスフレーズを付けない | 誰が操作したか分からず、1か所から漏れるとすべての機器に入られる | 1人1組の鍵ペアにし、秘密鍵にはパスフレーズを付ける |
| 退職者の公開鍵を機器に残す | 退職後もその秘密鍵でログインできる | 退職の手続きに公開鍵の削除を入れる |

## 事例

[みなと事務所](../../../network/)（社員30名・2フロア）では、[リスクアセスメント](../../cia/) の結果を受けて、次の3つに取り組みました。

**1. 営業のノート PC のディスク暗号化**

持出し用のノート PC 8台すべてで OS のディスク暗号化（AES）を有効にしました。
回復キーは、保守業者の勧めで PC の管理に使っているクラウドの管理サービスに保管し、念のため印刷したものを封筒に入れて総務の鍵付きの書庫に保管しています。台帳には PC ごとに「暗号化の完了日」「回復キーの保管場所」を記録しました。

1年後、営業の1名が電車でノート PC を紛失しました。
ディスクが暗号化され、回復キーも PC とは別の場所にあったため、データが読み出されるおそれは低いと判断できました。総務課長はすぐに管理サービスから遠隔ロックをかけ、本人のパスワードを変更しました。
個人情報保護法の漏えいの報告でも、高度な暗号化などの措置が講じられている場合は報告の対象外とされており、暗号化しておいたことが対応の負担を大きく減らしました（判断にあたっては保守業者と弁護士に確認しました）。

**2. 取引先へのファイルの送り方**

見積書や制作データを取引先に送るとき、パスワード付き ZIP とパスワードを続けてメールで送る方法をやめました。
代わりに、事務所で契約しているクラウドストレージに置き、取引先担当者のメールアドレスだけが開ける共有リンク（期限7日）を送っています。期限が過ぎたリンクは自動で開けなくなるので、送り終えた後の消し忘れも防げます。

**3. ネットワーク機器の管理を SSH の鍵ペアで**

[ファイアウォールの見直し](../../countermeasures/) で、機器の管理画面には総務課長の管理用 PC（192.168.10.10）からだけ接続できるようにしました。
あわせて、各階の L2スイッチの SSH ログインをパスワードから鍵ペアに切り替えました。総務課長と保守業者がそれぞれ自分の PC で鍵ペアを作り、2人分の公開鍵をスイッチに登録しています。
保守業者の担当者が交代したときは、前の担当者の公開鍵を削除し、新しい担当者の公開鍵を登録しました。

## 試験対策のポイント

- **ITパスポート**: 「公開鍵暗号で機密性を確保するときは、**受信者の公開鍵** で暗号化し **受信者の秘密鍵** で復号する」が最頻出です。共通鍵暗号が高速であることも押さえます。
- **基本情報**: 鍵の数の計算（$\dfrac{n(n-1)}{2}$ と $2n$）が定番の計算問題です。AES と RSA がそれぞれどちらの方式かも問われます。
- **応用情報**: ハイブリッド暗号の手順、RSA と楕円曲線暗号の安全性の根拠、鍵長と危殆化、前方秘匿性（PFS）など、方式の選択理由を説明できるようにします。
