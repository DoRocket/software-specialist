情報セキュリティは、技術的な対策を導入するだけでは維持できません。方針を定め、リスクを評価して対策を選び、運用状況を点検して改善し続ける **組織的な管理（マネジメント）** が必要です。
CIA やリスクアセスメントの基本用語は「情報セキュリティの要素」で扱ったので、ここではそれを組織でどう運用するかを掘り下げます。

## ISMS と PDCA

**ISMS**（情報セキュリティマネジメントシステム）の要求事項は JIS Q 27001（ISO/IEC 27001）に、具体的な管理策の実践の手引きは JIS Q 27002（ISO/IEC 27002）に定められています。

| 段階 | 主な活動 |
| --- | --- |
| Plan（計画） | ISMS の **適用範囲** と情報セキュリティ方針を決め、リスクアセスメントを行い、リスク対応計画と採用する管理策を決める（管理策の採否を **適用宣言書** にまとめる） |
| Do（実行） | リスク対応計画を実施し、教育・訓練を行う |
| Check（点検） | 監視・測定、**内部監査**、経営陣による **マネジメントレビュー** で有効性を評価する |
| Act（改善） | 不適合に対して **是正処置** をとり、継続的に改善する |

管理策は、組織的・人的・物理的・技術的の4つに分類されます。
第三者の審査機関が ISMS の適合を審査し認証する仕組みを **ISMS 適合性評価制度** といいます。

## 情報セキュリティポリシーの構成

情報セキュリティポリシーは、次の3階層で構成するのが一般的です。

| 階層 | 内容 | 例 |
| --- | --- | --- |
| 基本方針 | 組織としての情報セキュリティへの取組みの目的・姿勢。**経営者** が承認して示す | 「顧客情報を適切に保護することを経営の最重要課題とする」 |
| 対策基準 | 基本方針を実現するために **何を守り、何をすべきか** の規則 | 「社外に持ち出す PC のディスクは暗号化する」 |
| 実施手順 | 対策基準を実行するための **具体的な手順**。部署や業務ごとに作る | 暗号化ソフトの設定手順書 |

一般に、基本方針と対策基準の2つを「情報セキュリティポリシー」と呼び、実施手順は含めません。
ポリシーは全従業員に周知し、環境の変化に合わせて定期的に見直します。

## リスク分析の進め方

リスクアセスメントの最初に、守るべき情報資産を洗い出して **情報資産台帳** にまとめ、機密性・完全性・可用性の観点から重要度を分類します。

### リスク分析の手法

| 手法 | 内容 |
| --- | --- |
| ベースラインアプローチ | 既存の標準やガイドラインを基準に、一律の対策状況を確認する。手軽だが組織の実情に合わない場合がある |
| 非形式的アプローチ | 担当者や専門家の経験・判断に基づいて分析する。属人的になりやすい |
| 詳細リスク分析 | 資産ごとに脅威・脆弱性・価値を詳しく評価する。精度は高いが手間がかかる |
| 組合せアプローチ | 重要な資産は詳細リスク分析、それ以外はベースラインアプローチ、のように組み合わせる |

リスクの大きさを金額などの数値で表す **定量的分析** と、「高・中・低」などの段階で表す **定性的分析** があります。
定量的分析では、**$\text{年間予想損失額} = \text{1回の損失額} \times \text{年間発生頻度}$** がよく使われます。

### 例題: 対策の費用対効果

**問** ある障害が起きると 2,000 万円の損失が出て、年間の発生確率は 0.1 である。年間費用 100 万円の対策を導入すると、発生確率が 0.02 に下がる。対策を導入すべきか。

**解き方** 対策前の年間予想損失額は $2{,}000\text{万円} \times 0.1 = 200\text{万円}$ です。
対策後は $2{,}000\text{万円} \times 0.02 = 40\text{万円}$ に対策費 100 万円を加えて 140 万円となり、対策前より 60 万円少ないため、**導入が有利** と判断できます。

### リスク対応の選び方

対応の種類（回避・低減・移転・受容）は、発生可能性と影響度の組合せから選ぶのが基本的な考え方です。受容は「保有」とも呼ばれます。

| | 影響度: 小 | 影響度: 大 |
| --- | --- | --- |
| **発生可能性: 高** | 低減 | 回避 |
| **発生可能性: 低** | 受容（保有） | 移転（保険、外部委託） |

対策を講じたあとにも残るリスクを **残留リスク** といい、それが組織の **リスク受容基準** 以下であることを確認し、リスク所有者（そのリスクに責任をもつ人）が受け入れを承認します。

## 組織体制とインシデント対応

| 組織 | 役割 |
| --- | --- |
| 情報セキュリティ委員会 | 経営層を中心に、方針の決定や対策の推進を全社的に統括する |
| CSIRT（シーサート） | セキュリティインシデントが起きたときに対応するチーム。社内外からの報告の受付窓口や、外部組織との連携も担う |
| SOC | ネットワーク機器やログを **24時間体制で監視・分析** し、攻撃の兆候を検知して CSIRT などに通知する |
| PSIRT | 自社が開発・提供する **製品** の脆弱性に対応するチーム |

インシデント対応は、一般に次の流れで進めます。

1. **検知・報告**: 監視や利用者からの報告でインシデントを把握し、窓口に連絡する。
2. **トリアージ**: 影響範囲や緊急度を見て、対応の優先順位を決める。
3. **封じ込め**: 感染した PC をネットワークから切り離すなど、被害の拡大を防ぐ。調査のため、電源を切らずに **証拠を保全** することも重要（デジタルフォレンジックス）。
4. **根絶・復旧**: 原因を取り除き、バックアップなどからシステムを正常な状態に戻す。
5. **事後対応**: 報告書をまとめ、再発防止策を講じる。

大規模な障害や災害に備え、緊急時の行動を定めた **コンティンジェンシー計画** や、事業継続計画（BCP）に情報セキュリティの継続を組み込んでおきます。

## 関連法規・ガイドライン

不正アクセス禁止法と個人情報保護法は「法務と知的財産」で扱っています。ここではそれ以外を概観します。

| 名称 | 概要 |
| --- | --- |
| サイバーセキュリティ基本法 | 国のサイバーセキュリティ施策の基本理念と、国・地方公共団体・重要社会基盤事業者などの責務を定める |
| 不正指令電磁的記録に関する罪（刑法） | 正当な理由なくコンピュータウイルスを作成・提供・供用・取得・保管する行為を罰する（いわゆるウイルス作成罪） |
| 特定電子メール法 | 広告・宣伝メールの送信には原則として受信者の事前の同意（**オプトイン**）を必要とする |
| サイバーセキュリティ経営ガイドライン | 経済産業省と IPA が策定。経営者がリーダーシップをとってセキュリティ対策を進めるための原則と重要項目を示す |
| 中小企業の情報セキュリティ対策ガイドライン | IPA が策定。中小企業が段階的に取り組める対策を示す |
| SECURITY ACTION | 中小企業がセキュリティ対策に取り組むことを **自己宣言** する制度 |
| PCI DSS | クレジットカード会員データを保護するための業界のセキュリティ基準 |
| ISMAP | 政府が利用するクラウドサービスのセキュリティを評価・登録する制度 |

## 実際の進め方

インシデントは、起きてから手順を考えていては間に合いません。平常時に準備し、起きたときは決めた手順どおりに初動をとれるようにしておきます。
ここでは、専任の CSIRT を置けない小規模な組織を想定した手順を示します。

### 平常時に準備しておくこと

| 準備 | 内容 |
| --- | --- |
| 報告の窓口と判断する人 | 「おかしいと思ったら誰に連絡するか」を1か所に決め、全員に周知する。夜間・休日の連絡先と、判断する人が不在のときの代理も決める |
| 連絡先の一覧 | 経営者、保守業者、利用しているクラウドサービスの窓口、保険会社、警察（サイバー犯罪の相談窓口）、IPA などの連絡先を、紙でも保管する（ネットワークが使えないときにも見られるように） |
| 機器・アカウントの一覧 | 情報資産台帳、ネットワーク構成図、管理者アカウントの一覧。どこを止めれば封じ込められるかを判断する材料になる |
| ログの保管 | 機器・サービスのログの保存期間を確かめ、必要なら延ばす。時刻を同期しておく |
| 初動の手順書 | 下の「種類ごとの初動」を、組織の機器やサービスに合わせて具体的に書く |
| 訓練 | 年に1回程度、「この事象が起きたら」を想定して、連絡と判断の流れを机上で確かめる |

### 初動の手順

1. **記録を始める**: 報告を受けた時刻、報告者、見たこと（画面の表示、届いたメールなど）を書き留める。以降の対応も時刻とともに残す。
2. **事実を確かめ、影響を見積もる（トリアージ）**: 何が起きているか、被害が続いているか、個人情報や取引先の情報が関係するかを確かめ、優先順位を決める。
3. **封じ込める**: 被害の拡大を止める。PC ならネットワークから切り離し、アカウントならパスワードの変更とセッションの無効化を行う。調査のため、PC の **電源は切らない**。
4. **証拠を保全する**: 不審なメールは削除せずに保存し、画面の写真、ログの書き出し、設定の記録をとってから、設定の削除や修正をする。
5. **報告・連絡する**: 経営者に報告し、保守業者などの支援を求める。取引先や顧客に被害が及ぶおそれがあれば、早めに注意を呼びかける。
6. **根絶・復旧する**: 原因（マルウェア、盗まれたパスワード、不正な設定など）を取り除き、正常な状態に戻したことを確かめてから業務を再開する。
7. **振り返る**: 記録をもとに、原因・対応の良かった点と悪かった点・再発防止策をまとめ、リスクアセスメントや手順書に反映する。

個人データの漏えい（またはそのおそれ）があり、要配慮個人情報が含まれる、財産的被害が生じるおそれがある、不正アクセスなど **不正の目的による** おそれがある、1,000人を超える、のいずれかに当たる場合は、個人情報保護法により個人情報保護委員会への報告と本人への通知が必要です（詳しくは「[法務と知的財産](../../strategy/legal/)」）。
報告には期限があるので、該当しそうなときは早めに専門家に相談します。

### 種類ごとの初動（チェックリストの例）

| 事象 | 封じ込め | 証拠保全 | 確認すること |
| --- | --- | --- | --- |
| PC のマルウェア感染の疑い | LAN ケーブルを抜き、無線LAN を切る。電源は切らない | 画面の写真、表示されたメッセージ | 同じネットワークの他の PC や NAS に異常がないか |
| メールアカウントの乗っ取り | パスワード変更、全セッションの無効化、多要素認証の設定 | ログイン履歴、送信履歴、転送ルールを記録してから削除 | 誰に何を送られたか、どのメールが読まれた可能性があるか |
| PC・スマートフォンの紛失 | 遠隔でのロック・データ消去、アカウントのパスワード変更 | 紛失した日時・場所の記録、警察への届出 | ディスクの暗号化の有無、保存されていたデータ |
| メールの誤送信 | 送信先に削除を依頼する | 送信したメールの控え | 送ったデータに個人情報が含まれるか |

### よくある失敗と対策

| 失敗 | 起きること | 対策 |
| --- | --- | --- |
| 感染を疑った PC の電源をすぐ切る・初期化する | メモリ上の情報やログが失われ、原因や被害範囲が分からなくなる | ネットワークから切り離すだけにし、調査を終えてから復旧する |
| 本人が「自分で何とかしよう」として報告が遅れる | 被害が広がり、取引先への連絡も遅れる | 報告した人を責めない方針を示し、「迷ったら報告」を徹底する |
| 不審なメールや設定をすぐ削除する | 何が起きたかを後から確かめられない | 保存・記録してから削除する |
| 連絡先がメールやクラウド上にしかない | アカウントやネットワークが使えないと連絡できない | 連絡先の一覧を紙でも保管する |
| 復旧して終わる | 同じ原因で再び起きる | 振り返りの場を設け、再発防止策の担当と期限を決める |

## 事例

[みなと事務所](../../network/)（社員30名・2フロア）で起きた、問い合わせ窓口の共有アドレス（info@minato.example）の乗っ取りへの対応です。
このアドレスは、[多要素認証を導入したとき](../authentication/) に例外として残っていたものでした。

**1. 発見と初動の記録（抜粋）**

| 時刻 | 事象・対応 | 担当 |
| --- | --- | --- |
| 月曜 9:20 | 取引先から総務に「御社の info@ から、ファイル共有の案内メールが届いたが本物か」と電話。総務課長に報告 | 総務の担当者 |
| 9:25 | 記録を開始。info@ の送信済みフォルダに、日曜深夜に取引先など約120件へ送られた身に覚えのないメールを確認 | 総務課長 |
| 9:30 | 所長に報告。乗っ取りと判断し、メールサービスの管理画面で info@ のパスワードを変更、全セッションを無効化 | 総務課長 |
| 9:40 | ログイン履歴を書き出して保存。金曜の夜から、普段と違う国の IP アドレスによるログインが続いていた | 総務課長 |
| 9:45 | 受信したメールをすべて外部のアドレスへ自動転送するルールが追加されていた。設定画面を撮影して記録してから削除 | 総務課長 |
| 10:00 | 保守業者に連絡し、調査を依頼。送られた不審メールの宛先一覧を書き出す | 総務課長 |
| 10:30 | 宛先の取引先に、所長名で「開かずに削除してほしい」と別のアドレスからメールと電話で連絡。自社サイトにもお知らせを掲載 | 総務・営業 |

**2. 原因と影響の確認**

担当者に聞き取りをしたところ、前の週の金曜に info@ に届いた「メールボックスの容量が上限に達しました」というメールのリンクから、偽のログイン画面にパスワードを入力していたことが分かりました。
多要素認証の例外だったため、パスワードだけで外部からログインされていました。

info@ には問い合わせのメール（氏名・電話番号・相談内容）が約300件残っており、自動転送や閲覧によって外部に渡った可能性がありました。
不正アクセスによる個人データの漏えいのおそれがあるため、弁護士・保守業者と相談のうえ、個人情報保護委員会への報告と、該当する問い合わせ者への通知を行いました。

**3. 再発防止**

- 共有アドレスは各自のアカウントから共有メールボックスとして開く方式に変え、すべてのアカウントで多要素認証を必須にしました。例外を認める場合は、理由と期限を台帳に記録して所長が承認します。
- 自動転送のルールで社外のアドレスへ転送することを、メールサービスの設定で禁止しました。
- フィッシングの見分け方と報告の訓練を行うことにしました（[主な攻撃手法と対策](../attacks/) の事例）。
- 対応の振り返りで、「保守業者の夜間の連絡先が分からなかった」ことが分かり、連絡先の一覧に追加して紙でも保管しました。

## 試験対策のポイント

- **ITパスポート**: ISMS が PDCA で継続的に改善する仕組みであること、情報セキュリティポリシーの基本方針・対策基準・実施手順の関係、CSIRT と SOC の役割が問われます。SECURITY ACTION やサイバーセキュリティ基本法などの名称と目的も押さえます。
- **基本情報**: 年間予想損失額による対策の比較、リスク分析手法の特徴、残留リスクとリスク受容基準、PDCA の各段階に当たる活動（内部監査・マネジメントレビューは Check）を判断する問題が出ます。
- **応用情報**: 午後問題では、インシデント発生時の初動対応（封じ込めと証拠保全の両立）、CSIRT の体制や報告経路の設計、ISMS の管理策の選定といった、組織的な対応の妥当性を考察する力が求められます。
