会計は、お店や会社のお金の動きを **決まったルールで記録し、集計して、関係者に報告する** ための仕組みです。
「今年はいくら儲かったのか」「手元にどんな財産と借金があるのか」を、だれが見ても同じように読める形にまとめます。
この分野では、会計の基本用語から始めて、記録の技術である **簿記**、結果の読み方である **財務諸表**、
経営判断に使う **損益分岐点分析** と **減価償却** までを順に学びます。

## 会計は何のためにあるか

会社のお金の動きは、さまざまな人が知りたがります。

| 知りたい人 | 知りたいこと | 使う情報 |
| --- | --- | --- |
| 経営者 | どの商品が儲かっているか、値下げしてよいか、設備を買ってよいか | 損益、費用の内訳、損益分岐点 |
| 株主（出資者） | 出したお金がどれだけの利益を生んだか | 当期純利益、ROE |
| 銀行などの債権者 | 貸したお金を返せる会社か | 負債の大きさ、手元の資金、流動比率 |
| 税務署 | 税金の計算のもとになる利益はいくらか | 利益（税法に合わせて調整したもの） |

これらの人たちに、会社ごとにばらばらの書き方で報告されると比べられません。
そこで、記録のしかた（簿記）と報告の形（財務諸表）にルールが決められています。

会計は目的によって2つに分けて考えます。

| 区分 | 誰に向けたものか | 特徴 | この分野での例 |
| --- | --- | --- | --- |
| **財務会計** | 株主・債権者など社外の利害関係者 | 法令や会計基準に従い、決まった形式で報告する | 損益計算書、貸借対照表、キャッシュフロー計算書 |
| **管理会計** | 経営者・社内の管理者 | 意思決定や業績管理のために、目的に合わせて自由に分析する | 損益分岐点分析、部門別の損益、投資の採算計算 |

## 取引から財務諸表まで（会計の1年の流れ）

会計の記録は、次の順に進みます。この流れが、この分野の記事の並びにもなっています。

| 段階 | すること | 学ぶ記事 |
| --- | --- | --- |
| 1. 取引 | 商品を売る、仕入れる、給料を払う、お金を借りるなど、財産が増減する出来事が起きる | 会計の基本用語 |
| 2. 仕訳 | 取引を「借方」と「貸方」の2つの面に分けて、勘定科目と金額で記録する | 仕訳と勘定科目 |
| 3. 転記 | 仕訳を勘定科目ごとの帳簿（総勘定元帳）に書き写す | 転記と試算表 |
| 4. 試算表 | 元帳の金額を一覧にして、借方と貸方の合計が一致するかを確かめる | 転記と試算表 |
| 5. 決算整理 | 期末に、売れ残った商品や設備の価値の減少などを反映させる | 決算、減価償却 |
| 6. 財務諸表 | 損益計算書・貸借対照表を作り、報告する | 決算、財務諸表の読み方 |

1〜4 は日々（または月ごと）に行い、5〜6 は会計期間（ふつうは1年）の終わりにまとめて行います。

## この分野の地図

| 記事 | 内容 | 主な対象 |
| --- | --- | --- |
| 会計の基本用語 | 売上高・費用・利益・資産・負債・純資産、会計期間。架空のお店の1年を数字でたどる | すべての記事の前提 |
| 財務諸表の読み方 | 損益計算書の段階利益、貸借対照表、キャッシュフロー計算書、財務指標による分析 | ITパスポート〜応用情報 |
| 簿記の基本 | 仕訳と勘定科目 → 転記と試算表 → 決算（精算表・財務諸表の作成） | 日商簿記3級、基本情報・応用情報の「企業会計の手順」 |
| 損益分岐点分析 | 固定費と変動費、利益が 0 になる売上高、安全余裕率、値下げや設備投資の判断 | ITパスポート〜応用情報 |
| 減価償却 | 設備の取得原価を使う期間に配分する、定額法・定率法、記帳のしかた | 基本情報・応用情報、日商簿記3級 |

## 学ぶ順序

1. **会計の基本用語** を最初に読みます。ほかのすべての記事が、ここで説明する言葉を使います。
2. IT系の試験が目的なら、次に **財務諸表の読み方** と **損益分岐点分析** を読みます。試験ではこの2つの計算がよく出ます。
3. 簿記を学ぶなら、**簿記の基本** の3つの記事を順に読みます。仕訳が分かると、財務諸表の数字がどこから来たのかが見えるようになります。
4. **減価償却** は、簿記の決算でも、IT投資（サーバやソフトウェアの購入）の費用の考え方でも使います。

## IT と会計の関係

情報システムの仕事でも会計の知識は必要になります。
販売管理や会計のシステムは仕訳や元帳の仕組みをそのままデータ構造にしたものですし、
システムへの投資を提案するときは「費用がいくらで、何年で回収できるか」「購入したサーバは何年で減価償却するか」を説明できなければなりません。
