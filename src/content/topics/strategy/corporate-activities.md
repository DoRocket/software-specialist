企業が目的を達成するには、適切な組織で経営資源（ヒト・モノ・カネ・情報）を管理し、データに基づいて業務を分析・改善し、合理的に意思決定する必要があります。
QC 七つ道具の節の後では、パレート図 → 特性要因図 → 対策 の順に原因を掘り下げる手順を、架空の IT 企業のサポート業務の改善で通して見ます。

## 前提となる用語

| 用語 | 意味 |
| --- | --- |
| 累積比率 | 大きい順に並べた項目の割合を、上から順に足し合わせた値。パレート図の折れ線で表す |
| 相関 | 2 つの量の一方が増えるともう一方も増える（又は減る）傾向。相関があっても、一方が他方の原因とは限らない（[確率と統計](../../basics/probability-statistics/)） |
| 要因・真の原因 | 要因は結果に影響しうるものの候補、真の原因はデータで確かめて特定した、結果を生んでいる原因 |
| 標準化 | 効果のあったやり方を、手順書や仕組みにして誰でも同じようにできるようにすること |

## 経営組織

| 組織形態 | 特徴 |
| --- | --- |
| 職能別組織 | 営業・製造・経理など **機能ごと** に部門を分ける。専門性を高めやすいが、部門間の調整に時間がかかる |
| 事業部制組織 | 製品・地域・顧客ごとに事業部を作り、各事業部が **利益責任** を持つ。意思決定は速いが、機能が重複しやすい |
| マトリックス組織 | 職能と事業（プロジェクト）の2つの軸で構成し、メンバーが **2人の上司** の指示を受ける |
| プロジェクト組織 | 特定の目的のために各部門から人員を集めた **期間限定** の組織 |
| カンパニー制 / 持株会社 | 事業部を社内の独立した会社のように扱う / 株式の保有を通じてグループ会社を管理する |

経営層の役職として、CEO（最高経営責任者）、CIO（最高情報責任者）、CFO（最高財務責任者）などがあります。

### CSR と企業統治

**CSR**（企業の社会的責任）は、企業が利益の追求だけでなく、従業員、顧客、取引先、地域社会、環境などの **ステークホルダ** に対して責任を果たすべきという考え方です。
経営者の活動を監視・規律する仕組みを **コーポレートガバナンス** といいます。

## OR と IE

**OR**（オペレーションズリサーチ）は、線形計画法（制約条件の下で利益最大化・費用最小化を図る）、在庫問題、ゲーム理論などの数理モデルで最適な意思決定を支援する手法です。
**IE**（インダストリアルエンジニアリング）は、作業時間分析やワークサンプリング法などで作業の方法や時間を測定し、生産性を高める手法です。

## QC七つ道具と新QC七つ道具

主に **数値データ** を分析する QC 七つ道具と、主に **言語データ** を整理する新 QC 七つ道具があります。

| QC七つ道具 | 用途 |
| --- | --- |
| パレート図 | 項目を件数の多い順に並べた棒グラフと累積比率の折れ線グラフ。重点的に対策すべき項目を見つける |
| 特性要因図 | 結果（特性）とそれに影響する要因の関係を魚の骨の形で整理する |
| ヒストグラム | データの分布（ばらつき）を柱状図で表す |
| 散布図 | 2つの変数を縦軸と横軸にとって点を打ち、相関関係の有無を見る |
| 管理図 | 時系列のデータを中心線と上下の管理限界線とともに描き、工程が安定しているかを判断する |
| チェックシート | 確認項目や発生件数を記録・集計する |
| 層別 | データを機械別・作業者別などのグループに分けて比較する |

| 新QC七つ道具 | 用途 |
| --- | --- |
| 親和図法 | 断片的な言語データを、意味の近いものどうしでまとめて問題を明確にする |
| 連関図法 | 複雑に絡み合った原因と結果の関係を矢印で結んで整理する |
| 系統図法 | 目的を達成する手段を、目的→手段の階層に展開する |
| マトリックス図法 | 2つの要素の組合せを行と列にとり、関連の有無や強さを整理する |
| マトリックスデータ解析法 | マトリックス図の数値データを解析して整理する（新QC七つ道具で唯一の数値解析） |
| PDPC 法 | 計画の実行過程で起こりうる事態を予測し、対策を事前に検討する |
| アローダイアグラム法 | 作業の順序関係を矢印で表し、日程計画を立てる |

パレート図の考え方を在庫や売上の管理に応用し、品目を重要度で A・B・C に分けて管理の度合いを変える手法を **ABC 分析** といいます。

## 実際の進め方: QC 手法で原因を掘り下げる

QC 七つ道具は、ばらばらに使うより、**問題を絞り込む → 原因を探す → 原因を確かめる → 対策する → 効果を確かめる** という順に組み合わせると力を発揮します。この手順は、品質管理の改善活動で「QC ストーリー」と呼ばれる流れに沿ったものです。

| 手順 | すること | 主に使う道具 |
| --- | --- | --- |
| 1. テーマを決める | 何を改善するかを、測れる形で決める（例: 問合せ件数を減らす） | — |
| 2. 現状を把握する | データを集めて分類し、件数の多い項目に絞り込む | チェックシート、パレート図、層別 |
| 3. 目標を決める | 何を、いつまでに、どれだけにするか | — |
| 4. 要因を洗い出す | 絞り込んだ項目について、考えられる要因を漏れなく挙げる | 特性要因図（必要なら連関図法） |
| 5. 真の原因を確かめる | 要因の候補をデータで検証する。思い込みで決めない | 層別、散布図、ヒストグラム |
| 6. 対策を立てて実施する | 原因を取り除く手段を考え、効果と実現性で選ぶ | 系統図法、マトリックス図法 |
| 7. 効果を確かめる | 対策の前後で同じ方法でデータを取り、比べる | パレート図（前後の比較）、管理図 |
| 8. 標準化する（歯止め） | 効果のあったやり方を手順や仕組みにして、元に戻らないようにする | — |

特性要因図の大骨（要因の分類）は、製造業では **4M**（人 Man・機械 Machine・方法 Method・材料 Material）がよく使われます。サービスや IT の業務では、「人・方法・システム（設備）・環境」のように対象に合わせて決めます。

### よくある失敗と対策

| 失敗 | 対策 |
| --- | --- |
| 分類の項目が「その他」ばかりになり、パレート図で絞り込めない | チェックシートの分類項目を事前に決め、「その他」が多ければ分類を見直す |
| 件数だけで絞り込み、影響の大きい項目を見落とす | 必要に応じて、対応時間や損失額など影響の大きさでもパレート図を描く |
| 特性要因図に挙げた要因を、確かめずに原因と決めつける | 層別や散布図でデータを確かめてから対策する |
| 相関があることを因果関係と取り違える | 時間の前後関係や、原因を取り除いたときに結果が変わるかで確かめる |
| 対策の効果を、対策前と違う方法で測る | 期間・分類・集計方法をそろえて比べる |
| 効果が出たところで終わり、しばらくすると元に戻る | 手順書・システムの設定・教育で標準化し、管理図などで監視を続ける |

## 事例: ヨヤクルの問合せを減らす

架空の企業 **ツバメ情報システム** の、予約・顧客管理 SaaS **「ヨヤクル」** のサポート窓口での改善です（数値・状況は架空の設定です）。
契約店舗が増えるにつれて問合せが増え、サポート担当が新しい店舗の導入支援に時間を割けなくなっていました。

**① テーマ**: 「既存店舗からの問合せ件数を減らし、導入支援の時間を確保する」。

**② 現状の把握**: 9 月の問合せ 600 件を、チェックシートで決めた分類に沿って集計し、パレート図にまとめました。

| 順位 | 分類 | 件数 | 比率 | 累積比率 |
| --- | --- | --- | --- | --- |
| 1 | ログインできない | 210 | 35.0% | 35.0% |
| 2 | 外部の予約サイトとの連携（予約の取込みのずれ） | 150 | 25.0% | 60.0% |
| 3 | 席の設定の操作方法 | 90 | 15.0% | 75.0% |
| 4 | 請求・支払 | 60 | 10.0% | 85.0% |
| 5 | プリンタの設定 | 45 | 7.5% | 92.5% |
| 6 | その他 | 45 | 7.5% | 100.0% |

$$
\text{上位 2 項目の累積比率} = \frac{210 + 150}{600} = 60\%
$$

上位 2 項目で全体の 60% を占めます。このうち「予約の取込みのずれ」は外部の予約サイトとの連携の不具合が原因と分かっていて、開発チームが問題管理で対応中だったため（[インシデント管理と問題管理](../../management/service-management/incident-problem/)）、サポート部門は 1 位の「ログインできない」に取り組むことにしました。

**③ 目標**: 「ログインできない」の問合せを、3 か月後に月 210 件から 70 件以下にする。

**④ 要因の洗い出し**: サポート担当 6 名で、特性要因図を作りました。

| 大骨 | 挙がった要因 |
| --- | --- |
| 人 | アルバイトの入れ替わりが多い / パスワードを覚えていない |
| 方法 | 店舗で 1 つのアカウントを共有している / 共有のパスワードを変えても全員に伝わらない |
| システム | 5 回失敗するとアカウントがロックされ、解除はサポートへの電話が必要 / ブラウザに古いパスワードが保存されている |
| 環境 | 開店前の忙しい時間に慌てて操作する |

**⑤ 真の原因の確認**: 要因の候補を、データで確かめました。

- **層別**: 210 件を「店舗がパスワードを変更してから 7 日以内か」で分けると、7 日以内が 168 件（80%）でした。パスワードの変更が引き金になっていることが分かりました。
- **散布図**: 店舗ごとに「アカウントを共有しているスタッフ数」と「ログインの問合せ件数」を点で打つと、スタッフが多い店ほど件数が多い **正の相関** が見られました。
- 「開店前の忙しい時間」は、問合せの時刻を層別すると特定の時間帯への偏りが小さく、主な原因ではないと判断しました。

これらから、真の原因を「1 つのアカウントを大勢で共有しているため、パスワードの変更が伝わらず、古いパスワードで失敗を繰り返してロックされる。ロックの解除にはサポートへの電話が必要」と特定しました。

**⑥ 対策**: 系統図法で手段を展開し、効果と実現性で次の 3 つを選びました。

| 対策 | ねらい |
| --- | --- |
| スタッフごとにアカウントを作れる機能を追加する（変更要求として提出） | 共有をやめ、パスワード変更の伝達そのものを不要にする |
| 店長がスマートフォンからロックを解除できるようにする | 解除のための電話をなくす |
| パスワードを変更したとき、ブラウザに保存されたパスワードの更新を促す案内を表示する | 古いパスワードでの失敗を減らす |

**⑦ 効果の確認**: 対策から 3 か月後の 12 月に、9 月と同じ分類と集計方法で比べました。

| 分類 | 9 月 | 12 月 |
| --- | --- | --- |
| ログインできない | 210 | 50 |
| その他の分類の合計 | 390 | 390 |
| 合計 | 600 | 440 |

「ログインできない」は $\dfrac{210 - 50}{210} \fallingdotseq 76\%$ 減り、目標の 70 件以下を達成しました。問合せ全体も 600 件から 440 件に減りました。

**⑧ 標準化**: 新しく契約した店舗には、導入時にスタッフごとのアカウントを作る手順を導入手順書に加えました。また、ログインの問合せ件数を毎月グラフにして監視し、増えたら原因を調べることにしました。次のテーマは、問題管理で対応中の連携の不具合を除いて最も件数の多い「席の設定の操作方法」です。

## 意思決定とデシジョンツリー

**デシジョンツリー**（決定木）は、意思決定の分岐（□）と、確率的に起こる事象の分岐（○）を木構造で表し、各案の **期待値**（金額 × 確率の合計）を比較して最適な案を選ぶ手法です。

### 例題（デシジョンツリー）

**問** 新製品の生産規模を決める。需要が大きくなる確率は 0.6、小さくなる確率は 0.4 である。期待利益が最大になる案はどれか。

| 案 | 需要大のときの利益 | 需要小のときの利益 |
| --- | --- | --- |
| 大規模生産 | 1,000 万円 | −200 万円 |
| 小規模生産 | 500 万円 | 200 万円 |
| 生産しない | 0 万円 | 0 万円 |

**解き方** 各案の期待値を計算します。
大規模生産 $= 1{,}000 \times 0.6 + (-200) \times 0.4 = 600 - 80 =$ **520 万円**、
小規模生産 $= 500 \times 0.6 + 200 \times 0.4 = 300 + 80 = 380$ 万円、生産しない $= 0$ 万円。
期待値が最大の **大規模生産** を選びます。損失の可能性がある点が気になる場合は、最悪の結果が最も良い案を選ぶ **マクシミン原理** という別の判断基準もあります（この場合は小規模生産）。

## 在庫管理と発注方式

| 方式 | 発注のタイミング | 発注量 | 向いている品目 |
| --- | --- | --- | --- |
| 定量発注方式（発注点方式） | 在庫量が **発注点** を下回ったとき | 毎回一定（経済的発注量など） | 需要が安定した重要度の低い品目 |
| 定期発注方式 | **一定の間隔**（毎週、毎月など） | その都度、需要予測と在庫量から計算 | 重要度の高い品目（ABC 分析の A 品目） |

- **発注点** $= \text{1日当たりの平均使用量} \times \text{調達期間（発注から納品までの日数）} + \text{安全在庫}$
- **安全在庫** は、需要のばらつきや納期の遅れによる品切れを防ぐために上乗せする在庫です。
- **経済的発注量（EOQ）** は、発注費用と在庫保管費用の合計が最小になる1回当たりの発注量です（年間需要量 $D$、1回の発注費用 $S$、1個当たりの年間保管費用 $H$ のとき $\sqrt{\dfrac{2DS}{H}}$）。

### 例題（発注点）

**問** ある部品の1日の平均使用量は 20 個、発注から納品までの調達期間は 5 日、安全在庫は 30 個である。発注点は何個か。

**解き方** 発注点 $= 20 \times 5 + 30 =$ **130 個** です。納品までの5日間に平均 100 個使っても、安全在庫分が残ります。

## 試験対策のポイント

- **ip**: 組織形態の特徴（特にマトリックス組織、事業部制）、CSR、パレート図・特性要因図・散布図・管理図の用途、デシジョンツリーによる期待値の計算が頻出です。
- **fe**: QC七つ道具と新QC七つ道具の区別、発注点や期待値の計算、定量発注方式と定期発注方式の比較、線形計画法の定式化が問われます。
- **ap**: マクシミン原理・ラプラスの原理など不確実性下の意思決定基準、経済的発注量の計算、管理図による工程の異常判定など、計算と判断を組み合わせた問題に備えます。
